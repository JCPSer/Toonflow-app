# 记忆：画布 Agent 节点派活（P1）

- 时间：2026-11-15 19:33
- 类型：新能力（多 Agent 通信）

## STAR

**Situation（背景）**
画布上多个 Agent 节点彼此隔离，用户要求真正派活与结果回传，并明确不要共享黑板节点。

**Task（任务）**
在「页面关闭/刷新即中断」的前提下，做同画布 Agent 的异步派活、排队、实时可见与结果回传。

**Action（行动）**
- 服务端新增 `sendToAgent` 工具，只下发 `agentDispatch` 意图（身份、深度、目标、A 的模型），立即返回 taskId；只在顶层、绑定画布的会话注册，子 Agent/A2A 不继承。
- 画布新增 `agentDispatcher`：队列、每画布并发 4、60 秒去重、8 跳、目标校验、用现有 `/api/agent` 流跑 B、处理 canvasCall/question/session、写回会话文件与节点状态。
- 结果以「Agent 任务结果」回传 A，自动开新一轮；A 忙则排队。
- 面板镜像后台事件、停止按钮可取消派发任务、提问写入全局 store 并在打开面板时回放。
- 单测：服务端 4 例 + 前端 dispatcher 2 例；服务端 131 测试通过。

**Result（结果）**
P1 核心链路完成，待真实模型联调；已知限制（模型落盘、跨链去重、多标签页、重命名）记录在测试文档。

## 关键经验

1. 真正的跨 Agent 通信不等于共享节点：必须有队列、并发、深度、去重、结果回传与取消语义。
2. 服务端 headless 路线会把会话准入/所有权/取消/绑定/画布通道全部重做；确认「刷新即中断」后，画布 dispatcher 复用现有流是成本低得多的真实方案。
3. 面板自己的请求与 dispatcher 请求必须互斥（panelRunning），否则同一会话会被两路流同时驱动。
4. 结果回传不能依赖 followUp：作为新输入排队，等目标当前流结束再发，才不会丢消息。
5. 事件镜像要容错：面板未挂载、会话不一致、提问卡片缺工具块时都不能打断后台任务。

## 补充：结果回传空文本

- 现象：结果消息只有 completed + 「没有返回文本」。
- 根因：dispatcher 读取 `/api/agent/get` 漏了 `x-toonflow-workspace: 1`，403 被吞成空串。
- 教训：工作区类接口在桌面端也走同一套本地工作区校验；「结果为空」先看请求是否 403，不要先怀疑模型。
- 同时把结果提取改为跳过 tool-only 的末尾 assistant，并补 `agentModel` 模型回退。

## 产品决策：不补建节点时指定模型

- `addNode` 只能建空 Agent 节点（type/position/label），没有模型与会话；模型仍由用户在面板手选。
- 2026-11-15 用户明确选择「都不做」，`addNode` 不加模型参数、`agentModel` 也不落盘；`agentDispatcher` 里已有的 `node.data.agentModel` 回退层保留，等以后需要时再用。
