# 记忆：会话/工程复制改用写时复制（COW）

- 时间：2026-10-30 23:45
- 改动范围：5 个文件（`packages/file` 1 个 + 服务端 4 个）

## Situation

Agent 节点「创建副本」把整个会话 jsonl 逐字节复制。用户长期迭代（复制到第 10 代）时磁盘占用按代叠加；
工程另存、文件树复制目录、跨设备重命名也都在做「读全量 + 写全量」。两块工作盘都是 APFS。

## Task

在不改变复制语义（EXCL、符号链接拒绝、部分复制保留、错误码）的前提下，让这些复制在 APFS 上不再占用等量磁盘。

## Action

新增原语 `copyFileClone`（`packages/file/src/index.ts`）：

```
copyFileClone(source, target)
  = withFileAccess([source, target], "write",
      fs.copyFile(source, target, COPYFILE_EXCL | COPYFILE_FICLONE))
```

- `COPYFILE_FICLONE`：内核优先 clonefile/reflink，卷不支持时自动降级为普通复制。
- 保留 `COPYFILE_EXCL`，目标已存在仍报 `EEXIST`；仍走 withFileAccess 的写锁。

三处接入：

1. `copyWorkspaceFile()` 单文件分支 → `copyFileClone`；
2. `copyWorkspaceFile()` 目录分支：**保留 `fs.cp`，只去掉预先的 `mkdir(target)`**，目标已存在时自己抛 `EEXIST`；
   目录由 cp 创建，权限位与源一致（`mkdir` 会被 umask 削成 0755）
   （第一版曾自实现递归 `copyTreeClone`，审查实测证明 Bun 的 `fs.cp` 本来就 reflink，且递归会丢权限位，已回退）；
3. `renameWorkspaceFile()` 的「复制 + 删源」步骤 → `copyFileClone`。

会话克隆（`sessions.ts` `cloneAgentSession`）：未运行会话不再 `readFile → writeWorkspaceFile(bytes)`，
改为 `copyWorkspaceFile(源, 目标)` + 复制后按**副本末字节**决定补不补 `\n`（`endsWithNewline`）；
复制、补换行、`renameAgentSession` 全包在同一个 `try` 里，失败 `unlink`，避免留下残缺 jsonl 被历史列表当真会话。
运行中会话仍走内存快照。AgentHost.workspace 端口新增 `copyWorkspaceFile`，agent 层不直接碰文件系统。

## Result

| 用例 | 改前 | 改后 |
| --- | --- | --- |
| 2GB 文件复制 | +2048MB | **+0MB** |
| 副本追加 100MB | 复制 2GB 后 +100MB | **+100MB**（只耗增量） |
| 会话克隆（含末尾无换行的旧文件） | 全量读 + 全量写 | 字节前缀一致、行不粘连、名称「· 副本」 |
| 目录复制（300MB + 空目录 + 嵌套，源 0700） | 全量复制 | **df 增量 0MB**，结构一致，权限 700 保留 |
| 目录含符号链接 / 目标已存在 | 报错 | 报错消息与错误码不变 |

## 经验

- **`du` 不能用来判断 reflink**：克隆后两个文件各自仍报告整份块数。唯一可靠口径是复制前后 `df` 可用空间差。
- **Node 的 `COPYFILE_FICLONE` 在 APFS 上会静默降级为完整复制**（Node 25.5.0 实测可用空间减少 2GB），
  Bun 1.3.11 才是真 clone。本项目服务端跑 Bun，所以生效；这个差异必须在文档里写明，否则换运行时就会「优化悄悄失效」。
- SDK 的 `SessionManager._rewriteFile()` 用 `openSync(file,"w")` 原地重写（回退/改标签时触发），那一刻副本会全额分叉；
  正常追加走 `appendFileSync`，只分配新块。
- **「`fs.cp` 不支持 reflink」是错的**：Bun 的 `fs.cp` 在 APFS 上逐文件 reflink（1.3.11 与 1.4.0 均实测 df 增量 0，权限位也保留）。
  自己递归逐文件 `copyFileClone` 不多省一个字节，还会因为 `mkdir` 被 umask 削减而丢掉目录权限位（0700 → 0755）。
- **「先 mkdir 再 cp」在 Bun 1.4.0 / Node 下必失败**：`fs.cp(force:false, errorOnExist:true)` 遇到已存在的目标目录直接
  `ERR_FS_CP_EEXIST`，只有 Bun 1.3.x 恰好容忍。复制目录时要让 cp 自己建目标目录。
- 凡是「先算一个结论、再执行一次 I/O」的写法，结论与真正写入的字节之间可能已经有别的写入方：换行判断要读**副本**的末字节，不要用复制前那次 readFile 的结果。
