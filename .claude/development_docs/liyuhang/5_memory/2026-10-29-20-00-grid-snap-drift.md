## Situation

开启「网格吸附」（16px）后，画布上仍有节点轻微错位：分组和组内节点恒定偏 8px，部分节点是 `1474.792116359792` 这种小数坐标。拖拽修不好——Vue Flow 只吸附拖拽和指针投影，组内子节点拖的是组。

## Task

1. 找到所有会把坐标写偏的路径；
2. 修到"新建即对齐"；
3. 让旧画布自动归位且可撤销。

## Action

- 新增 `canvas/snapNodes.ts` 作为唯一吸附源（`snapValue/snapPoint/snapOffset/normalizeNodesToGrid`）。
- 建组内边距从 24/40/+24 改成 32/48/+32（网格倍数），并在 `fitGroupBounds` 吸附 `left/top`。
- 建组、合并组、取消分组、拖入分组、副本偏移、手动排列、dagre 自动排版、空画布首节点、节点菜单「创建副本」、分组缩放收手，全部改为写吸附后的坐标；缩放只在收手时吸附一次。
- 打开画布时做一次性归一化：绝对坐标吸附、组内相对间距保持，整体一个 `canvasHistory.batch`（可撤销）；守卫修正为"成功后记账 + 重入标志 + active/directory 二次校验"，开关只在实际归一化时读。
- 明确取舍：结构操作始终对齐网格（网格固定 16），网格开关只影响拖拽与归一化；节点包内部批量生成的兄弟节点不逐处改，靠重开画布兜底。

## Result

- 真实画布验证：7/28、11/28、3/3 三个画布的错位节点归一化后全部 `%16 == 0`；两个画布组内间距变化 0，一个因小数节点变化 8px。
- web 构建通过，`deploy-local.sh --build` 部署完成（含 10 个节点包）。
- 待重启后人工验证 7 项（见测试记录第四节）。

## 关键教训

- Vue Flow 的 `snapToGrid` 覆盖面只有 `useDrag` 与 `project/screenToFlowCoordinate`，项目自己算坐标必须显式吸附；"开了吸附"不等于"坐标一定对"。
- 分组内边距这类"结构性常量"如果不是网格倍数，会产生用户永远拖不掉的偏移——因为拖的是组，子节点跟着走。
- 归一化这类"加载期自愈"逻辑的守卫必须后置记账，否则一次抖动就让修复永久失效。
