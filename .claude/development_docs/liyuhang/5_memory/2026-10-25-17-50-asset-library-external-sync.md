# 素材库与磁盘一致：监听自动刷新 + inode 元数据 + 缺失提示（STAR）

## Situation

素材库的磁盘结构本来就是 1:1（全局 `<数据目录>/assets`、项目 `<项目>/library`），读取也是实时扫盘，但：外部改动不会自动出现；索引按相对路径存标签/备注/收藏，在 Finder 里改名或移动就丢；被外部删掉的素材看不到任何痕迹。

## Task

1. 素材库可见时监听库根，外部改动自动出现，不刷新整棵树。
2. 标签/备注/收藏跟随文件（inode）。
3. 外部删除的素材标"缺失"并提示，不自动改引用。
4. 性能：大目录不阻塞。

## Action

- **服务端监听**（`utils/assets/watch.ts`）：每个库根一个 `fs.watch(recursive)`，按路径分段过滤 `.library/.trash/.thumbs`、`.DS_Store`、`.tmp`、`~$`；事件只记父目录，300ms 合并 + 2s 上限；多订阅者共享；根消失发 `gone`；创建失败降级为空订阅。
- **推送**（`routes/assets/events.ts` + `router.ts`）：NDJSON 流（ready/change/gone/ping），20s 心跳，断开即取消订阅。
- **索引**（`libraryMeta.ts`）：`LibraryEntry` 增加 `dev/ino/isDirectory/staleAt`；`reconcile` 前建 inode→path 映射，路径不存在但 inode 命中时整体迁移（目录走前缀迁移），旧路径仍存在（硬链接/副本）则不迁；`prune` 从"直接删除"改为"标 stale"，30 天或 5000 条后回收。
- **列表**（`library.ts`）：`readChildren` 收集 dev/ino；`list` 额外返回 `missing/missingTotal`（只对当前目录、非搜索、未截断）；`tree` 的子项数改并发 4 + 2s 缓存。
- **清理接口**（`routes/assets/forget.ts`）：只删索引，不动磁盘。
- **前端**：`subscribeAssetChanges`（fetch 流 + 3s 重连）；`useAssetLibrary` 增加 `active` 参数，隐藏时断开，恢复/重连时补一次静默刷新；事件按"当前目录/祖先/子目录"判定后 500ms 合并、2s 上限；`loadList(silent)` 不清空列表避免闪烁；顶部"缺失"提示条 + 一键清理索引。

## Result

- 外部新建文件 ≤1.5s 自动出现；外部删除 ≤1.8s 消失并出现"已不在磁盘"提示，可一键清索引。
- 改名/移动后标签、备注、收藏跟随（含整目录改名）。
- 素材库隐藏时不刷新，切回立即补上。
- 1100 项目录 list ~85ms；100 子目录的 tree ~35ms（原为 100 次串行读）。
- server/web 类型检查与构建通过。

## 经验

- "文件系统即真相"的产品里，索引只能存**元数据**，不能存"文件是否存在"；失效要用"标记 + 提示 + 过期回收"，而不是立刻删。
- 路径会变，身份要稳：用 `dev+ino` 做迁移凭据，但必须防硬链接/副本抢元数据（旧路径还在就不迁）。
- 递归监听的坑在"自己写自己"：索引文件就在库根里，过滤必须按路径分段，否则 200ms 一次的索引落盘会把自己刷成事件风暴。
- 推送只是优化，不是保证：断线、隐藏、网络卷不支持递归监听都要有"恢复时补一次"的兜底，否则会出现"看着没变"的错觉。
