# 记忆：提示音不响的排查与解锁加固

- 时间：2026-11-10 00:09
- 类型：Bug 加固（WebAudio / 设置页）

## STAR

**Situation（背景）**
用户反馈重启后没有提示音。设置文件为 `completionSound=always`、音量 70；部署包内的合成音、任务事件订阅、UI 解锁调用都在；11 个内置节点 UMD 都含 `toonflow:node-task`。完成音本身有 30 秒门槛，且手工安装的 5 个节点（exec/videoPost/imageResize/depthCapture/webEpisodeEditorPro）根本没有完成事件。

**Task（任务）**
把「音频没启动」和「事件没触发」分开，并让用户能一键自证；不改变既有触发规则。

**Action（行动）**
- `chime.ts`：新增 `resumeChime()`、`chimeSupported()`；`installChimeUnlock()` 在 pointerdown/keydown/touchstart 捕获阶段反复尝试 `resume`，`state === "running"` 才解绑；TS 收窄问题用函数读取 state 规避。
- `main.ts`：删除一次性 `pointerdown` 监听，改调 `installChimeUnlock()`。
- 设置 → 节点提示音：音量行加「试听」按钮，点击先恢复上下文再播完成音；失败时按「已支持但没启动 / 环境不支持」分别提示。

**Result（结果）**
typecheck 仅剩既有 `@/agentRuntime`；web 构建成功并已同步应用（00:09）；未重启。

## 关键经验

1. WKWebView 的 AudioContext 解锁不能只挂一次 `once`：首次手势可能撞上音频子系统未就绪，之后没有手势的 `resume()` 会被拒绝，整轮会话静音。
2. 提示音有三道门槛（开关、30 秒、节点是否派发完成事件），排查时先看事件源再看音频；手工安装的节点包不重建就不会发事件。
3. 音频问题必须给用户一个不依赖节点运行的自证入口（试听按钮），否则只能靠猜。
