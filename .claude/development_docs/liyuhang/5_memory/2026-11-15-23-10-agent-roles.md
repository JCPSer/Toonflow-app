# 记忆：Agent 预制角色

- 时间：2026-11-15 23:10
- 类型：新能力

## STAR

**Situation（背景）**
用户按职责拆分多个 Agent（导演、分镜、提示词审核/撰写），每次都要新建节点并手写初始上下文，重复劳动。

**Task（任务）**
做一套可复用的全局角色：名称 + 系统提示词，在 Agent 节点面板管理与选择；角色提示词优先于软件默认提示。

**Action（行动）**
- 角色库存 settings.agentRoles；保存与读取共用 sanitize（坏项丢弃、去重、截断、上限 50），避免脏数据拖垮设置保存。
- 运行时按 roleId 解析，角色段置于系统提示最前，声明职责/语气以角色为准、安全与授权规则仍按软件；子 Agent 不继承。
- 模型弹层「思考强度」下新增角色选择；节点保存 agentRoleId，派发使用目标节点角色，分支节点继承，分享导出剥离。
- 节点面板内新增角色管理弹窗（增删改、50000 字预算）。

**Result（结果）**
服务端 137 测试通过（含角色 6 例），web 派发测试 3 例通过；产物已构建并同步到桌面负载，待重启验收。

## 关键经验

1. 角色提示词不能简单「一律优先」：安全与授权规则必须晚于角色且不可覆盖。
2. 角色库混在设置里时，校验要「清洗」而不是「整体拒绝」，否则一条脏角色会挡住所有设置保存。
3. 系统提示不参与压缩，角色总量必须有预算；单字段上限不够。
4. 全局角色不随工作区导出，分享时要剥离引用 id，否则接收方出现悬空角色。
