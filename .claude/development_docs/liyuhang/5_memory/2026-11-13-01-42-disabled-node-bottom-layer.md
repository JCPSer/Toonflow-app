# 记忆：禁用节点恒在画布下层（派生 zIndex）

- 时间：2026-11-13 01:42
- 类型：功能（画布层叠）

## STAR

**Situation（背景）**
禁用节点在画布上会盖住启用节点。Vue Flow 的节点 z 默认全为 0，同 z 时按 DOM 顺序（后加入的在上），后禁用的节点自然压住更早的启用节点。

**Task（任务）**
让禁用节点恒在启用节点之下，同时不破坏「选中节点浮起」的既有交互；分组内节点不能被分组底色盖住。

**Action（行动）**
- 采用 Vue Flow 自己的 `node.zIndex`：禁用节点设为 -1，启用节点保持 undefined。
  未选中时 -1 < 0；选中时 +1000 得 999 / 1000，禁用节点仍低于选中的启用节点，但能浮到未选中的启用节点之上（可看见、可选、可拖）。
- 用一个 watch 从 `data.disabled` 派生 zIndex：依赖里带「节点数组本身」，
  这样 `setNodes` 整体替换（加载画布、撤销/重做、粘贴）也会重算，而不是只在禁用切换时生效一次。
- `zIndex` 加入 `index.vue` 与 `useCanvasHistory.ts` 两处 `nodeRuntimeFields`：不触发保存节流、不进撤销快照。
- 分组不额外干预：子节点 z 由 Vue Flow `max(父, 子) + 1` 计算，天然在分组本体之上。

**Result（结果）**
typecheck 仅剩既有 `@/agentRuntime`；web 构建成功并同步应用（01:42）；未重启。

## 关键经验

1. 「谁压住谁」先看清框架的 z 规则，再决定用负数还是抬升正数：这里选中会 +1000，用 -1 能同时满足「恒在下层」和「选中可浮起」。
2. 派生字段（zIndex）必须显式排除在保存/撤销之外，否则每次重算都会写盘、都会进历史。
3. 只监听「禁用集合变化」不够——`setNodes` 换掉节点对象时禁用集合可能不变，zIndex 会丢；依赖必须包含节点数组身份。
4. 分组子节点的 z 由父级推导，压得太低会被分组底色/边框盖住，这是「跟随分组层级」这个取舍的由来。
5. `nodeRuntimeFields` 只影响「变更触发什么」，**不影响序列化**：Vue Flow 的 `toObject()` 会原样带出派生字段，落盘和剪贴板要各自剥离（本项目序列化边界有三处：saveCanvas、nodeClipboard、历史快照）。
6. 画布关了 `selectNodesOnDrag`：拖动未选中的节点不会自动选中，拿不到 Vue Flow 的选中提升，需要在 `onNodeDragStart` 手动临时抬 z，并在 stop/中断两处收回。
