# 记忆：Agent 运行中无法停止

- 时间：2026-11-15 22:20
- 类型：bug 修复

## STAR

**Situation（背景）**
派活功能让节点可能在无本地请求时运行（dispatcher 派发/结果续跑），面板只有发送按钮；用户点发送会丢草稿并撞服务端 409。

**Task（任务）**
让后台运行可停止、停止后不被排队任务或结果回传拉起，并保证命令真正结束。

**Action（行动）**
- 前端工具栏按 `busy || remoteRunning` 显示停止；发送入口三处拦截，保留草稿。
- `stopMessage` 无论有没有本地 controller 都调用 `dispatcher.stop`，并消费命中结果；`stoppedByUser` 只随本地请求。
- dispatcher 增加 `pausedNodes`：stop 清排队与 dedupe、粘住节点，用户手动发送才解除。
- 取消结果改为 `note`（只写会话、不跑模型），父 Agent 停在等待输入。
- `runCommand` 改 detached + 进程组 SIGKILL，避免 `sleep` 变孤儿。

**Result（结果）**
3 例 dispatcher 测试 + 131 服务端测试通过；web/server 与桌面负载已部署，待重启验收。

## 关键经验

1. 「可停止」不等于「有按钮」：停止必须同时处理本地请求、dispatcher 队列、去重表与后续结果投递。
2. 停止标记要粘住目标节点，否则下一秒就被排队任务或回传唤醒。
3. `bash -c` 的孙进程不在直接子进程树里，必须用进程组终止。
4. 只写会话不跑模型的「通知」需要一个独立事件类型，不能复用 userMessage（会拉起流式占位）。
