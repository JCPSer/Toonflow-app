# 记忆：图片节点颜色调整（亮度/对比度/饱和度/色温/色调）

- 时间：2026-11-13 18:26
- 类型：功能（节点工具）

## STAR

**Situation（背景）**
图片节点缺最基础的颜色校正：生成图偏色/发灰/偏暗时只能重新生成或外部软件处理。已有裁剪/缩放/打光，但没有滑块式调色。

**Task（任务）**
加一个「调整」工具：五根滑杆、弹窗内实时预览、所见即所得、应用后落盘并替换输出、可恢复调整前；图片节点与图片生成节点共用。

**Action（行动）**
- 抽出 `imageAdjust.ts` 纯像素函数：白平衡（色温/色调）→ 亮度 → 对比度 → 饱和度，全部在 `Uint8ClampedArray` 上原地处理。
  对比度用线性系数 `1 + c/100`（0 全灰、2 双倍），不用标准 259 公式——后者在 +100 会把中间调压成纯黑白。
- `components/imageAdjust.vue`：打开时把图下采样到长边 800 并取一次 `ImageData` 作为基准；滑杆变化用 rAF 合帧、每帧从基准复制再套参数（绝不累加）；导出用全尺寸 canvas 走同一个函数，保证预览与结果一致。
- 落地沿用裁剪的状态机：`data.adjust = { previous, appliedUrl }`，仅当输出仍是上次结果时显示「恢复调整前」；上传/AI 改写/选历史时与 `clearCropHistory()` 一起清。
- 两个节点各加工具栏按钮「调整」、组件实例与 `handleAdjustApplied/Restore`；包新增 `./imageAdjust` 导出；重建两个 UMD 并备份同步。

**Result（结果）**
两个节点包 typecheck 通过、vite build 成功，已备份旧包并同步 `/Applications/toonflow-data/nodes/` 与 `data/nodes/`。纯函数手算抽查（恒等/极值/组合）符合预期。需重启应用生效。

## 关键经验

1. 调色「预览 vs 导出不一致」的根源通常是采样尺寸或多次累加：解决办法是**只取一次基准像素**，每次从基准重算，两条路径共用同一个纯函数。
2. 对比度公式不要照抄 259 公式当滑杆映射：滑杆中后段会整段截顶，用户会觉得「调不动」；线性系数更好用。
3. 像素循环里用 `Uint8ClampedArray` 的隐式夹紧，比每个通道手写 clamp 更快也更不容易写错。
4. 新工具要复用既有的「应用 → 落盘 → previous/appliedUrl → 可恢复」状态机，否则恢复、清理、复制节点这几条路径都会漏。
5. 评审补充：**异步操作必须在入口快照 props**。apply 里 await 之后再读 `props.source.url`，等于把「防覆盖校验」交给了一个可能已经变了的对象——快照的 fromUrl 才有效。
6. 新的「落盘类」工具要同时接进父节点的 busy/守卫（`adjusting`）、delete 前 `cancelApply()`、以及分享包/跨项目的状态清理，否则会留下孤儿文件或指向源项目的旧路径。
7. 分享包 sanitize 是白名单式逐字段 drop：新增任何带 `previous/appliedUrl` 的编辑状态，都要在 `sanitizeCanvas` 和 `nodeClipboard` 两处补一条，否则旧图会被打进包里。
