# 记忆：图片节点裁剪工具

- 记录时间：2026-10-29 13:05

## S 情境

图片类节点已有缩放、宫格切分、局部重绘、打光、多角度、全景图、标记，但没有最基础的取景裁剪，用户只能导出到系统图片工具里裁完再拖回来。裁剪是几何精度操作，节点卡片 240px 的预览拖不准。

## T 任务

给 `imageNode` 与 `imageGenerationNode` 的工具栏加「裁剪」：大图弹窗框选、比例预设、像素级精度，结果替换当前输出且可一层恢复。

## A 行动

**形态**：独立 `el-dialog`（`min(920px, 100vw-32px)`，appendToBody），共享组件 `imageCrop.vue` 放在 `imageNode/src/components`，通过新增的 `@toonflow/node-image/imageCrop` 导出给两个节点复用。

**坐标**：持久化与计算一律用图片像素坐标，渲染时投影成百分比。这样窗口缩放、节点缩放、弹窗尺寸变化都不影响已选区域，应用时直接用像素矩形喂 `drawImage`，不会累积误差。

**遮罩**：四块百分比定位的 DOM（上/下/左/右），不是 `box-shadow`——阴影会在图片边缘被裁掉，八向手柄也会跟着被裁。

**比例锁**：角手柄取更"跟手"的一维主导、另一维按比例推出；边手柄固定对边、垂直方向绕原中心居中；Alt+角以中心对称缩放；每次算出后统一走 `clampRect` 夹紧到图片内。

**落盘**：Canvas 2D 裁剪 → `toBlob` → `workspace.write(path, blob, true)` 写 `assets/<nodeId>/crop-<w>x<h>-<ts>.<ext>`，不覆盖原文件；父级校验 `current.url === fromUrl` 后才改输出，`crop.previous/appliedUrl` 与缩放同构，只回一层。

**接入**：两个节点各加按钮、`cropping` 计算属性、所有 `:disabled` 串与 `save/delete` 守卫；输出被上传/替换/改选历史时 `clearCropHistory()`。

## R 结果

- 两节点 vue-tsc 通过，`deploy-local.sh --build` 成功并同步 UMD。
- 运行中实测：1:1 预设置信（1792×1792，y=288 居中）、数字框、方向键 ±1/±10、手柄联动、越界夹紧、Esc 只关弹窗、取消后重开恢复上次框、应用后节点自适应、恢复裁剪前、画布 JSON 持久化正确。
- 像素级验证：`ffmpeg crop=640:480:50:60` 参考图与实际产物解码后 md5 完全一致。

## 关键坑

1. **浮点百分比会产出非法 CSS**：`7.10543e-15%`、`100.00000000000001%` 会被浏览器整条丢弃并保留上一帧值，表现为遮罩错位（图片外多一块黑、该暗的地方不暗）。所有百分比必须经 `pct()` 夹紧 + 定点 3 位小数。
2. **`props.src` 是 blob URL**：任何"记住上次"的状态都必须用 `props.source.url`（工作区路径）做键，否则重挂载/重启必然失配。
3. **`@keydown.stop` 会连 Esc 一起拦掉**：Element Plus 的 Esc 监听挂在 document 上；画布侧本来就是捕获阶段 + `.el-overlay` 守卫，不需要 stop 兜底。
4. **数字框的夹紧方向要有利于用户**：溢出时收缩宽高，不要把用户输入的 X/Y 改回 0，否则"先输 X 再输宽度"的常见顺序会把 X 吃掉。
5. **手势结束不要写 `node.data`**：每拖一下写一次等于持续触发画布自动保存，改成关闭弹窗时落一次。
6. **格式判定优先看 `mimeType`**：只看扩展名时，`.jpg` 里实为 PNG 的图会把透明区压成黑块。
7. **自己写的自动化测试能"绕过"UI**：直接对舞台元素派发 pointerdown，会跳过我给 `cropBox` 挂的 `@pointerdown.stop` —— 真实用户点不到舞台。凡是"点击落在哪个元素"会改变语义的交互，测试必须走 `elementFromPoint` 取真实命中目标。
8. **两个客户端会互相覆盖画布**：桌面窗口和浏览器标签同时在线时，各自 500ms 防抖保存，A 的修改会被 B 的旧快照盖回去。排查"数据没保存"要用 400ms 轮询抓写入瞬间，否则会误判成功能 bug。
9. **CSS 镜像不影响 `drawImage`**：预览用 `transform: scaleX(-1)`，但 canvas 拿的是原图；翻转落盘必须把视图坐标换算成源坐标（`sx = W - x - w`）再 `translate/scale` 反向绘制，否则裁出来的还是未翻转区域。
10. 测试期间应用被重启过（端口从 50844 换到 50095），旧进程里未落盘的裁剪结果丢失——排查"数据没存"时先确认进程是否换过。
