## 4. 问题清单（全部为非阻断，建议后续清理）

**P3-1｜入口存在死公开面（装饰性导出）**
`modules/assetLibrary/index.ts:4` 的 `internalAssetDirectories`、`modules/mcpIntegration/index.ts:6` 的 `getMcpSettings` 无模块外消费者（实测：仅入口自身 re-export 与模块内部相对引用）。TEST-2026-10-27-03 §6 已说明保留理由（删除会让入口静态面为空，可能改变 `Bun.plugin` 求值时序）。建议：在 `types/module.ts` 或 `AGENTS.md` 用一行登记“入口可保留 0～2 个仅供内部/形态稳定的 re-export”，避免下一轮被当作死代码争议。

**P3-2｜`ServerModule` 契约的三个钩子字段无运行时消费者**
`initialize / warmup / mount` 字段仅作类型约束（`app.ts` 调具名导出）。已由 `types/module.ts:22-23` 注释与 `AGENTS.md` 明文承认（不新增自检命令），但漂移只能靠人工/地图复核——历史上一轮已真实发生一次（`localRuntime`/`platformCore` 的 `dependencies` 写错）。建议维持现状的同时，把“改跨模块 import 必须同步 `dependencies` + AGENTS 表 + 子图”写进 PR 模板/审查清单。

**P3-3｜bootstrap 仍深引模块内部（2 条）**
`apps/server/src/index.ts:22-23` 动态 `import("@/modules/mcpIntegration/mcp/runtime")`、`import("@/modules/localRuntime/mobileLink")`，与 `AGENTS.md`“跨模块引用统一用 alias（`@/modules/pluginMarket`）”的示例形态存在张力。均为动态 import（不进静态求值图），风险低；建议在 `AGENTS.md` 补一句“bootstrap 的 2 条运行时启动深引为例外”，把口径写死。

**P3-4｜两套“模块边”计量口径未在文档中区分**
`ServerModule.dependencies` 的口径是**仅模块目录**（`modules/<id>/**`）；地图子图口径是**全 server-api 文件**（含 `routes/**`、`lib/**`）。因此子图存在 `local_runtime→asset_library 3`（来自 `routes/workspaces/files/{thumb,remove}.ts` 引用 `assetLibrary/assets/{thumb,guard}`）、`local_runtime→media_generation 1`、`platform_core→media_generation 1`（`routes/settings/save.ts`）等“入口契约里看不到”的边。两者各自自洽，但同一名词在 `AGENTS.md` 同段落中并用易被误判为漂移。建议在 `AGENTS.md` 的 `dependencies` 行注明“口径 = 模块目录内直引，不含 routes/**”，并说明子图口径。

**P3-5｜台账行数口径未标注**
`AGENTS.md` 与地图 `review_note` 记 `server-api` 为 14,584 行；按文件行数（含末行无换行）为 14,586 行。差 2 行属 `wc -l` 与“行数”口径差，建议在地图 `review_note` 注明口径或改为区间表述。

**P3-6｜地图元数据与 override 不一致**
`.easyvibe/map/_analysis/meta.json` 的 `languages` 含 `Kotlin`、`loc=97,878`；`map.json` 为 7 项（无 `Kotlin`）、`loc=98,243`，两者 `generated_at` 相同。建议 `finalize` 后加一步“override 键逐项回读校验”，避免地图元数据内部自相矛盾。

**P3-7｜工作区卫生**
未跟踪产物包含迁移前快照 `.easyvibe/map/_analysis/edges_raw2.json`（仍列 `apps/server/src/utils/**` 旧路径）、6 个 `growth.log.*.bak`/2 个 `map.json.*.bak`、`_analysis/*.out|*.json`、`.easyvibe/map/_tools/stage.py`，以及仓库规定的文档目录之外的 `.claude/liyuhang/development_docs/task_*.json`。仓库既有的确会跟踪部分 `_analysis/*.out` 与 `*.bak`，但把 `edges_raw2.json` 这类**迁移前路径快照**一并提交会让“旧路径”在地图中残留。建议提交时只纳入与被审改动相关的产物，过程文件不入库。
