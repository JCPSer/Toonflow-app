## 2. 运行时能力验证（关键前提）

`df` 可用空间增量是判断「是否真的写时复制」的唯一可靠口径；`du` 会把共享块按整份计入，不能用来判定。

| 场景 | Bun 1.3.11 | Bun 1.4.0（安装包） | Node 25.5.0 |
| --- | --- | --- | --- |
| `copyFileSync / copyFile(EXCL \| FICLONE)` 复制 2GB / 256MB | 可用空间 +0 | +0（4KB 级元数据） | **等于文件大小（静默全量复制）** |
| `fs.cp` 目录复制 256MB | +0（含权限位一致） | +0 | 等于文件大小 |
| `cp` 前先 `mkdir(target)` 再 `fs.cp(force:false, errorOnExist:true)` | 通过 | **`ERR_FS_CP_EEXIST` 失败** | **`ERR_FS_CP_EEXIST` 失败** |
| 非 APFS 卷（FAT 实测） | 降级全量复制，`EEXIST` 语义保留 | 同左 | 同左 |

结论：服务端生产运行时是 Bun，单文件 COW 生效；Node 下自动降级为普通复制，功能正确性不受影响。
推论：目录复制不需要自己实现（Bun 的 `fs.cp` 本来就 reflink），需要改的只是「不要预先 mkdir」——
Bun 1.3.x 容忍，1.4.0 与 Node 会直接失败。

## 4. 接口级验证（隔离实例：端口 3899 + 临时数据目录，不触碰用户真实应用与画布）

### 4.1 会话克隆 `/api/agent/clone`

| 用例 | 结果 |
| --- | --- |
| 正常会话（末尾有换行） | 200，副本 = 源文件字节前缀 + 追加 `session_info`，逐行 JSON 合法，名称「新对话 · 副本」 |
| 末尾缺换行的旧会话 | 200，自动补 `\n` 后再追加 `session_info`，未出现行粘连，3 行均为合法 JSON |
| 副本与源字节前缀一致性 | `dst.startswith(src) === true` |

### 4.2 目录复制 `/api/workspaces/files/copy`（最终实现：`fs.cp` 且不预先 mkdir）

在安装包运行时 **Bun 1.4.0** 下复测：

| 用例 | 结果 |
| --- | --- |
| 含 300MB 文件 + 嵌套目录 + 空目录，源目录 `chmod 700` | 200，结构完全一致（含空目录），可用空间增量 **0MB**，**副本权限 700 = 源** |
| 目录内含符号链接 | 500 `ECOPYINCOMPLETE`，消息仍为「复制未完成，已复制的内容保留在 …。不能复制包含符号链接或特殊文件的文件夹」 |
| 目标已存在 | 409 `EEXIST`，原内容不被覆盖 |

对照（第一版自实现递归）：结构一致、同样 0MB，但副本权限被削成 **755**；且在 Bun 1.4.0 上因「先 mkdir 再 cp」直接失败。两组数据共同决定了最终实现。

## 6. 未覆盖 / 已知限制

0. 目录复制不再持有「根路径整树」的写锁（逐文件复制由 `fs.cp` 内部完成，外层锁只覆盖根路径）；
   子路径本来就不受精确路径锁保护，现有调用方（文件树复制、素材跨卷移动）外层都有更粗的锁，记录为已知项。
1. 未测试 Windows / Linux 卷（FICLONE 在 Btrfs、XFS 可用，NTFS/FAT/exFAT 会降级为普通复制）。
2. 未测试「克隆后 SDK 回退（rewind）」路径：`SessionManager._rewriteFile()` 用 `openSync(file,"w")` 原地重写，会让副本在那一刻全额分叉——预期行为，不影响正确性。
3. 克隆时仍会把源文件整体读一遍来算展示名（`readFile` + `parseSessionLines`），100MB 级会话有内存与耗时成本；本次只解决磁盘占用，读取优化留待「工具结果外置」那一轮。
4. 运行中的会话克隆仍走内存快照（本轮内容未落盘，没有可复制的源文件），不在 COW 覆盖范围。

## 7. 复现命令（节选）

```bash
bun <script>  # 直接调用 packages/file/src/index.ts 的 copyFileClone，用 df -k 前后差做口径

# 接口级
TOONFLOW_SERVER_PORT=3899 TOONFLOW_DATA_DIR=<tmp> NODE_ENV=dev bun src/index.ts   # 在 apps/server 下
curl -X POST http://127.0.0.1:3899/api/agent/clone \
  -H 'x-toonflow-workspace: 1' -H 'Origin: http://127.0.0.1:3899' \
  -H 'Content-Type: application/json' -d '{"directory":"<proj>","sessionFile":"<file>.jsonl"}'
```
