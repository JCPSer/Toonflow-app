## 七、评审后修正（2026-10-29 00:20）

子 agent 评审（对着需求文档逐条核对，含 Vue Flow 1.48.2 与 conversation.vue 的实例假设）提出 2 个 blocker、9 个 should-fix，已全部处理：

| # | 问题 | 修法 |
| --- | --- | --- |
| B1 | 新节点首次发送必定「请先选择模型」，而面板按需求隐藏了选择器 | `conversation.vue` 补模型兜底：已选值不在可选列表时落到第一个可用模型 |
| B2 | 面板在会话加载完成前就挂载，重开显示空对话 + 状态错乱 | 增加 `loaded` 标记，加载完成才渲染 `conversation`；同时天然挡住加载中发送 |
| S3 | 打开第二个节点时前一个面板不收起 | `open()` 先隐藏上一个，仍需保证唯一可见 |
| S4 | 删除清理的 watch 不触发（`getNodes` 原地 push/splice） | 改监听 id 串；面板同理 |
| S5 | 克隆失败 / 500 会污染 `agentSessionCloneFrom` 甚至清掉有效绑定 | 指针先消费再请求；只有 404 才解绑，其它错误保留 |
| S6 | 空输入 + 有上游时会发出一条「只有引用没有指令」的消息 | 用注入前的正文做空判断 |
| S7 | 上游引用在整个面板生命周期内不刷新 | 边/节点变化 250ms 去抖后重建 |
| S8 | 清理可能删掉仍被复制节点引用（`cloneFrom`）的会话 | 删除前检查是否被任何节点引用 |
| S9 | 删除会话不清理子会话；409 后无重试 | 复用 `removeSessionFiles` 递归清理；409 排一次 10s 重试 |
| S10 | 克隆运行中的源会话会拷出半行 | 与 fork 一致返回 409 |
| S11 | 首轮在落盘前被停止，之后每次发送都 404 | `conversation` 新增 `sessionLost` 事件，面板解绑，下次发送重建 |
