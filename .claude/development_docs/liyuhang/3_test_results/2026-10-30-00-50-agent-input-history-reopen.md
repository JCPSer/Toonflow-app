# 测试结果：Agent 面板输入历史在重开后失效

- 时间：2026-10-30 00:50
- 对应方案：`4_bugs_fix/bug_solution-2026-10-30-00-45-agent-input-history-reopen.md`

## 1. 环境

应用 `/Applications/toonflow-exec.app`（桌面端，23:58 重启，server 端口 64029），浏览器客户端直连该端口，使用真实项目 `蕾姆Rem` 的 Agent 节点会话（会话 75 条用户消息）。

## 2. 修复前（临时日志插桩）

在 `handleHistoryKey` 打印守卫状态，复现到被阻塞的状态：

| 步骤 | 观测 |
| --- | --- |
| 翻历史取出带 `@` 提及的消息 → 清空输入 → 按 ↑ | `{ text:"", mentions:1, empty:false, len:59 }`，`afterUp: ""`（无任何反应） |
| 同上，但不清空直接按 ↑ | 因草稿非空按设计不进入历史 |
| 面板关闭再打开后再按 ↑ | 仍带同一条幽灵提及（实例被 `hasDraft` 保留），依旧无反应 |

结论：幽灵提及让 `draftEmpty()` 恒为 false，且让面板实例跨关闭保留，坏状态无法自愈。

## 3. 修复后（终版：不回收数组、判空查标签、填充窗口豁免、收起时代次复位）

| 用例 | 期望 | 实测 |
| --- | --- | --- |
| 清空输入后按 ↑ | 立即翻出历史 | `{ text:"", mentions:0（标签集为空）, empty:true }`，翻出上一条用户消息 |
| 打开 → 关闭 → 重开 → ↑ | 能翻出关闭前的历史 | 双端浏览器实测通过（同一会话最早一条可达） |
| 带草稿关闭 → 重开 | 草稿保留，清空后 ↑ 可用 | 通过（草稿 "诊断草稿abc" 保留，清空后 ↑ 翻出旧消息） |
| 历史还原（带提及） | 提及数组与编辑器标签一致 | 代码路径核对：不回收数组，发送按 `getTagData` 过滤；还原后标签存在 |
| 删标签后 ⌘Z 撤销 | 标签回来，发送不被"存在无法读取的提及"拦下 | 代码路径核对（数组保留元数据；终版取消回收后成立） |
| 程序化插入期间关面板 | 不丢提及、不卸载写入中的实例 | 代码路径核对（`insertingMentions/historyFilling` 时 `hasDraft` 为 true、`draftEmpty` 为 false、`handleHistoryKey` 直接返回） |
| 幽灵提及闭环（清空 → 关闭 → 重开 → ↑） | 仍可用 | 实测通过（清空后 mentions 标签集为空，重开 ↑ 正常） |
