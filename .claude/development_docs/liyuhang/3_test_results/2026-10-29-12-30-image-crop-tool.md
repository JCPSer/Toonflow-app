## 四、测试中发现并修复的缺陷

| # | 现象 | 根因 | 修复 |
| --- | --- | --- | --- |
| 1 | 遮罩错位：图片右侧出现一条延伸到图片外的黑块，顶部不变暗 | 浮点残差产出 `7.10543e-15%`、`100.00000000000001%` 这类非法 CSS，浏览器整条丢弃并保留上一帧的值 | 新增 `pct()`：夹紧 0–100 并定点到 3 位小数，`boxStyle`/`maskStyle` 全部改用 |
| 2 | 关闭再开同一张图，裁剪框总是重置 | `last` 写入用 `source.url`（工作区路径），读取却比 `props.src`（blob URL），重启/重挂载后必然失配 | 读写统一用 `props.source?.url` |
| 3 | 弹窗按 Esc 关不掉 | 内容根节点 `@keydown.stop` 拦住了 Element Plus 挂在 document 上的 Esc 监听 | 去掉 `@keydown.stop`；画布侧靠 `.el-overlay`/`[role=dialog]` 守卫让路（实测不会误触退出项目） |
| 4 | 方向键微调无效 | 只绑了 `@pointerdown`，`@keydown` 没绑到舞台 | 舞台加 `@keydown="onKeydown"`，并在处理内 `preventDefault` |
| 5 | 先输 X 再输宽度，X 被夹回 0 | `applyFields` 用 `clampRect` 平移夹紧，宽度仍是整图时 x 只能为 0 | 改为「用户输入的 X/Y 优先，溢出时收缩宽高」，并补比例二次修正 |
| 6 | TIFF 等浏览器不能解码的格式，弹窗永远停在「正在读取图片尺寸…」 | 只判了 `naturalSize` 缺失 | 新增 `loadFailed`，提示「该图片格式无法在浏览器内解码，请先转为 PNG/JPEG 再裁剪」，应用保持禁用 |
| 7 | 拖动手势每结束一次就写一次 `node.data` | `persistLater(0)` 在手势结束触发，等于每拖一下都触发画布自动保存 | 只在关闭弹窗时落一次 `last`，且要求 `rectSource === source.url` |
| 8 | 扩展名与真实内容不符时会把透明区压成黑块 | `resolveOutputFormat` 只看 URL 后缀 | 改为优先用 `source.mimeType` 判定，动图/未知格式统一回退 PNG |

## 四点六、落盘"看起来失败"的假象（重要）

测试期间多次出现「应用成功、节点已换图，但画布 JSON 仍是旧输出」。用 400ms 轮询抓到真相：

```
12:55:26 out=crop-320x240-…png  crop=[previous, appliedUrl]   ← 我的浏览器标签写对了
12:55:37 out=image55cf0b48….png  crop=[]                      ← 被另一个客户端覆盖
```

原因是桌面窗口与浏览器标签**同时在线**，两边各自有 500ms 防抖的自动保存，互相覆盖。裁剪本身的写入是对的，**不是功能缺陷**。真实使用只有桌面窗口一个客户端时不会出现。

## 六点五、代码审查（子 agent）后的修正

子 agent 判定 3 条阻断级、若干建议级。阻断级全部修复并回归验证：

| # | 问题 | 修复 | 回归证据 |
| --- | --- | --- | --- |
| B1 | **整图框铺满时 `@pointerdown.stop` 吞掉按下事件**，真实用户永远拖不出新框（此前的自动化测试直接对舞台派发事件，掩盖了这个问题） | `.cropBox` 改 `pointer-events:none`（手柄单独 `auto`），命中判定交给舞台：框内拖动=位移、框外拖动=新建，整图状态下任何位置拖动都按新建 | 在图片 30% 处按下（`elementFromPoint` 命中 IMG 而非 cropBox）拖到 55%，得到 `538/710/448/474`，与坐标换算完全一致 |
| B2 | 比例锁下拖手柄到边界时，`clampRect` 只平移会让"固定边"漂移 | 重写 `fromCreate`/`fromResize`：先按锚点侧可用空间夹紧尺寸，再按锚点摆放位置 | 1:1 下把 e 手柄拖出右边界，左边仍为 125（锚点不动），结果 350×350，比例恰为 1.000，未越界 |
