## 四、审查后发现并修复

| 编号 | 问题 | 修复 |
| --- | --- | --- |
| I1 | 全量轮在文件树刷新后可能重复触发，撞上「先建目录、后加节点」的媒体任务窗口 | 全量轮改为按目录计数，最多两次；失败 5 秒后重试一次，不再以「是否成功」决定是否重跑 |
| I2 | 扫描时画布 404 被静默跳过，可能误删刚被移动的画布素材 | `readCanvasFiles` 新增 `failOnMissing`，清理调用遇到 400/404 直接整轮放弃 |
| I3 | 50 万工作量上限会让既有「删除画布」在文件已删后报错 | `getCanvasAssetDirectories` 捕获超限，退化为只按节点 ID 判断 |
| I4 | 上传/AI 改写输出后「恢复缩放前」成为死按钮 | 上传与 `setImage` 清除缩放记录；子组件仅在 `appliedUrl === 当前输出` 时显示恢复按钮 |
| S7 | 卸载后 400ms 防抖仍会写 `node.data.scale` | `onBeforeUnmount` 清理 persist timer |

## 五、未覆盖

- 撤销历史淘汰（第 102 个快照裁掉最旧一步）触发的回收：需要连续 100+ 次画布操作，未在 E2E 中构造。
- 文件树删除画布/文件夹后的即时回收：代码已接入候选，未做端到端点击验证。
- 删除时的 EBUSY、扫描期间的 404/画布移动竞态：仅代码路径核对。
- 画布复制进行中的回收避让：仅代码路径核对（`assetCopyInProgress`）。
- 打包 app 内的运行验证：已重打包 `/Applications/toonflow-exec.app`（备份 `/tmp/toonflow-exec-old10.app`），并同步 `data/nodes`、`data/ext`；需 ⌘Q 重开后确认。
- 移动端布局与真实项目（`/Volumes/WD_BLACK_MAC/...`）的清理：未在用户真实项目上执行，避免未经确认删除 266 MB 素材。

## 六、已知边界

- 节点存续期间重复缩放会累积 `resize-*` 中间文件；孤儿回收只处理整个节点目录，不会单独清理这些中间文件，节点目录被回收时一并删除。
- 切换画布不会中止缩放任务（后台画布实例保留），与宿主「后台任务不打断」策略一致；只有切换工作区、删除节点或源图变化才中止。
