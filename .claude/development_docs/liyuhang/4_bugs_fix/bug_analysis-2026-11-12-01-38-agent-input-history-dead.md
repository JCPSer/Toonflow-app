# Bug 分析：Agent 输入框按 ↑ 翻历史无反应

- 时间：2026-11-12 01:38
- 提出人：liyuhang
- 优先级：P2（效率功能失效，不影响消息发送）
- 状态：正常路径已实测通过；针对「运行实例卡死」补了护栏（待重启验证）

## 1. 现象

Agent 对话输入框清空、Agent 空闲时按 ↑，没有任何反应（不翻出历史消息，光标也不动）。用户感觉「以前能用，现在失效」。

## 2. 代码与实测证据

| 项 | 结论 |
| --- | --- |
| 历史代码 | `messageInput.vue` 的 `handleHistoryKey/stepHistory/restoreHistory` 自 2026-10-30 修复后未再改动；11-08 的批次只改了 `conversation.vue` 的 canvasCall origin，与历史无关 |
| 部署产物 | 当前 `index.html` 引用的 chunk（`workspace-VMGv0Vx0.js`）包含 `clearHistory`、`role==='user'` 等历史逻辑 |
| 数据 | 用户会话文件里用户消息成百条（如 `2026-11-11T10-13-13-873Z` 会话 151 条），`historyMessages` 不会为空 |
| 实测 | 用浏览器客户端直连应用端口（`/index.html?web=1`，非 desktop 模式可看隐藏项目），打开 `蕾姆Rem` 的 Agent 节点面板：清空输入按 ↑ 能翻出带 @ 提及的历史消息；**关闭面板重开后再按 ↑ 仍能翻出**（2026-10-30 的幽灵提及修复仍然有效） |

结论：功能本身在当前构建上工作正常，问题出在**运行实例的局部状态**，不是代码回归。

## 3. 根因候选

1. **历史还原挂起（最可疑）**：`restoreHistory` `await` x-sender 的 `reset()` 与 `nextTick()`。面板隐藏/窗口失焦时这些 Promise 可能永不结算：
   - `historyFilling` 永远为 true → `draftEmpty()` 恒 false、`handleHistoryKey` 直接返回 → ↑ 永久失效；
   - `hasDraft()` 也恒 true → 面板关闭不卸载实例 → 重开面板仍是同一个坏状态；
   - `historyQueue` 链在挂起的 Promise 上，后续按键永远不会执行。
2. 幽灵提及：10-30 已修，本次实测未复现。
3. 其他数据前提：`props.busy`（运行中按设计不翻）、`props.history` 为空（新会话）；用户确认空闲、输入框已清空。

## 4. 目标

让「还原挂起」不再造成永久失效：每一步有上限，卡死可自愈；正常路径行为不变。

## 5. 风险

- 超时只影响异常挂起路径，正常还原几十毫秒完成。
- 超时后不会强行写入半成品内容，只释放标记与队列。
- 需要重启应用生效；重启本身也会清掉当前卡死的实例状态。
