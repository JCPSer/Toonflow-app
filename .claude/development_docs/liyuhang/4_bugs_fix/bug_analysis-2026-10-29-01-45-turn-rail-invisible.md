# Bug 分析：轮次目录条整体消失，右侧只留一条空白槽

- 记录时间：2026-10-29 01:45
- 代码基线：`897da71`
- 用户原话：「agent 面板明显有一个空白区域占位，导致显示观感不好，不对称」「历史记录控件没有渲染出来」（确认：主对话面板与 Agent 节点面板都一样，指的是右侧轮次目录条）

## 一、Bug 矩阵

| 编号 | 背景 | 现象 | 目标 | 优先级 | 难度 | 风险 |
| --- | --- | --- | --- | --- | --- | --- |
| B1 | 上一轮把目录条改成「高度按内容 + 垂直居中」，顺手把列表从 `flex: 1` 改成 `flex: 0 1 auto` | 目录条整体不可见；右侧只剩 34px 宽的空白槽，两个面板都复现 | 目录条恢复显示：收起态一行一短横，悬停展开提问列表 | P0 | 低 | 低：纯样式回归，数据与交互逻辑未受影响 |
| B2 | 消息列表无条件 `padding-right: 34px` 给目录条留槽 | 轮次不足 2 条（不渲染目录条）时，右侧仍挂一条空白 | 只有真的渲染目录条时才留槽 | P2 | 低 | 低 |

## 二、根因

`.turnRail` 是 `display: flex`，默认 `flex-direction: row`，内部只有一个子元素 `.turnRailList`。上一轮为了让高度按内容收缩，把列表写成 `flex: 0 1 auto`（没有宽度）：

1. 列表作为**横向** flex 容器的项目，宽度按内容 max-content 计算；
2. 列表内容是纵向 flex 的按钮，按钮宽度靠 `align-items: stretch` 撑满列表宽度（循环依赖，解为 0）；
3. 按钮里唯一可见的短横是绝对定位（`inset: 0` + `margin: auto`），不撑宽度，而按钮上的索引/文字是 `display: none`；
4. 于是列表宽度 = 0，短横被列表的 `overflow: hidden` 裁掉 → 整条目录不可见。

空白槽则来自 `.messageList` 无条件预留的 34px。

## 三、结论

`flex: 0 1 auto` 想控制的是**高度**，但它在横向 flex 容器里作用于**宽度**，方向搞错了。正确做法是让 `.turnRail` 变成纵向 flex（子项默认 `align-items: stretch` 撑满 26px 宽），列表的高度继续用 `flex: 0 1 auto + min-height: 0` 收缩。

## 四、评审意见

- 子 agent 初审：（回归修复，改动极小，未单独跑初审）
- 用户评审：已确认两个面板现象一致、控件就是右侧轮次目录条。
- 结论：按纵向 flex + 条件空槽修复。
