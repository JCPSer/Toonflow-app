# Bug 分析：复制 Agent 节点后两边对话像「孪生兄弟」一样同步

- 时间：2026-10-31 21:20
- 来源：用户转述使用者反馈
- 状态：已定位并修复（防御性）

## 一、现象

复制 Agent 节点（创建副本 / 拖拽复制）后，两个节点的对话内容保持同步：在一边发消息，另一边也会出现，看起来不像各自独立的副本。

## 二、影响与优先级

| 项 | 判断 |
| --- | --- |
| 影响面 | 画布上所有 Agent 节点复制场景；一旦命中，两条独立创作线会互相污染上下文 |
| 数据风险 | 会话文件被两个节点共用，删除/回退其中一个会波及另一个 |
| 优先级 | P1（功能正确性问题，不阻塞启动） |
| 难度 | 低（画布层兜底 + 打开时自愈） |
| 风险 | 低（只影响 Agent 节点复制路径，不碰会话内容与压缩逻辑） |

## 三、代码走查结论

### 3.1 现有设计（本应防住孪生）

| 环节 | 行为 | 位置 |
| --- | --- | --- |
| 节点复制 | Agent 节点注册 `copy` 事件：清空 `agentSessionFile`、留下 `agentSessionCloneFrom` | `packages/nodes/agentNode/src/index.vue:91` |
| 复制落节点 | 画布把补丁合并进副本数据 | `selectionToolbar.vue:133`、`index.vue:1498` |
| 首次打开面板 | 发现待克隆指针才调用 `/api/agent/clone`，服务端生成新 UUID 文件名并写入独立 jsonl | `agentNodePanel.vue:207`、`sessions.ts:666` |
| 另存 / 导入 / 跨工程粘贴 | 单独把 `agentSessionFile` 转成 `agentSessionCloneFrom` | `canvasFiles.ts:126` |

按当前源码，复制不会共用会话文件；服务端克隆也是逐字节复制 + 新文件名，不存在硬链接或共享 inode。

### 3.2 仍可能孪生的缺口

| 编号 | 缺口 | 触发条件 | 后果 |
| --- | --- | --- | --- |
| B1 | 节点 `copy` 事件是 2026-10-29 之后才加入的 | 旧版客户端 / 旧节点包 | 副本原样带走 `agentSessionFile`，两边共用同一 jsonl |
| B2 | `emit("copy")` 依赖节点组件已挂载；组件未渲染、脚本加载失败时返回空补丁 | 节点包加载异常、非常规渲染路径 | 同上 |
| B3 | 剪贴板复制（节点菜单「复制到剪贴板」）与粘贴链路在画布层没有二次校验 | 旧剪贴板数据 / 节点事件异常 | 粘贴出的节点带同一个会话文件 |
| B4 | 历史画布中已经存在两个节点指向同一会话文件的脏数据 | 曾经用旧版本复制过 | 更新后仍持续同步，不会自愈 |

## 四、结论

- 当前主路径设计正确，问题集中在「复制动作过度依赖节点包事件」与「历史脏数据无人修复」。
- 修复方向：在画布层做与节点包无关的最后一道兜底；打开面板时检测并自动分离已共享的会话。
