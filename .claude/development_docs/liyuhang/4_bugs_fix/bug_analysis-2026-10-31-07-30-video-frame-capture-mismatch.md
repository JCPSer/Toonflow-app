# Bug 分析：视频节点「截取首/尾帧」与视频真实帧不一致

- 时间：2026-10-31 07:30（初次）/ 2026-10-31 08:10（按子 agent 初审修订）
- 代码基线：`f72ee6f`
- 影响文件：`packages/nodes/videoNode/src/components/videoPlayer.vue`（`captureFrame` / `loadFrame` / `presentedFrame` / `nudgeFrame`）
- 关联节点：`videoNode`、`videoGenerationNode`（共用同一 `videoPlayer` 组件）

## 1. 背景

用户在视频节点用「截取首帧 / 截取尾帧」，把截出的图片与视频本身对比：
在剪映里把原视频与截图放在同一条时间线目测（未导出），两者亮度和细节都对不上，截图更亮。
进一步：把截出的尾帧喂给「首尾帧生视频」工作流（MiniMax H3，首/尾帧必填）做接续，接续出现跳变、不连贯。
用户已明确：**亮度问题与截取位置偏差无关，是另一件事。**

## 2. 现象

| 项 | 现象 | 归属 |
| --- | --- | --- |
| 亮度 | 截出的 PNG 比视频画面整体偏亮，用户确认量级为「约 2 个灰阶」 | 成因 B |
| 细节 | 与真实首帧/尾帧画面内容不同（动作位置、构图） | 成因 A |
| 下游 | 用截出的尾帧做首尾帧接续，接缝不连贯 | 成因 A |

## 3. 实测

素材：工程内 24fps / 1600×2112 / H.264 / yuv420p / `color_range=tv` / `bt709` / `trc=iec61966-2-1`，
481 帧，`format.duration=20.041`，末帧 PTS=20.000。
测量脚本与对照图未入库，参数见本节（ffmpeg 7.x 默认 swscale，PNG 输出 `-pix_fmt rgb24`）。

### 3.1 成因 A：取帧时刻不是首/尾帧

`loadFrame`（`videoPlayer.vue:305-308`）写死：

```
first: target = max(0.05, ...)
last : target = max(0.01, duration - 0.05)
```

浏览器 `currentTime` 的语义是「包含该时刻的那一帧」，由此：

| fps | 0.05s 落在 | `duration-0.05` 落在（duration = 末帧结束时间 ≈ N/fps） |
| --- | --- | --- |
| 24 | frame #1（第 2 帧） | frame N−2（倒数第 2） |
| 25 | #1 | N−2 |
| 30 | #1 | N−2 |
| 50 | #2 | N−3 |
| 60 | #3（边界） | N−3 / N−4 |

即**偏移约 ⌈0.05 × fps⌉ 帧**，不是固定 1 帧；`duration` 取自 `mvhd`，其定义、音轨长度、首帧 PTS≠0、edit list、VFR 都会改变具体帧号。
本素材实测：相邻帧 PSNR 仅 16.99–19.6dB（画面差异极大），因此「细节不一样」成立；尾帧偏早也是接续跳变的直接原因。

### 3.2 成因 B：颜色管线数值差（与帧位置无关）

同一时刻、同一帧，用三种解码口径取帧后比对（不涉及任何 PNG 色彩标记解释）：

| 管线 | 说明 | 与 ffmpeg 的差 |
| --- | --- | --- |
| WKWebView canvas（应用现在用的） | 与应用同一内核 | 高 1.75/255（中位 +2） |
| AVFoundation（QuickTime/系统播放器所见） | macOS 系统解码 | 高 1.75/255，且**与 canvas 逐像素相同**（mse=0） |
| ffmpeg | 剪映/PR/ffmpeg 系工具口径 | 基准 |

- 分区间统计：ff 值落在 0–32 / 32–64 / … / 224–255 时，`canvas - ffmpeg` 分别为 +1.65 / +1.93 / +1.77 / +2.03 / +1.70 / +1.74 / +1.68 / +1.75，与 ff 值相关性仅 0.106 → **是近似恒定的直流偏移**，不是 gamma 曲线、也不是范围缩放；中位数恰为 +2，与用户目测「约 2 个灰阶」一致。
- 合成灰阶视频（16 级灰度、与真实素材同色彩标记）复现同一现象：AVFoundation/canvas 输出 == 原始灰度值，ffmpeg 低 1.3–2.0。
- **已排除「PNG 色彩标记差异」**：canvas 输出带 `sRGB` chunk，AVFoundation 输出带 `iCCP(QuickTime 'nclc' Video (1,13,1))`；两者用 ColorSync 转到同一 sRGB 空间后逐像素差为 0（max 0 / mean 0.0 / 差异像素 0），即两种标记等价 → 用户看到的差异来自**像素数值本身**，与 ICC 无关。
- 结论：WebKit/系统解码与 ffmpeg 的颜色转换口径不同，差一次近似恒定的 +2/255；剪映预览是 ffmpeg 系口径，所以截图在剪映里显得更亮。

### 3.3 成因 C：空帧重试会换帧（初审补充）

`nudgeFrame`（`videoPlayer.vue:367-377`）在画布全透明时把 `currentTime` 挪 ±40ms 再取帧，**成功后不回位**：
首帧可能从 0.05 漂到 0.09（24fps 下再往后 1 帧），尾帧从 `D-0.05` 漂到 `D-0.09`。
重试是「静默换帧」，会与成因 A 叠加。

### 3.4 成因 D：呈现容差过宽

`presentedFrame`（`:328-359`）在 `|mediaTime - target| ≤ 0.15` 时就认为目标帧已呈现。
24fps 下 150ms ≈ 3.6 帧，50fps ≈ 7.5 帧；seek 刚落盘时先到的旧帧也落在容差内会被接受。`截取当前帧` 同样受影响。

## 4. 根因

1. **A**：取帧时刻写死 `0.05s` / `duration-0.05`，不是「首帧=frame 0、尾帧=最后一帧」。
2. **B**：取帧在 WebView 里做，颜色转换走 WebKit/系统色彩管理，与 ffmpeg、剪映等工具口径不同（恒定 +2/255）。
3. **C**：空帧重试挪动时间且不回位。
4. **D**：呈现容差 150ms 远大于一帧。

## 5. 影响面

| 位置 | 是否属于本 bug |
| --- | --- |
| `videoPlayer.captureFrame`（视频节点/生成节点菜单） | 是（A/B/C/D 全命中） |
| `videoPlayer.readPreview`（无服务端海报时的 canvas 封面） | 否，但同为 canvas 取帧，色差相同（仅封面） |
| `videoActions.loadThumbnails`（裁剪面板 10 张预览条） | 否，仅预览，不改 |
| `referenceCard.vue`（引用卡缩略图） | 否，仅预览 |
| 服务端 `assets/thumb.ts`（`-ss 0.5` 固定） | 否，且**节点海报本来就不是 frame 0**，不要把「截图与海报不一致」误判为新 bug |
| `videoGenerationNode` 的 `firstFrame/lastFrame` 下游 | 是（A 的直接受害者） |

## 6. 期望

1. 「首帧」= frame 0，「尾帧」= 最后一帧；与 ffmpeg 系工具（剪映）同帧、同像素。
2. 截出的 PNG 与视频在剪映里并排时无可感知亮度差（≤1/255）。
3. ffmpeg 不可用（未安装、移动端）时：**帧序仍正确**，只保留已知的 +2/255 色差，且不崩、不弹安装引导。

## 8. 验收标准（可执行）

真值一律用 ffprobe 帧表 + ffmpeg 独立命令产出，**不复用实现里的同一条命令**：

| 编号 | 验收点 | 判定方法 |
| --- | --- | --- |
| A1 | 首帧正确 | `ffprobe -show_frames` 第 1 帧 PTS → `ffmpeg -ss <pts> -i in -frames:v 1` 产出真值；截图与之逐字节比对（`cmp`），要求完全一致 |
| A2 | 尾帧正确 | 同上取最后一帧 PTS 的真值；截图与之逐字节一致 |
| A3 | 亮度与剪映一致 | 截图与 ffmpeg 真值的整幅均值差 ≤1/255（不含 alpha 与边缘 1px） |
| A4 | 帧序正确（无 ffmpeg 时兜底） | 兜底产物与 A1/A2 真值做结构比对（缩放到 64×84 后归一化 L1 距离 <0.03），允许色差 |
| A5 | 旋转视频 | 90° 旋转元数据素材：宽高与画面方向与播放器一致，A1/A2 仍成立 |
| A6 | 短视频 / VFR / 无音轨 / start_time≠0 | 各自能截出真正首/尾帧，不报错 |
| A7 | 播放中截帧 | 播放不中断、进度不变；截出帧与暂停后同位置截帧一致 |
| A8 | 取消与清理 | 截帧中途切画布/删节点：ffmpeg 进程被杀、无残留 `assets/<id>` |
| A9 | 移动端 | 无 ffmpeg 时走兜底，A4 通过 |
| A10 | 下游接续 | 用截出的尾帧跑首尾帧接续，人工确认无跳变（模型随机性下只验「起始帧一致」） |
