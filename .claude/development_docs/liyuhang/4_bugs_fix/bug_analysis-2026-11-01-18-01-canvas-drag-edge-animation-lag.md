# Bug 分析：拖动多连边节点时画布卡顿

- 时间：2026-11-01 18:01
- 提出人：用户
- 现象：拖动一个连着 7 根线的节点，整个拖动过程「持续发涩、跟手延迟」；松手即恢复
- 状态：已定位根因，待方案评审

## 1. 背景

画布基于 `@vue-flow/core@1.48.2`，边为内置 `simplebezier`，每条边一个独立 `<svg>`。应用通过 `defaultEdgeOptions.class` 函数给「有端点选中/正在拖动」的边追加 `edgeNodeActive / edgeActive / animated` 三个类名，其中 `animated` 触发应用自定义的虚线流动动画（`stroke-dashoffset`，`steps(20)` 约 10 Hz 失效重绘）。

## 2. 复现与定位

| 步骤 | 结果 |
| --- | --- |
| 用户环境（WKWebView 打包应用，20–50 节点画布）拖动 7 连节点 | 持续掉帧、跟手延迟 |
| 设置 → 常规配置 → 关闭「连线流动动画」后再拖同一节点 | **不卡了** |
| 静态链路核对 | 拖动期间 `active` 为真 → 被拖节点关联边全部带 `animated`；每条边 10 Hz 触发 SVG path 重绘，且几何同时在变 |
| 历史对照 | `bug_analysis-2026-10-26-17-10-workspace-perf.md` 实测：21 条边动画时最大帧 17 ms → 267 ms |

结论：主因是「拖动期间给关联边挂虚线流动动画」，不是边组件重渲染本身，也不是 O(N+E) 的每帧全表扫描（20–50 节点规模下这部分可忽略）。

## 3. Bug 矩阵

| 编号 | Bug | 优先级 | 复杂度 | 风险 |
| --- | --- | --- | --- | --- |
| B1 | 拖动节点时，其关联边被加上 `animated`，虚线动画以 10 Hz 持续重绘 SVG，边数越多越卡 | P0 | 低（一处类名计算） | 低：仅影响拖动期间的视觉 |
| B2 | 分组拖动时子节点自身 `dragging=false`，按「端点在被拖」判断会漏掉组内连边 | P1 | 低 | 中：漏判会导致分组拖动仍卡 |
| B3 | 若用「拖动开始置位/结束复位」的手动状态，拖动静默中断（切画布、卸载、指针丢失）可能让动画一直停 | P1 | 低 | 中：需要自愈机制 |
| B4 | 选中但未拖动的节点，关联边仍应保留流动动画 | P2 | 低 | 低：不能一刀切关掉动画 |

## 4. 不在本次范围

- 不改连线流动动画的默认开关与频率（用户已确认保留）。
- 不改拖动开始/结束的全画布 JSON 快照与分组重贴合（那是「起手/松手卡一下」，用户反馈的不是这一形态）。
- 不改节点组件重渲染、`interactionWidth`、`onlyRenderVisibleElements`。

## 5. 验收标准

1. 打开连线流动动画，拖动任意连边节点：拖动过程不再持续发涩，松手恢复流动。
2. 分组拖动、多选拖动、拖动复制时同样不卡（组内子节点的连边也不流动）。
3. 没有拖动时，选中节点的关联边仍正常流动（拖动进行中全画布统一暂停）。
4. 拖动被意外中断（切画布、切面板）后，动画不会永久停住。
5. 关闭连线流动动画时行为不变。

## 6. 评审意见

子 Agent 初评（2026-11-01 18:09）：

| 级别 | 意见 | 处理 |
| --- | --- | --- |
| P1 | 方案原以为「节点 dragging 派生状态天然自愈」不成立：d3-drag 只在 window 等 mouseup，拖动期间失焦/窗口外松开/切画布不会再有 nodeDragStop，`dragging` 会永久为 true，连线将一直停流动 | 已修：新增 `clearStuckDragging()`，在画布切换/失活 watch 与 `resetCanvasKeys()`（覆盖 window blur、设置面板开关）里复位 |
| P2 | 全局拖动态会让「已选中但没被拖的节点」的连边也暂停流动，验收口径要写清 | 已改口径：拖动期间全画布统一暂停，无拖动时选中节点照常流动 |
| P2 | `flow.getNodes` 在 `onlyRenderVisibleElements=true` 时会依赖 viewport，边缘 autoPan 可能让它每帧重算 | 已改用 `flow.nodes.value`（全量顶点，不受可见性开关影响） |
| P2 | 拖动复制开始时有很短的异步窗口没有节点处于 dragging，流动会短暂继续 | 接受：窗口极短且期间画布没有位移，不额外处理 |
| P2 | 拖动复制若在清理前中断，副本 `dragging` 可能残留 true | 由 `clearStuckDragging()` 在失焦/切画布时兜底；概率低，不扩大本次改动 |
| P2 | 「第一帧仍带动画」表述不准确，实际是越过 8px 拖动阈值且产生第一段位移之前 | 已改口径 |

结论：**修改后通过**，整改后实施。
