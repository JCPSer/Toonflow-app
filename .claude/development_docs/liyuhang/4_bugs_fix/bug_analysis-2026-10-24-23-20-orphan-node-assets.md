# Bug 分析：删除节点后节点素材目录成为永久孤儿

## 一、Bug 背景

工作区里每个节点的素材都写在 `assets/<节点ID>/` 下（图片节点上传、图片生成节点出图、音频/视频节点产物、文本节点正文）。节点删除后这些文件没有再被任何地方回收。

在用户当前项目实测（`/Volumes/WD_BLACK_MAC/.../ToonFlow项目-黑木`）：

| 指标 | 数值 |
| --- | --- |
| `assets/` 子目录 | 53 个 |
| 总占用 | 555.1 MB |
| 画布 JSON 中仍存在的节点 ID | 41 个 |
| 已无任何画布引用的目录 | 35 个（占 66%） |
| 孤儿占用 | 266.2 MB（占 48%） |

## 二、现象与复现

1. 在画布中上传一张图片到图片节点（或生成一张图），文件落在 `assets/<节点ID>/`。
2. 删除该节点。
3. 目录 `assets/<节点ID>/` 仍然存在，重启应用、重新打开项目也仍在。
4. 只有画布菜单里的「删除画布」会按 `getCanvasAssetDirectories()` 删除该画布独占的节点目录；文件树里删除画布或文件夹走 `performFileAction` 的 delete 分支，**不回收素材**。

补充事实：把节点输出「保存到素材库」只是把文件**复制**到全局素材库（`data/assets`），与工作区 `assets/<节点ID>/` 是两份独立文件；因此素材库里有没有副本并不影响工作区目录能否回收，也不会因为节点删除而失效。

## 三、根因

| 环节 | 现状 | 后果 |
| --- | --- | --- |
| 节点删除事件 | 各节点 `nodeEvent.on("delete")` 调 `files.removeNodeFiles()` | 表观上有删除动作 |
| 保留开关 | 画布 `provide("retainNodeFiles", true)`，`removeNodeFiles()` 直接 `return` | 删除动作实际是空操作 |
| 撤销历史 | 节点快照与 `nodeReferences` 只存在内存，最多 101 步 | 删除后靠它保留文件，刷新/重启即失去引用 |
| 回收路径 | 只有画布菜单的「删除画布」会计算并删掉独占的节点目录；文件树删除画布/文件夹不回收 | 单节点删除与文件树删除都没有回收路径 |
| 启动扫描 | 无 | 重启后历史清空，孤儿目录再无人认领 |
| 画布复制 | `copyCanvasFiles` 先复制素材目录、后写临时画布 JSON | 存在「目录已建、暂无引用」的短暂窗口，清理必须避让 |

结论：`retainNodeFiles` 的设计是「删除节点先保留文件，保证撤销能恢复图片」，但**缺少历史淘汰后的回收**，也没有启动时的孤儿扫描，于是文件永久残留。

## 四、Bug 目标

1. 节点目录在**不再被任何画布、任何撤销/重做历史引用**后自动回收，释放磁盘。
2. 撤销仍然可用：删除节点后立刻撤销，图片必须还在。
3. 不误删：只处理节点 ID 形态的目录，共享目录（`assets/chat`、`assets/generated`、`assets/imported` 等）一律不碰。
4. 读取画布失败时**整体放弃清理**，宁可不清也不能误删。
5. 不打扰用户：后台静默执行，失败只记录，不弹错、不阻塞画布操作。

## 五、Bug 矩阵

| 编号 | 描述 | 优先级 | 难度 | 风险 |
| --- | --- | --- | --- | --- |
| B1 | 打开项目后扫描 `assets/`，删除无画布引用的节点目录 | P0 | 中 | 画布 JSON 读取失败时若继续执行会误删，必须整体放弃 |
| B2 | 撤销历史淘汰节点后，回收对应目录（不必重启） | P0 | 中 | 需准确拿到「刚被历史丢弃」的节点 ID，且再次校验全局引用 |
| B3 | 撤销/重做期间不清理 | P0 | 低 | 快照中仍引用的节点必须视为有效引用 |
| B4 | 只清理 UUID 形态目录，保留共享目录与手工目录 | P0 | 低 | 现有节点 ID 均来自 `crypto.randomUUID()`，无已知非 UUID 生成路径；仍按形态过滤，非 UUID 目录一律不碰 |
| B5 | 多画布引用保护 | P0 | 低 | 同一节点目录被多个画布引用时必须保留 |
| B6 | 清理动作串行化、失败可忽略 | P1 | 低 | 并发的打开与历史淘汰可能同时触发 |
| B7 | 静默执行与可观测性 | P1 | 低 | 需要日志便于排查，不应弹窗 |
| B8 | 与「删除画布」现有清理不冲突 | P1 | 低 | 删除画布后目录已不存在，重复清理需容忍 ENOENT |

## 六、明确不做

- 不清理 `assets/chat`、`assets/chatImages`、`assets/generated`、`assets/imported` 等共享目录。
- 不清理非 UUID 名称的目录（含用户手工创建的目录）。
- 不做回收站/延迟删除（用户已选择直接删除）。
- 不因历史对话（`.agent/sessions/*.jsonl`）引用而保留目录；聊天图片在 `.agent/attachments` 有独立副本。
- 不扫描 `content.md` 等正文里内嵌的 `assets/<id>/...` 路径；因此以下失效面可接受：文档面板已打开的节点正文标签页、剪贴板里引用旧路径的节点快照，在目录回收后会读不到文件。
- 不改动「删除画布」的现有清理逻辑（不照搬其只展开一层的保护集缺陷）。
