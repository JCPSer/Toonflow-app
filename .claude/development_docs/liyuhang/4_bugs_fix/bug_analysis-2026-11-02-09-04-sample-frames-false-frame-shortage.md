# Bug 分析：sampleFrames 误报「帧数不足」

- 时间：2026-11-02 09:04
- 提出人：用户
- 现象：Agent 调视频节点 `sampleFrames`（宫格）报 `抽帧失败：未生成文件（视频时长或可用帧数不足）`
- 状态：根因已定位并修复，待用户重启验收

## 1. 背景

`sampleFrames` 与 `captureFrame` 都由 `packages/nodes/videoNode/src/inspectVideo.ts` 实现：ffmpeg 先写到唯一临时名 `.contact-9.<uuid>.tmp.jpg`，再改名为 `contact-9.jpg`；改名前后用目录列表确认文件真的写出来。产物写 `assets/<nodeId>/inspect/`。

## 2. 复现与定位

| 步骤 | 结果 |
| --- | --- |
| 定位用户工程：`/Volumes/WD_BLACK_MAC/[0]【AI Art】/2026/蕾姆Rem`，节点 `138e01e7-…/inspect` 里只有 `frame-3000/5000/7000/9000ms.jpg`，没有宫格 | 单帧成功、宫格失败 |
| 用同一视频（1920×2560、24fps、10.125s）在宿主以应用自带 ffmpeg 6.0 跑宫格命令（fps=0.987654、scale 384×512、pad、tile=3x3） | 4/9/16 三档都能正常出图，**不是帧数问题** |
| 代码核对 | `clearOutputs` 的清理规则是「同类产物 ∪ 所有 `*.tmp.jpg`」；`sample()` 在 ffmpeg 成功**之后**才清理旧宫格，于是把自己刚写好的临时文件一起删掉了 |
| 随后 | `settleOutput` 查目录找不到临时文件 → 抛出「未生成文件（视频时长或可用帧数不足）」 |
| 为何单帧偶发成功 | 单帧 ffmpeg 极快，清理时的目录列表可能还没看到临时文件，侥幸没删；宫格解码整段更慢，列表稳定能看到，必删 |

结论：**误报**。真实原因不是视频帧数不足，而是清理规则误伤正在使用的临时文件。

## 3. Bug 矩阵

| 编号 | Bug | 优先级 | 复杂度 | 风险 |
| --- | --- | --- | --- | --- |
| B1 | `clearOutputs` 把本次刚写好的 `.tmp.jpg` 当残留删掉，宫格结算失败并误报帧数不足 | P0 | 低（清理时排除当前临时文件） | 低 |
| B2 | 结算依赖目录列表判断文件是否存在，列表滞后时会误判失败 | P2 | 低 | 低 |

## 4. 不在本次范围

- 不改 fps/scale/tile 的采样与拼图参数。
- 不改产物命名与目录结构。
- 不改前端展示。

## 5. 验收标准

1. 视频节点（含生成视频节点）调 `sampleFrames` 4/9/16 三档都能出宫格，返回 path 可用 `read` 打开。
2. 宫格与单帧互不删除：先截单帧再出宫格，单帧还在；反之亦然。
3. 重复调用只保留最新一张宫格，旧临时文件不残留。
4. 失败时不删掉上一轮可用宫格。
