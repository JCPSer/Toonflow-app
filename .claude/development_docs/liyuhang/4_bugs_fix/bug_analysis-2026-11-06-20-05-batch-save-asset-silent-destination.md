# Bug 分析：画布批量「加入素材库」不弹目标选择框、静默写入上次位置

- 时间：2026-11-06 20:05
- 提出人：liyuhang
- 状态：已实施（待人工验收）

## 1. Bug 矩阵

| 项目 | 内容 |
| --- | --- |
| 背景 | 画布支持框选多个图片/视频节点，选区工具栏提供「加入素材库」批量入口；单节点菜单的「保存到素材库」会有弹窗，可选目标库、文件夹、素材名 |
| 现象 | 批量点「加入素材库」后没有任何选择框，直接保存成功；落点是上一次单节点保存时选的库与文件夹 |
| 目标 | 批量保存也弹出目标选择框，用户确认目标位置后才写入；默认回填上次位置，减少重复选择 |
| 优先级 | P1（写入位置与用户预期不一致，且没有任何确认机会；素材可能落到隐私/错误目录） |
| 难度 | 低-中（改动集中在画布选区工具栏与素材库保存弹窗组件，不涉及服务端） |
| 风险 | 低：只新增交互；需要避免批量期间选中集合变化导致保存范围漂移 |

### B1 静默写入

- `selectionToolbar.vue` 的 `saveToAssets()` 直接调用 `saveSelectionToAssets(..., getSaveDefaults(directory))`，没有弹窗。
- `saveSelectionToAssets.ts` 顶部注释明确写着「批量入口没有弹窗可选位置，直接沿用保存弹窗记住的……」，属于当时的设计选择，但与用户预期不符。

### B2 用户看不到目标位置

- 保存成功后只提示「已加入 N 个素材」，不提示落点；用户无法在写入前确认，也无法在写入后定位。

### B3 单节点与批量的默认位置来源不一致

- 单节点弹窗无记忆时回落到「素材库当前浏览目录」，批量无记忆时回落到「项目库根目录」；用户感知为两套逻辑。

### B4 文件名不可预期

- 批量文件名由「节点名 序号.扩展名」自动生成，用户事前看不到真实文件名，重名自动改名也只能事后从提示里知道数量。

## 2. 复现步骤

1. 打开任一项目，画布中至少有两个已生成图片/视频的节点。
2. 单独对其中一个节点走「保存到素材库」，选择目标库与文件夹并保存。
3. 框选两个及以上图片/视频节点，点选区工具栏「加入素材库」。
4. 观察：没有弹窗，直接提示成功；文件出现在第 2 步选择的文件夹。

## 3. 影响范围

- 仅画布选区工具栏的批量入库入口；单节点保存、素材库内上传/收藏不受影响。
- 服务端接口与文件写入逻辑不变。

## 4. 不在本次范围

- 批量逐个重命名（本次仍自动命名，只做预览）。
- 失败项留在弹窗内重试（本次部分失败仍汇总提示）。
- 批量保存进度条（沿用按钮 loading）。
