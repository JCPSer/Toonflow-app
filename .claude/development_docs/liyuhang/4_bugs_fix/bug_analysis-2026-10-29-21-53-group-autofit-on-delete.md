# Bug 分析：分组内节点删除后，分组不再自动贴合内容

- 时间：2026-10-29 21:53
- 提出人：liyuhang
- 模块：`apps/web/src/pages/workspace/panels/canvas`

## 1. 背景

分组（`canvasGroup`）是画布上的矩形容器，子节点通过 `parentNode` 归属。分组的尺寸有两种来源：建组/合并组时按内容一次算好；之后每次拖动节点松手时由 `finishGroupDrag` → `fitGroupBounds` 重新贴合内容（内边距左/右 32、上 48、下 32，均为 16 网格倍数）。

用户反馈：**把分组里的节点删掉后，分组大小不再跟着变**，留下大片空白，需要手动拉右下角手柄。

## 2. 现象与目标

- 现象：组内有 3 个节点，删掉 1 个后分组矩形维持原大小，剩下的节点在框内偏居一角。
- 目标：删除子节点后分组自动收缩到刚好包住剩余内容；组内节点被删空时收缩到一个最小可用尺寸（160×96）保留空组，而不是维持一个巨大的空框。

## 4. 根因

### 4.1 贴合逻辑从未接过删除

- 现有关闭/贴合入口只有两个：`finishGroupDrag`（拖动松手，`selectionNodes.ts:118`）和 `arrangeSelection`（整理选中，`arrangeSelection.ts:77`）。
- `git log -S fitGroupBounds --all` 只有 `ec8f545`（代码，整理功能引入）与 `0e5fda5`（文档）两次提交；初始提交 `4f9a6d4` 的 `selectionNodes.ts` **没有**该函数。即：贴合能力是「整理」功能才引入的，**删除链路从未调用过它**，不是本轮改动引入的回归。
- 佐证：把节点拖出分组松手会收缩，删除不会——两条路径行为不一致，用户感知到的「以前会自动变」来自前者。

### 4.2 真正的删除入口（已逐个核对，`removeSelectedElements` 是**取消选中**，不是删除）

Vue Flow 的 `removeSelectedElements` 只把 `selected` 置 false（dist `vue-flow-core.mjs:6410`），因此 `index.vue:704/1387/1598`、`useCanvasTools.ts:273`、`nodeMenu.vue:427/443/449`、`selectionToolbar.vue:225`、`selectionHandle.vue:128`、`nodeSearch.vue:80` 都只是清选区，不属于删除路径。

真正会删节点的入口：

| 入口 | 位置 | 是否进撤销批次 |
| --- | --- | --- |
| 统一删除 `deleteSelection`（右键菜单 / Delete·Backspace / 分组标题栏删除） | `components/nodeMenu.vue:499`；入口 `nodeMenu.vue:414-415`、`index.vue:1549-1553`、`index.vue:439-443`→`groupNode.vue:140` | 是（调用方包 `canvasHistory.batch`） |
| 节点卡片自带「删除节点」 | `packages/nodeScaffold/src/nodeSkeleton.vue:509`（`removeNodes(nodeId)`） | 否 |
| 远端节点「移除节点」按钮 | `components/remoteNode.vue:10` | 否 |
| MCP `deleteNodes` 工具 | `useCanvasTools.ts:208` | 否 |
| 解组（删组容器、提升子节点） | `components/selectionToolbar.vue:183` | 是（工具栏 batch） |
| 新建节点连接失败回滚 | `nodeMenu.vue:448` | 是（同批） |
| 插件内部删除（拉片结果、全景、变体、3D 导出等） | `packages/nodes/frameAnalysisNode/src/resultNodes.ts:116,123`、`imageNode/src/usePanoramaCapture.ts:93`、`imageNode/src/useImageVariationNode.ts:36`、`director3dNode/src/index.vue:255`、`videoNode/src/components/videoActions.vue:186` | 否 |

结论：删除入口横跨画布与节点包两侧、且多数不进批次，逐处补调用既容易漏，也会被插件后续新增的删除路径绕过。修复必须在**画布层的唯一观测点**上做：监听「哪些节点属于哪个分组」的结构变化，谁少了直接子节点就重算谁，并把它的全部祖先分组一起纳入。

## 5. 行为口径（已与用户确认）

1. 删除后自动贴合剩余内容，内边距沿用 32/48，不做新的一套参数。
2. 组内节点删空 → 收缩到 160×96（10×16 / 6×16，仍落在网格上），位置不变，分组保留。该下限与手柄缩放最小 120×80 不同，取整格口径。
3. **只处理「减少」方向**：粘贴、MCP 新增、拖入节点只增大内容时不做自动贴合（沿用既有行为：拖入由 `finishGroupDrag` 处理，其余靠用户触发整理）。
4. 既有行为保持：建组、合并组、拆组、拖拽换组、整理画布、画布自动保存。
5. **拖出最后一个子节点同样收缩到 160×96**：空组下限放进 `fitGroupBounds` 本身，所有调用方口径一致，避免「删除会缩、拖空不缩」的二次不一致。
6. 撤销/重做不触发贴合，恢复的组尺寸以快照为准。
7. 画布加载/切换不触发贴合，用户手工保存的组尺寸原样保留。

## 6. 影响范围与不做的事

- 只影响分组矩形尺寸与组内相对坐标补偿（贴合时 group 与 children 同步平移，绝对坐标不变）。
- 不改节点数据、不改连线、不改画布文件格式。
- 不处理「节点隐藏」导致的视觉空白：隐藏节点仍算组内容，贴合时照旧计入（与 `fitGroupBounds` 现状一致，`finishGroupDrag` 选组时排除隐藏**组**是另一件事，不要顺手统一）。
- 非空组不额外 clamp 最小尺寸：只剩一个很小的节点时组宽 = 节点宽 + 64，可能小于 160，按内容走。
- 用户手工放大的留白组，在组内节点删除后会缩回内容大小——与拖拽松手行为一致，属预期。

## 8. 验收标准

- 组内 3 个节点删 1 个：分组收缩到剩余内容 + 内边距，剩余节点绝对坐标不变。
- 删到空：分组变成 160×96，位置不动。
- 拖出最后一个子节点：同上收缩到 160×96。
- 嵌套组：内层收缩后外层同步收缩；整组连同子节点一起删除时外层同步收缩。
- 撤销一次即回到删除前的状态（节点、尺寸一起回来），不会多出一步「只改尺寸」的历史。
- 打开旧画布不会重排任何组，也不新增撤销步。
- 粘贴、MCP 新增、拖入节点不触发自动贴合。
- 拖出/拖入、整理画布、建组/合并/拆组行为与现在一致。
