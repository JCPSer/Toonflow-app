# Bug 分析：画布区域偶尔出现窗口级滚动条

日期：2026-10-26 20:10
状态：已修复

## 一、现象

工作区里有时会在窗口底部（横向）与右侧（纵向）同时出现滚动条，整个画布跟着挪动几像素；窗口越窄越容易出现。

## 二、定位过程与证据

在 dev（1312×812、1440×900）无法复现，缩小到 800×560 后复现：

| 断言 | 结果 |
| --- | --- |
| `documentElement.scrollWidth / clientWidth` | **1237 / 794**（横向溢出 443px） |
| `documentElement.scrollHeight / clientHeight` | 560 / 544（横向滚动条占高后引发纵向滚动条） |
| 溢出元素 | `.comfyMonitor`（ComfyUI 状态条）内的 `.chip`，右边到 869/929，超出 794 |

根因链：

1. `.comfyMonitor` 是 `position: absolute; display: flex` + `max-width: calc(100% - 16px)`，但**没有 `flex-wrap`、没有 `overflow`**，子项 `white-space: nowrap`。窗口变窄时子项不换行也不收缩，直接溢出容器盒。
2. 画布容器 `.canvas` 只设了宽高，**没有 `overflow` 约束**；Vue Flow 自身会裁切，但它管不到与它同级的覆盖层（状态条、浮层）。
3. 溢出到 `.workspacePage` → `body` → 文档横向滚动条出现；横向滚动条占用高度，又诱发纵向滚动条。这解释了「下方和右侧一起出现」和「有时」（取决于窗口宽度与状态条展开状态）。

## 三、目标

1. 工作区内永远不出现窗口级滚动条（横向与纵向）。
2. 状态条在窄窗口下仍然可用（不被裁掉按钮）。
3. 不影响首页、设置等需要文档滚动的页面。

## 四、优先级 / 难度 / 风险

P1（观感与操作精度），难度低，风险低：三处独立的溢出约束，互不依赖。

## 五、评审意见

（用户未提出额外约束；按「永远不要出现滑动条」执行根因修复 + 兜底约束。）
