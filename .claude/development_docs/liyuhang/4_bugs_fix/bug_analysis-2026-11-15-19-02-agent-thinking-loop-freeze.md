# Bug 分析：Agent 思考死循环导致界面完全卡住

- 时间：2026-11-15 19:02
- 类型：性能/健壮性缺陷
- 状态：待评审

## 1. 现象

Agent 面板（含子 Agent）在模型思考阶段刷出大量重复的「写。」，随后整个界面无响应，停止按钮也点不动，只能强杀应用。

## 2. 取证

- 会话文件：`/Volumes/WD_BLACK_MAC/[0]【AI Art】/2026/黒木茜/ToonFlow项目-黑木/.agent/sessions/2026-11-11T10-13-13-873Z_6840bcd6-...jsonl`
- 单条 assistant 消息条目 `7512b886`：thinking 块 **86,010 字符**，其中「写。」出现 **20,513 次**；另一条 `30eb2886` 为 29,548 字符、6,594 次。
- 同一会话中重复文本累计 33,258 次，全部集中在 thinking，不是正常正文。
- 基准：`@markmend/ast` 解析 86 KB 重复文本约 **127 ms/次**（本机 Bun 实测）。
- 前端 `replyStream.ts` 以 **50 ms** 节流刷新，相当于 **20 次/秒**；每次刷新 `messageMarkdown` 的 `blocks` computed 都会对全文重新 `parseMarkdownIntoBlocks`。
- 结果：86 KB 时每秒需要约 2.5 秒 CPU 解析，主线程被占满；思考块流式期间默认展开，DOM 持续增长，进一步放大重排/测量成本。

## 3. Bug 矩阵

| 编号 | 描述 | 优先级 | 难度 | 风险 |
| --- | --- | --- | --- | --- |
| B1 | 服务端对模型重复输出（死循环）没有任何检测，只能等模型自己停或 maxTokens 耗尽 | 高 | 中 | 低：纯新增检测，阈值保守 |
| B2 | 流式刷新固定 50 ms，全文重新解析，成本随内容线性增长 | 高 | 低 | 中：降频会影响流式观感 |
| B3 | 思考块流式默认展开且无长度上限，超长内容持续渲染 | 高 | 低 | 低：超长自动折叠，可手动展开 |
| B4 | 主线程饱和后停止按钮无法点击，用户失去唯一止血手段 | 高 | 依赖 B1–B3 | 低 |

## 4. 目标

- 模型输出陷入重复循环时，服务端尽早识别并中止本轮，给出明确提示。
- 流式渲染在长内容下自动降频，思考块超长自动折叠，界面始终保持可点击（至少能点停止）。
- 正常长文生成不受影响。

## 5. 非目标

- 不改变模型/供应商选择，不调整 prompt。
- 不做输出内容的“去重改写”。
- 不引入 Web Worker 或重构整个 Markdown 渲染管线。

## 6. 风险

- 误判正常文本为循环：用「最近 4096 字符内不同 4-gram ≤ 16」这类极保守条件，并设置最小检查长度。
- 中止语义与用户手动停止混淆：需要单独的错误标记，前端提示“模型输出陷入循环，已自动停止”，而不是普通中断。
