# 需求方案：画布节点「禁用」

- 时间：2026-10-30 19:35（v2：20:15 按方案初审 4 条 P0 / 9 条 P1 整改）
- 对应需求：`1_requirements_matrix/2026-10-30-19-03-node-disable.md`（v4，已通过）
- 代码基线：`feat/exec-node` / `9546420`

## 1. 方案总览

```
                     ┌────────────────────── 前端画布 ──────────────────────┐
 入口(右键/工具栏/快捷键) → 写 node.data.disabled → 自动保存 + 撤销快照        │
                     │            │                                        │
                     │            ├→ nodeSkeleton 外观/交互守卫（灰化/覆盖层）  │
                     │            ├→ 连线/小地图/搜索/文件树 过滤               │
                     │            ├→ 禁用集合 watcher → 关文档/Agent 面板       │
                     │            └→ Agent 工具与 mention 过滤 ←─┐             │
                     │                                          │             │
 执行链：nodeInputs（禁用节点给「无值占位」）→ useNodeReferences → 各节点按钮置灰 │
                     └──────────────────────────────────────────┘             │
                                                        MCP/A2A 继承同一批工具 ┘
```

设计原则：

1. **状态只有一处**：`node.data.disabled === true`，不引入项目级清单。
2. **执行用「占位」不用「过滤」**：禁用节点必须留在输入值列表里（`value: undefined, disabled: true`），否则下游会静默生成。
3. **交互关内部、不关选择级**：节点内部控件全部关闭，选中/拖动/连线/复制/删除照常。
4. **过滤统一收口**：读类走「按 ID 抛错 / 扫描跳过」，写类在返回结构上剔除，计数与分页游标同步。
5. **禁用状态变化只监听集合**：所有关闭面板、刷新推导都挂在一个「禁用集合」watcher 上，覆盖菜单、快捷键、撤销/重做三条写入路径。

## 2. 数据模型

| 项 | 设计 |
| --- | --- |
| 字段 | `node.data.disabled?: boolean`，仅 `true` 表示禁用；`false`/缺省 = 启用 |
| 类型 | `connection.ts` 的 `NodeData` 增加 `disabled?: boolean`；文档侧 `DocumentNodeData` 同步；`canvasFiles.ts` 的 `DocumentNode` 增加 `disabled?: boolean`（**只加字段不过滤**） |
| 关键坑 | `nodeSkeleton` 的 props 继承 `NodeData`，加 `disabled` 后 Vue 会把它当 Boolean prop，`nodeProps` 不传时被 cast 成 `false`。因此节点骨架内**必须**用局部 `const disabled = computed(() => node.data?.disabled === true)`，禁止读 `props.disabled` |
| 序列化 | 复用现有保存链路（`data` 深 watcher + `toObject()`），不改画布文件格式 |
| 复制 | 复用现有 6 条 `data` 深拷贝路径，副本天然继承禁用 |
| 旧画布 | 无该字段 → 视为启用，不做迁移 |

## 3. 交互设计

### 3.1 入口

| 入口 | 位置 | 行为 |
| --- | --- | --- |
| 节点右键菜单 | `nodeSkeleton.vue` 现有菜单 | 未禁用：原有项 + 「禁用节点」；已禁用：**保留「复制节点 / 创建副本 / 复制到剪贴板 / 删除节点」**，新增「解除禁用」，**移除「保存到素材库」** |
| 选区右键菜单 | `nodeMenu.vue:32-46` | 多选（含分组）时新增「禁用」「解除禁用」，只作用于非分组节点；无 eligible 节点时两项都不出现 |
| 浮动工具栏 | `selectionToolbar.vue` | 新增按钮，按钮集合见表 3.2；`eligible` 为空时隐藏 |
| 快捷键 | `canvasShortcuts.ts` 新增 `toggleDisabled`，默认 `Cmd/Ctrl+Shift+D` | 有未禁用 eligible → 禁用它们；否则 → 全部解除；`eligible` 为空时 no-op |

所有入口统一调用画布提供的 `setNodeDisabled(ids, value)`（见 §7），不直接写 `node.data.disabled`。

**运行中保护（单节点与批量）**：菜单项 `:disabled="busy || running || isNodeBusy(id)"`，点击兜底提示「节点运行中，无法禁用」；批量入口跳过运行中节点并汇总「N 个节点运行中，未禁用」。所有变更包在 `canvasHistory.batch()` 内，一次撤销。

**批量执行规则**：跳过 `canvasGroup`、跳过运行中节点（busy / Agent thinking、running、compacting；`waiting` 不跳过）。

### 3.3 禁用后的节点外观与内部交互

```
┌─────────────────────────────────────┐
│  [◇] 图片生成  · 已禁用        [🗑] │ ← 标题栏：角标(title=节点已禁用)；刷新隐藏；删除保留
├─────────────────────────────────────┤
│  预览图（灰度、半透明、不可点击）      │ ← .contentCard 加 inert；覆盖层是其兄弟节点
│  参数文本（只读显示）                 │
├─────────────────────────────────────┤
│  ●────────────────────────●         │ ← handle 在覆盖层外，可拖线
└─────────────────────────────────────┘
```

- 根元素加 `nodeDisabled` 类；`.contentCard` 灰度 + 透明度（CSS 变量统一控制），文字保持可读。
- **覆盖层是 `.contentCard` 的兄弟节点**（绝对定位、z-index 低于 handle），不进 `inert` 子树；top/bottom slot 各自处理。
- `inert` / `aria-disabled` 只加在 `.contentCard` 与 slot 本身上；标题栏删除按钮与 `.nodeHandle` 在 `inert` 之外。
- **top slot 整体不渲染**（悬浮条与节点自定义动作按钮一并消失）；**bottom slot 必须保留渲染**（参数区在这里，如 imageGenerationNode/textNode 的 `#bottom` prompt/model/reference 块），加 `inert` 并用兄弟覆盖层包裹，保证 R3 的「只读参数仍可见」。
- 守卫：`focusNode`、`editLabel`、`reloadNode` 首行 `if (disabled.value) return`；刷新按钮 `v-if="!disabled"`；标题文字禁用时去掉 `tabindex`。
- 画布层守卫：节点单击打开 Agent 面板（`canvas/index.vue:617-623`）、未读提问横幅（`:684-690`）判断禁用后不打开。
- 节点内部 teleport 的编辑器/全屏预览（`el-image-viewer`、inpaint/mark/lighting/multiAngle/panorama）**放在各节点自己的 `index.vue` 里处理**：`watch(() => node.data.disabled)` 关闭对应开关（`previewVisible/inpaintPreviewVisible/lightingVisible/multiAngleVisible/panorama/crop/gridSplit`），并给打开入口加禁用守卫；画布 watcher 拿不到节点组件内部 ref，不能放在画布层。

### 3.4 画布其它位置

| 位置 | 行为 |
| --- | --- |
| 连线 | `defaultEdgeOptions.class` 里读源/目标 `data.disabled`，返回 `edgeDisabled`；CSS 只降 `stroke-opacity`，不拦截点击 |
| 小地图 | `node-color` 改为函数：禁用 → 灰色，否则原色 |
| 节点搜索（Cmd+F） | 保留禁用节点，行尾加「已禁用」标签，可定位/选中 |
| 文件树 | `DocumentNode` 带 `disabled` 字段，`fileTree` 的 `canvasItems`/`readCanvasItems` **展示映射处**过滤；共享的 `readDocumentNodes` 与 `readNodeIndex` 不过滤（素材归属不受影响） |
| 快速打开 | `quickOpen` 自己读 JSON，过滤 `node.data?.disabled === true` |
| 缩略图/画布导出 | 不特殊处理，沿用灰化外观 |
| Agent 未读横幅 | 禁用节点不出现 |

## 4. 执行链

### 4.1 输入占位（核心）

```
readSourceValue(...):
  if source?.data?.disabled === true: return undefined        // 判定放这里，口径统一

getTargetValues(nodeId, handleId):
  for each 入边:
    source = findNode(edge.source)
    if source?.data?.disabled === true:
      emit { source, sourceHandle, dataType, value: undefined, disabled: true }   // 保留占位
    else:
      emit 现有 { value }
```

- `NodeInputValue` 增加 `disabled?: true`。
- **禁止**在 `getTargetSources` 里过滤禁用节点。
- `useNodeReferences` 从 refList 计算 `disabledUpstreams`（按 source 去重计数），参考卡片对 `disabled` 项显示「已禁用」标签，仍可 `removeReference`。

### 4.2 各节点运行入口

| 节点 | 入口函数 | 改动 |
| --- | --- | --- |
| imageGenerationNode | `startGeneration`、`confirmInpaint` | 按钮 `:disabled` 加 `disabledUpstreams.length > 0`；首检报「上游 N 个节点已禁用」 |
| videoGenerationNode | `startGeneration` | 同上 |
| audioGenerationNode | `startGeneration` | 同上 |
| textNode | `generateText` | 同上 |
| director3dNode | `generate` | `index.vue` 把 `disabledUpstreams` 作为 prop 传入 `directorPanel.vue`，面板按钮据此置灰并展示原因 |
| frameAnalysisNode | `run` / `runAi` | 直接用 `useNodeInputs` 计算禁用上游；按钮 `:disabled` 加上 `title`/`aria-label`，区分「无输入」与「上游 N 个节点已禁用」 |

Agent 节点：软依赖，不置灰；`buildMentions` 过滤禁用上游。

### 4.3 节点函数

- `nodeTools.call`：目标节点禁用 → 拒绝「节点已禁用：<id>」。
- `nodeTools.list`：**显式 `nodeIds`** 命中禁用节点 → 抛「节点已禁用」；**全量枚举（`tools` getter 的 `list([...index.nodes.keys()])`）→ 跳过禁用节点**，不能因为一个禁用节点让整次枚举失败。

## 6. 撤销 / 持久化

- `useCanvasHistory.capture()`：节点 data 只保留 `{ label }` + `disabled`（仅当 `=== true`）。
- `restore()`：对已存在节点显式写 `disabled`，快照无该字段时 `delete node.data.disabled`；对删除后重建的节点，先用快照值覆盖 `nodeReferences` 取回的 data。
- 历史触发：`canvas/index.vue:1120-1125` 的 watcher 合并监听 `[label, disabled]`；不落进 `:1119` 的只保存链。
- 批量操作包 `batch()`；撤销恢复时跳过运行中节点（不写回，快照按实际状态记录，实现注释说明）。

## 7. 面板关闭通道

**唯一写入通道**：`canvas/index.vue` 提供 async `setNodeDisabled(ids, value)`（`provide` 给节点骨架/选区菜单/工具栏，快捷键也调用它），所有入口不再直接写 `node.data.disabled`：

```
setNodeDisabled(ids, value):
  1) eligible = ids 去掉分组、去掉运行中（首次检查）
  2) await flushNodeDocuments(每个 eligible 节点)      // 只 flush，不关标签
  3) 任一 flush 失败 → 整体不写、不关，提示「文档保存失败，未禁用」，返回 false
  4) 二次检查 isNodeBusy / Agent 状态，剔除这期间新进入运行的节点（汇总提示）
  5) batch(() => 写 node.data.disabled)               // 一次撤销
  6) closePanelsForDisabled(实际写入的节点)            // 关文档 + Agent 面板
  7) 节点内部编辑器由各节点 watch 自行关闭（见 §3.3）
```

**统一关闭函数** `closePanelsForDisabled(ids)`：对每个节点调用 `closeNodeDocuments(directory, canvasPath, nodeId)` 与 `agentNodePanelRef.value?.close(nodeId)`。主动禁用与「撤销/重做」watcher **共用**这一个函数，避免两条路径行为不一致。

跨组件通道：`workspace/index.vue` 持有 `documentPanelRef`（`document/index.vue` `defineExpose` 的 `flushNodeDocuments` / `closeNodeDocuments` / `forceCloseNodeDocuments`），通过 `provide` 交给画布子树（画布不是文档面板的祖先，只能用这种自上而下的注入）。

- `flushNodeDocuments`：只 flush、不关标签，用于写入前的原子性检查。
- `closeNodeDocuments(directory, canvasPath, nodeId)`：按 `directory + pathIdentity(canvasPath) + nodeId` 匹配 `resource.kind === "canvasNode"` 的会话，遍历关闭全部 viewId。
- `forceCloseNodeDocuments`：撤销/重做/外部写入路径用，flush 失败时 `cancelSave` 后强制关闭并提示「文档未保存」。
- 画布的 watcher 只处理撤销/重做与外部写入（例如另一窗口刷新）：检测到「新禁用集合」后调用 `closePanelsForDisabled(新禁用节点)`（其中文档走 force 版本），**Agent 面板也在这里关闭**。
- 守卫：`readDocumentNode`、`mountDocumentNode`、`saveDocumentNode`、`observeDocumentNode`、`canvasHost.focusDocumentNode`、`canvasMenu.syncDocumentNode` 判断禁用后拒绝/直接 return。

## 9. 测试计划

1. **函数级**（临时 Bun 脚本，跑完删除）：`getTargetValues` 占位、`useNodeReferences` 计数、历史 capture/restore（含 delete 语义）、`isNodeBusy`、`disabledSignature` 变化。
2. **手工回归（画布）**：禁用→刷新→重开；复制/粘贴/副本/拖拽复制；撤销/重做；删除后撤销；分组与混合选区；运行中禁用被拒；快捷键切换；纯分组选区不出现按钮；全量 `nodeTools` 枚举不被禁用节点打断。
