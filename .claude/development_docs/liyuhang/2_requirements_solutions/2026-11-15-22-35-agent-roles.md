## 1. 数据模型

```text
settings.agentRoles: AgentRole[]
AgentRole = { id: uuid, name: string(1..40), description?: string(≤200), prompt: string(1..20000), updatedAt: ISO }
```

- 全局一份，随设置保存（`PUT /api/settings`）；上限 50 个。
- 不新增文件；沿用设置的读写与桌面端请求校验。

## 2. 服务端

### 2.1 角色解析

新增 `agent/runtime/roles.ts`：

```text
listAgentRoles(): 从 settings.agentRoles 解析（zod 校验，坏项跳过）
findAgentRole(id): 按 id 取，找不到返回 undefined
```

### 2.2 系统提示组合（R4）

`createAgentResources` 增加可选 `options.rolePrompt`，组合顺序：

```text
1. 角色段（仅当有角色）
   ## 角色设定
   <角色提示词>
   以下默认规则作为补充；与本段冲突时，以本段为准。
2. buildSystemPrompt(...)   // 用户全局自定义提示 或 默认提示；工具/环境占位符仍按原逻辑展开
3. instructions（现有子会话附加说明）
```

AGENTS.md 与全局记忆继续走 `appendSystemPrompt`，不变。

### 2.3 请求入口

- `POST /api/agent` 入参新增 `roleId?: string(≤64)`。
- `run()` 解析 `roleId → findAgentRole`，取 `prompt` 传给 resources。
- 子会话（subAgent）不传 rolePrompt（R8）；单 Agent 模块不改。

### 2.4 设置保存

`PUT /api/settings` schema 增加 `agentRoles`：数组、最多 50、字段长度校验；保存后立即生效（每次运行都读设置）。


### 3.3 节点与派发（R3/R5/R6）

`agentNodePanel.vue`：

- 读取 `node.data.agentRoleId` 传给 conversation；
- `@roleChange` → `updateNodeData(nodeId, { agentRoleId })`；
- 角色被删除（store 中找不到）→ 传空并提示一次「角色已删除，已回退通用」。

`agentDispatcher.ts`：跑目标节点时读取 `node.data.agentRoleId`，随请求体下发。

UI 细节：弹窗宽 720，左侧 200 列表，右侧表单；沿用设置弹窗样式变量，深色主题自动适配。

## 4. 边界

- 切换角色立即生效于下一轮；会话历史不变（R6）。
- 角色提示词按纯文本拼接，不展开 `{{tools}}` 等占位符（默认提示段仍展开）。
- 角色不携带模型：模型仍按「会话 → 节点 → 派发方」回退链。
- 角色 id 失效（删除/改名不影响 id）→ 回退通用。

## 5. 测试

- 服务端：roles 解析（坏项跳过、超长拒绝）、组合顺序（角色段在默认段之前、冲突提示存在）、`/api/agent` 带 roleId 时系统提示包含角色正文。
- Web：settings store 解析；modelPopover 渲染「通用」+ 角色；dispatcher 请求体带目标节点 roleId。
- 手工：新建「提示词审核员」角色 → 节点选择 → 发送后回复体现角色职责；切换角色后下一轮生效；删除角色后节点回退通用；重启应用后角色仍在。
