# 需求方案：会话/工程复制改用写时复制（COW）

- 时间：2026-10-30 23:28
- 对应需求矩阵：`2026-10-30-23-25-cow-file-copy.md`

## 1. 方案总览

在 `@toonflow/file` 增加一个「写时复制」原语，然后把三处复制入口换过去。

```
copyFileClone(source, target):
    withFileAccess([source, target], "write"):
        fs.copyFile(source, target, COPYFILE_EXCL | COPYFILE_FICLONE)
```

- `COPYFILE_FICLONE`：内核优先用 clonefile/reflink；卷不支持时 Node 自动回退为普通复制，不抛错。
- 保留 `COPYFILE_EXCL`：目标已存在仍然报 `EEXIST`，与原语义一致。
- 仍然走 `withFileAccess`：同一进程内的读写队列不能被绕过。

## 2. 改动点

### 2.1 会话克隆（R1，`agent/runtime/sessions.ts`）

```
active 会话：维持现状（内存条目 → bytes → writeWorkspaceFile）
未运行会话：
    原：readFile 全量 → 归一化结尾换行 → writeWorkspaceFile(bytes)
    新：copyFileClone(源, 目标)
        若源末字节不是 \n，appendFile(目标, "\n")
    展示名仍按原口径从源文件内容算（本次不改）
```

结尾换行的处理必须保留：`renameAgentSession()` 紧接着会 `appendSessionInfo`，缺换行会和最后一行粘连成坏行。

### 2.2 目录复制（R2，`modules/localRuntime/workspace/files.ts`）

~~`fs.cp` 不支持 reflink，改成自实现递归~~（初审推翻，见 §6）：

实测 Bun 的 `fs.cp` 在 APFS 上本来就 reflink（256MB 树 df 增量 0），自实现递归不多省空间、还会丢目录权限位。
最终改法是**保留 `fs.cp`，只去掉预先的 `mkdir(target)`**：

```
copyWorkspaceFile(source, target):
    单文件 → copyFileClone
    目录   → 目标已存在则抛 EEXIST；否则交给 cp 自己创建目标目录
             cp(source, target, { recursive, force:false, errorOnExist:true, dereference:false, filter })
```

为什么必须去掉 `mkdir`：Node 与 **Bun 1.4.0（安装包实际运行时）** 在「目标已存在 + errorOnExist」下直接抛
`ERR_FS_CP_EEXIST`，只有 Bun 1.3.x 恰好容忍；而且 `mkdir` 建出来的目录会被 umask 削成 0755，
把源目录的 0700 / setgid / sticky 丢掉。改为 cp 自己建目录，权限位与源一致（实测 0700 → 0700）。

失败时保留已复制内容并抛 `ECOPYINCOMPLETE`，与现状一致。

### 2.3 跨设备重命名（R3）

`renameWorkspaceFile()` 里「复制 + 删源」的复制步骤换成 `copyFileClone`。

### 2.4 Host 端口

`cloneAgentSession` 走 `getAgentHost().workspace`，端口新增 `copyWorkspaceFile(source, target)`，绑定到本地实现，避免 agent 层直接碰文件系统。

## 3. 验证

| 用例 | 期望 |
| --- | --- |
| 100MB 文件 COW 复制 | 目标 apparent size 一致，`du` 增量 < 1MB；写目标后源不受影响 |
| 非 APFS 卷复制 | 正常完成，磁盘占用与普通复制相同（降级） |
| 目标已存在 | 抛 `EEXIST` |
| 目录复制（含空目录、嵌套） | 结构与内容一致，占用接近 0 |
| 目录含符号链接 | 抛错，且报错信息与现状一致 |
| 会话克隆后追加 session_info | 新文件可被会话列表正常读取，名称带「· 副本」 |
| 运行中会话克隆 | 行为不变 |

## 4. 风险与回退

- COW 只是落盘方式变化，文件内容逐字节等价；出问题把 `copyFileClone` 换回 `copyFile` 即可整体回退。
- SDK 回退（rewind）会用 `open(file,"w")` 原地重写，那一刻副本会全额分叉——预期行为，不影响正确性。
