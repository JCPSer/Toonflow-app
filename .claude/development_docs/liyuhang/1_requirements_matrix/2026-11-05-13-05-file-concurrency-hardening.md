# 需求矩阵：文件并发冲突处理加固（EBUSY / 原子重命名）

- 时间：2026-11-05 13:05
- 提出人：liyuhang
- 状态：待评审

## 1. 需求矩阵

| 项目 | 内容 |
| --- | --- |
| 背景 | 画布节点并发执行，节点结束时写产物、画布 JSON、文本快照。服务端已按路径串行（`access.ts`）并对写/改名/删除做互斥，冲突直接抛 EBUSY；但 ①EBUSY 没有映射成 409，被长读挡住 30 秒超时后返回 500；②客户端没有统一重试，节点批量完成时容易偶发失败；③文件重命名是 copy+unlink，非原子，失败可能留下不完整副本 |
| 目标 | 同一类并发冲突的表现稳定为「409 + 明确文案」，客户端对 EBUSY 自动退避重试；文件重命名改为原子操作（跨卷时回退） |
| 优先级 | P1（偶发失败影响体验，且 500 误导排查） |
| 难度 | 低-中（服务端错误映射 + 一个客户端重试封装 + 重命名实现替换） |
| 风险 | 低。重命名改原子操作需保持「目标已存在则报错」的现有语义，并处理 EXDEV 跨卷回退 |

### R1 EBUSY 映射

- `errorFromCause` 增加 `EBUSY → 409`，文案：「文件正在被其他操作使用，请稍后重试。」
- 响应 `data` 带上 `{ code: "EBUSY" }`（现有行为已带），客户端据此识别。

### R2 客户端统一重试

- `apps/web/src/lib/workspaceFiles.ts` 的写/改名/复制/删除/建目录/文本快照写，遇到 **409 + code EBUSY** 自动重试。
- 策略：最多 4 次，间隔 60/120/240ms + 随机抖动；其它错误立即抛出。
- 只重试「操作尚未开始就被拒」的情形，避免重复执行副作用。

### R3 原子重命名

- 文件重命名改为 `rename()` 原子替换；目标已存在仍报 EEXIST（保持现有语义，不静默覆盖）。
- 跨卷（EXDEV）回退到现有 clone 复制 + 删除。
- 目录重命名保持现有 `rename()`。

## 2. 验收标准

1. 两个操作同时改同一文件：后到的返回 409，文案为「文件正在被其他操作使用，请稍后重试」，不再出现 500。
2. 节点批量落文件发生短时冲突：客户端退避重试后成功，用户无感。
3. 重命名过程中的读请求只会读到旧文件或新文件；重命名失败不会留下半截目标文件（同卷）。
4. 重命名到已存在的目标仍提示「名称已被占用」。
5. 跨卷重命名（如同工作区内挂载点）仍能成功。
