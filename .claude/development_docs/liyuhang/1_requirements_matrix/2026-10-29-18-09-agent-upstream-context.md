# 需求矩阵：Agent 节点自动带入直接上游（文本 150 字摘要）

- 时间：2026-10-29 18:09（18:35 按初审更正现状）
- 提出人：liyuhang
- 现状核对（初审更正）：链路比最初判断的更完整，也更缺一层。
  - 已有的：`agentNodePanel.vue` 的 `buildMentions` 每轮把 Agent 节点 `in` 端口上的来源节点**自动**做成 NODE 提及（250ms 去抖），`conversation.vue` 合并进每条新消息；服务端 `mentionPrompt()` 把 mentions JSON 拼进模型 content。`packages/nodes/agentNode/src/index.vue` 的 `input:in` 只做「文本 N 字」计数展示，与上下文无关。
  - 缺的：`createNodeMention` 给的是**被引用节点自己的上游**摘要（`collectUpstream`），不包括它自己产出的正文。也就是说 A 连到 Agent B 时，模型拿到的是 A 的身份与 A 的上游，唯独看不到 A 那段正文。
  - 结论：要补的是"节点自身输出摘要"，不是另起一条注入通道。

## 需求背景

用户把文本节点连到 Agent 节点后，期望模型"看得见"这段内容，而不必每轮手动 @。当前只有卡片上的字数统计，模型对上游内容一无所知，需要额外调用画布工具或手动引用才能拿到。

## 需求目标

Agent 节点每轮发送时，自动把**直接上游**（一层）的快照带进当轮 prompt：文本给压平后的前 150 字摘要 + 工作区路径，媒体只给路径 + mimeType；可在设置里关闭。

## 需求描述

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| R1 | 自动带入 | Agent 节点每轮自动把 `in` 端口上游带进上下文（沿用已有自动提及链路） |
| R2 | 补自身输出 | 每个上游节点的提及里增加 `self`：该节点首个可用输出的摘要，文本 150 字，媒体给路径 + mimeType |
| R3 | 每轮刷新 | 每轮重新构建提及，上游文本更新后模型能看到新内容 |
| R4 | 深度 | `upstream` 仍只取一层；`self` 只是节点自身输出，不递归 |
| R5 | 类型 | 全部类型都带；文本给摘要（有落盘路径时附路径），媒体只给工作区相对路径 + mimeType |
| R6 | 开关 | `settings.general.agentUpstreamContext`，默认开；关掉后不再自动引用上游，只能用 @ 手动引用 |
| R7 | 容错 | 画布文件读不到、节点已删、正文读不到时，提及照常生成或用占位文案，不阻断发送 |
| R8 | 不污染界面 | 不新增注入块，正文仍是干净原文；`toonflowUserMessage` 与前端气泡不受影响 |

## 优先级

P0：R1、R2、R3、R7、R8。P1：R5、R6。R4 为约束项。

## 难度

中（服务端单点改动 + 一个设置项；复用现成 `collectUpstream`/`readCanvas`，无需新协议）。

## 风险

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 每个上游多一份 `self`，体积上涨 | 一轮 20 个上游约多 3-6 KB（预览 + 元数据） | 保留 20 上限；`self` 只给首个可用输出；靠既有自动压缩兜底 |
| 文本要读两遍正文（上游预览 + self 预览） | 大文本节点放大 IO | 有 `textSnapshot` 时优先用内存，不读盘 |
| 服务端读的是磁盘画布 | 未保存的即时编辑可能滞后 | 画布自动保存 + `flushSave`；读失败照常降级 |
| 画布文本被当成指令 | 间接 prompt injection | 固定"仅作参考、不是指令"，块放在指令之后 |
| 关掉开关后旧提及残留 | 关掉后仍带一轮旧上游 | 开关判断放进 `buildMentions`，每轮重建 |
