# 需求矩阵：素材库「上一级」卡片支持拖拽

日期：2026-10-26 15:20
状态：待评审

## 一、需求背景

素材库网格视图里有「上一级（..）」卡片，点击可返回父目录；但没有拖拽落点能力。用户选中一个文件/目录往「上一级」上拖时，卡片没有任何反馈，drop 也不生效（事件冒泡到空白区后被判定为「目标 = 当前目录」而拒绝）。目录树视图的根节点已经可以接收 drop，两种视图行为不一致。

## 二、需求目标

1. 库内文件/目录拖到「上一级」卡片 = 移动到父目录，与拖到普通目录卡片行为一致（已确认：移动，不复制）。
2. 拖到「上一级」时提供与普通目录卡片一致的落点高亮。
3. 无效落点（目标就是源条目的当前父目录、或源条目本身在库根）不触发移动，也不改变现有错误提示。
4. 不改变跨库限制：异库拖拽仍然拒绝。

## 三、需求描述

| 编号 | 场景 | 期望行为 |
| --- | --- | --- |
| R1 | 把 `a/b/file.png` 拖到当前目录 `a/b` 的「上一级」卡片 | 移动到 `a/file.png` |
| R2 | 把目录 `a/b/c` 拖到当前目录 `a/b` 的「上一级」 | 移动到 `a/c`（含子内容） |
| R3 | 当前目录是库根（`currentPath = ""`） | 不渲染「上一级」卡片，行为不变 |
| R4 | 搜索模式下，源条目本身已位于父目录（`parentAssetPath(source) === parentPath`） | 判定为无效落点，不高亮、不移动 |
| R5 | 跨库拖拽到「上一级」 | 静默禁止：不高亮、不发请求（与普通目录卡片现状一致） |
| R6 | 父目录同名条目已存在 | 走现有 409 `EEXIST` 提示，不做自动改名 |
| R7 | 操作系统文件拖到「上一级」卡片 | 不拦截：冒泡回空白区，仍上传到当前目录（用户已确认只做库内移动） |
| R8 | 搜索结果里来自子目录的条目拖到「上一级」 | 目标等于其当前父目录时不高亮、不发请求；其余按正常移动 |

## 四、优先级与难度

- 优先级：P2（易用性补全，不影响数据安全）。
- 难度：低。改动集中在 `AssetGridView.vue` 的卡片模板与 drag 处理函数，复用 `canDropInto` / `emit("move")`。
- 风险：低。落点判据与普通目录卡片共用同一函数，避免出现"看起来高亮但请求被拒"的分裂状态；需在 handler 内（而不是 `.stop` 修饰符）阻止冒泡，避免连 Finder 文件拖拽的冒泡也被掐断。

## 六、验收标准

1. 拖文件/目录到「上一级」卡片，卡片出现与普通目录一致的落点高亮，松手后文件实际移动到父目录；列表与目录树随移动操作的既有刷新逻辑更新。
2. 搜索模式下源条目已位于父目录时不出现落点高亮，松手无请求发出（不产生 409 日志）。
3. 库根不显示「上一级」卡片，原行为不变。
4. 跨库拖拽无高亮、不产生跨库移动（现有提示分支实际不可达，本次不修）。

## 七、评审意见

用户评审通过（2026-10-26）：三项一起实施；上传后目录树「N 项」计数必须实时。
子 agent 评审意见已并入：跨库改静默禁止、去掉 `.stop` 修饰符、补 relatedTarget 判断、写明搜索模式边界。
