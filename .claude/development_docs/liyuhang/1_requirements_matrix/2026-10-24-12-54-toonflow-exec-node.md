# 需求矩阵：Toonflow「运行指令」节点

## 需求背景

Toonflow 画布节点只能使用宿主开放的四类能力（工作区文件、FFmpeg、ASR、AI 模型）。
全仓 138 条路由中没有任何执行系统命令的入口，节点无法运行 python / shell / 自定义脚本。
用户已持有 app 源码（`/Users/liyuhang/Documents/git_projects/Toonflow-app`，自有 fork，master 干净），
同意通过改源码补一条执行路由的方式补齐能力。

## 需求目标

在画布上提供一个「运行指令」节点：手填命令 → 点击运行 → 实时看到 stdout/stderr → 结果作为文本向下游输出。

## 需求描述

| # | 子需求 | 详细描述 | 优先级 | 难度 | 风险 |
| --- | --- | --- | --- | --- | --- |
| R1 | 服务端执行路由 | 新增 `POST /api/exec`，接受命令与工作区目录，流式回传 stdout/stderr/退出码 | P0 | 中 | 任意命令执行面，需绑定本机来源 |
| R2 | 实时流式回显 | 输出逐行推送到节点，长任务可看到进度，不阻塞界面 | P0 | 中 | SSE 断连需能杀掉子进程 |
| R3 | 画布节点 | 命令输入框、运行/停止按钮、输出面板、状态行；上下可连线 | P0 | 中 | 无 |
| R4 | 输出作为节点值 | 下游可读取文本（完整输出 / 纯 stdout） | P0 | 低 | 无 |
| R5 | 参数持久化 | 命令、cwd、超时写进 `node.data`，重开画布还原 | P1 | 低 | 无 |
| R6 | Agent 可调用 | 注册 `node:runCommand` / `node:getExecStatus` 两个节点函数 | P1 | 低 | 宿主 120s 上限 |
| R7 | 打包验证 | 构建 web/server/nodes 并打包 `.app`，由用户自行安装测试 | P0 | 中 | electrobun 打包耗时、产物未签名 |

## 明确不做（本轮范围外）

- 命令中注入上游文件路径（用户选择纯手填）
- 命令白名单 / 沙箱隔离（用户选择不做限制）
- 历史命令列表、多标签终端、PTY 交互式输入
- 上游节点变化自动触发（只保留手动运行）

## 关键约束

1. 路由必须校验 `x-toonflow-workspace: 1` + 本机来源，禁止手机互联（MobileLink）与远程访问触发。
2. 命令通过登录 shell 执行，`cwd` 固定在工作区目录内，禁止逃逸到工作区外。
3. 客户端断开（关闭画布 / 点停止）必须终止子进程及其子进程组。
4. 节点函数受宿主 120s 上限约束，长任务需返回 `running` 并由状态函数轮询。

## 验收标准

- 画布上能新增节点、能接上游与下游连线
- `ls`、`python3 -c "print(1)"`、`ffprobe`、含 `&&` 的复合命令均能执行
- 每 0.5s 内能看到输出增量，不再等到命令结束
- `sleep 30` 中途点停止，进程确实消失（`ps` 无残留）
- 退出码、耗时正确显示
