# 需求矩阵：节点引用附带直接上游信息

- 记录时间：2026-10-28 13:54
- 需求来源：用户提问「现在引用功能有没有附上连接节点（输入侧）的信息？我看好像只有当前节点的内容」
- 代码基线：`c74b610`
- 澄清结论：确认需要补充；只带**直接上游**；每个上游端口带**短预览**（文本前 200 字 / 媒体文件名），不塞全文

## 一、背景

Agent 对话里 `@` 提及画布节点有两种粒度：

- 输出引用（点行主体）：把某个输出端口的值整体放进上下文；
- 节点引用（行尾「节点」按钮）：只放画布与节点身份，`dataType = NODE`、`value = null`，并附一句提示「需要它的输出、参数或连线时，用画布工具按 nodeId 读取」。

问题在于节点引用**完全没有连线信息**。用户看到一个文本节点（或任何处理节点）时，很自然想知道「它的输入来自哪些节点、各端口接了什么」，而当前模型必须先调 `getCanvasEdges({direction:"incoming"})` 才能知道，多一次工具往返；上下文里也看不出节点处于链路中间还是末端。

## 三、非目标

- 不做递归/多层链路展开。
- 不把上游输出正文放进引用（正文仍是「输出引用」或画布工具的职责）。
- 不改输出引用的行为与体积。
- 不改素材引用的行为。

## 四、验收标准

1. 引用一个中间节点（如「文本」节点，输入侧接了一个图片节点）后，mention JSON 的 `value.upstream` 里能看到目标端口名、来源节点名与类型、来源输出名、dataType 与 200 字以内预览。
2. 引用一个没有入边的节点时，`upstream` 为空数组，mention 仍可正常发送。
3. 画布未打开（离线读取 JSON）时同样能拿到上游信息。
4. 上游文本超过 200 字时被截断且不出现换行轰炸；媒体只显示文件名。
5. 上游超过 20 条时只保留前 20 条并标 `truncated: true`。
6. 发送给模型的提示词里说明"节点引用带上游摘要，正文需用工具读取"。
