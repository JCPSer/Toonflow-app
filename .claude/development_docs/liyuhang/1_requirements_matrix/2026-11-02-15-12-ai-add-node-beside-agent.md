# 需求矩阵：AI 新建节点固定在发起 Agent 旁边

- 时间：2026-11-02 15:12
- 提出人：用户
- 状态：已与用户确认（grill-me 逐项确认）

## 1. 需求背景

画布 Agent 通过 `addNode` 工具建节点时，位置完全由模型传入的 `position` 决定，实现只做网格吸附（`apps/web/src/pages/workspace/panels/canvas/useCanvasTools.ts:185-197`）。模型经常给出与当前上下文无关的坐标，节点会出现在画布任意位置，用户「不确定它会跑到哪儿去」。

画布工具调用链路目前没有携带调用方身份：服务端 `canvasCall` 事件只有 `{ callId, name, args }`，前端 `conversation.vue` 虽然持有 `props.nodeBinding.nodeId`，但没有传给画布上下文，所以 `addNode` 无法知道「是哪个 Agent 节点建的」。

## 2. 需求目标

1. 由画布 Agent 节点发起的新建节点，固定出现在该 Agent 节点的右侧一列。
2. 模型传入的 `position` 在该场景下完全忽略，结果可预测。
3. 新节点不与画布上已有节点重叠，按需向下顺延。
4. 不改变手动新建、复制粘贴、拖入、节点包自身生成、`moveNodes`、`arrangeCanvas` 的行为。
5. 无 Agent 绑定的入口（例如普通对话面板）保持现有行为。

## 3. 需求描述

### 3.1 功能需求

| 编号 | 需求 | 优先级 | 说明 |
| --- | --- | --- | --- |
| R1 | 锚点 | P0 | 取发起本次工具调用的 Agent 节点：`conversation` 把 `nodeBinding.nodeId` 传入画布调用 |
| R2 | 忽略模型坐标 | P0 | 存在有效调用方节点时，不读取 `args.position`；仍按 schema 校验 |
| R3 | 右侧单列 | P0 | 新节点左上角 x = Agent 节点绝对右边界 + 80，y 初始与 Agent 顶部对齐 |
| R4 | 向下避让 | P0 | 与已有节点矩形相交时，移到相交节点最低底边 + 40，重复直到无碰撞 |
| R5 | 网格吸附 | P0 | 最终坐标仍走现有 `nodePosition()`，保持画布吸附设置 |
| R6 | 回退 | P0 | 无 `nodeBinding`、节点不在当前画布、节点已被删除时，退回模型坐标 |
| R7 | 分组坐标 | P0 | 锚点使用 `computedPosition`（绝对坐标）；新建节点保持顶层，不写入分组 |
| R8 | 视口跟随 | P1 | 沿用现有 320ms 合并的 `scheduleReveal`，不逐次打断用户视口 |
| R9 | 工具说明 | P1 | `addNode` 描述注明：由 Agent 节点发起时 position 被忽略 |

### 3.2 非功能需求

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| N1 | 单次调用成本 | 只遍历当前画布节点做矩形相交，节点数在数百量级，开销可忽略 |
| N2 | 可测试 | 摆放算法抽为纯函数，不依赖 Vue Flow |
| N3 | 兼容性 | `CanvasContext.call` 新增可选第三参数，服务端桥接与其他实现不受影响 |
| N4 | 无持久化变更 | 不新增节点字段，画布 JSON 结构不变 |

### 3.3 不在本次范围

- 不限制 `moveNodes`、`arrangeCanvas`、`selectNodes`。
- 不改手动新建、复制粘贴、文件拖入、节点包内部生成。
- 不自动连线、不自动改分组、不自动选中新节点。
- 不给 `addNode` 增加 `anchorNodeId`、`parentNode` 等新参数。
- 不改服务端 `canvasCall` 事件结构（调用方身份由 Web 端 conversation 提供）。

### 3.4 边界约定

- 新建节点尺寸在挂载前未知，避让时用 320×300 兜底；挂载后已有节点用真实 `dimensions`。
- Agent 节点尺寸未测量时宽 300、高 180 兜底。
- 连续创建多个节点时，每次 addNode 是独立调用；前一个节点已挂载并测量，后一个会自动排到它下方。
- Agent 节点本身在分组内时，新节点仍创建为顶层节点，位置取分组内绝对坐标的右侧。
- 避让候选包括分组节点本身，避免压住组框。
- 若右侧一列被占满，向下顺延；10000 次仍未找到空位时视为计算失败，回退模型坐标（不阻断建节点）。

## 4. 需求难度与风险

| 项目 | 评估 |
| --- | --- |
| 难度 | 低—中。新增一个纯函数 + 打通 `nodeBinding` 到画布调用的可选参数 |
| 风险 1 | 调用方身份链路断裂 → 全部回退旧行为，不会报错 |
| 风险 2 | 坐标单位混淆（相对/绝对）→ 锚点与已有节点统一用 `computedPosition`，新节点写绝对坐标 |
| 风险 3 | 右侧一列过长 → 用户已选择单列，接受 |

## 5. 验收标准

1. 在一个 Agent 节点对话里让它连续新建 3 个节点：三个节点在 Agent 右侧同一列、从上到下排列、互不重叠。
2. 模型传入任意 `position`（包括画布另一头），节点仍出现在 Agent 旁边。
3. Agent 右侧已有节点时，新节点向下跳过该节点。
4. 手动右键新建、拖入文件、复制粘贴的位置不变。
5. 普通对话面板（无 `nodeBinding`）让 AI 建节点时，仍使用模型坐标。
6. 新建后视口仍在 320ms 合并逻辑内，只平移一次。
