# 需求矩阵：提示音音量可调

- 时间：2026-11-01 13:15
- 分支：`feat/exec-node`
- 提出人：用户

## 1. 需求背景

节点完成/失败与 Agent 提问的提示音由 `apps/web/src/lib/chime.ts` 用 WebAudio 现场合成，增益写死为 `VOLUME = 0.18`。用户反馈偏小，且写死意味着要调只能改代码。

## 2. 需求目标

- 提高默认音量，并在设置里提供可调滑杆。
- 音量与开关相互独立：0 = 静音但不改开关状态。
- 只影响应用内提示音，不影响桌面系统通知。
- 老配置升级后行为不变（默认按新的默认音量）。

## 3. 需求描述

| 编号 | 需求 | 优先级 | 难度 | 风险 |
| --- | --- | --- | --- | --- |
| R1 | 提示音默认音量从 0.18 提到 40%（滑杆 40） | P0 | 低 | 0.4 是否过响需实听确认 |
| R2 | 设置 > 通用 > 节点提示音 下增加 0-100（步进 5）音量滑杆，持久化 | P0 | 低 | 拖动时不能每一步都触发保存 |
| R3 | 音量 0 不发声，但「节点提示音」开关保持原状 | P0 | 低 | 0 是合法值，不能被默认值兜底覆盖 |
| R4 | 只作用于三种应用内提示音（完成/失败/提问） | P1 | 低 | 系统通知声音由操作系统控制 |
| R5 | 关闭开关时滑杆置灰 | P2 | 低 | 无 |

## 4. 不在本次范围

- 不改音色、音高、时长与合并窗口。
- 不做抽头试听按钮。
- 不影响桌面系统通知的 `silent` 标志与系统音量。

## 5. 验收口径

1. 默认安装/老配置升级后，提示音明显比之前响（约两倍增益）。
2. 设置页把音量调到 100 再拖动到 0：能保存、重启后保持；0 时提示音不响。
3. 关闭「节点提示音」后滑杆置灰；重新开启后音量值保持关闭前的设置。
4. 音量非 0 时开关行为与以前完全一致。
5. 系统通知的声音不受音量滑杆影响。
