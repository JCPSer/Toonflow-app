# 需求矩阵：Agent 会话回退（rewind）与复制为新会话（fork）

## 需求背景

现在 Agent 对话只有一个「编辑消息并重发」：它会截断当前分支后重跑，但入口是"改写后重发"，用户想要的是两件独立的事——

1. **回退（rewind）**：回到某条用户消息之前，直接把中间这段对话丢掉，像 Claude Code 的 rewind。
2. **复制为新会话（fork）**：从某条消息处截断，复制成一个新的会话文件并打开，原会话保持不变。

## 现状（代码事实）

- 会话是 JSONL 追加文件：首行 `type:"session"` 头，之后每条 entry 有 `id/parentId/timestamp`，SDK 用 `getBranch()` 取当前分支。
- `DELETE /api/agent/message` 已实现「删除消息」，但用的是**墓碑**：把被删 entry 改写成 `toonflowDeletedUser` / `toonflowDeletedEntry`，保留树结构与叶指针。
- 「编辑重发」走 `resendFrom`：把分支指针移回该用户消息的 parent，再发新 prompt；旧内容留在文件里但 UI 不再显示。
- SDK 自带 `SessionManager.forkFrom()`，但只支持**整段**复制，不支持截断到某条消息。
- 消息节点已经带 `entryId`，能精确定位要回退/复制的锚点。

## 需求描述

| # | 需求 | 优先级 | 难度 | 风险 |
| --- | --- | --- | --- | --- |
| R1 | 入口：用户消息（右侧）悬停加「回退到这里」；agent 回复（左侧）悬停加「复制为新会话」 | 高 | 低 | 两个入口分属两侧，需分别验证 |
| R2 | 回退：以该用户消息为界，把它及之后的全部内容**物理删除**，内容回填输入框 | 高 | 中 | 不可恢复；与现有「删除消息（墓碑）」行为不一致 |
| R3 | 回退覆盖被删内容派生的记录：回答、工具结果、附件/提及记录、计时、压缩记录、标签、子 Agent 上报卡片 | 高 | 中 | 漏删会留下悬空引用或残留摘要 |
| R4 | 复制为新会话：以该用户消息所在轮的结尾为截止点，新建会话文件并打开 | 高 | 中 | 新文件头要新 ID，entry id 沿用；命名与列表展示 |
| R5 | 会话运行中（流式生成 / 子 Agent 运行 / 有待回答的提问 / 另一个操作进行中）禁止回退与复制 | 高 | 低 | 与服务端活动会话表冲突 |
| R6 | 回退后输入框回填原文与提及，附件按 path 回挂 | 中 | 低 | 附件文件仍在工作区，无需重传 |
| R7 | 服务端并发契约：会话运行中/待回答时两个接口都返回 409，并持有文件锁 | 高 | 低 | 多实例同开同一工作区不互斥 |
| R8 | 子 Agent 关联：回退连带删除被丢弃轮派生的子会话文件；子 Agent 会话自身禁用两个功能 | 高 | 中 | 递归删除需防环 |
| R9 | 复制出的新会话必须落在历史列表里（不能触发父子会话过滤）且有新名字 | 高 | 低 | header 写错 parentSession 会让新会话永久隐形 |
| R10 | 叶指针、压缩记录 `firstKeptEntryId`、label、branch_summary 等悬空引用必须处理 | 高 | 中 | 悬空会让上下文静默少一段 |

## 已确认的决策

| 决策点 | 结论 |
| --- | --- |
| 回退落点 | 回到选中的用户消息**之前**，该消息及之后全部丢弃，内容回填输入框 |
| 丢弃强度 | **物理删除日志**（不是墓碑、不是只隐藏） |
| 复制范围 | 截到该消息所在轮结束（含它的回答），新建会话并直接打开 |
| 入口 | 回退在用户消息（右侧），复制在 agent 回复（左侧），都以该轮结束为截止点 |
| 覆盖层级 | 含子 Agent 上报与压缩记录（只沿当前分支重建） |
| 子会话处理 | 回退**连带删除**被丢弃轮派生的子会话文件 |
| 删除快照 | **不留快照**，纯破坏性删除 |
| 子会话入口 | 子 Agent 会话**禁用**回退与复制 |
| 确认弹窗 | 回退加二次确认，文案写明不回滚工作区文件/画布/附件 |
| 文件体积上限 | 超过 32 MB 拒绝操作（413），避免全量读写把服务拖住 |

## 评审意见（子 Agent 初审，已采纳）

1. 物理删除必须删「锚点整棵子树」而不只是当前分支尾部，否则子节点变孤儿；现有严格校验查不出孤儿。
2. 叶指针不落盘、SDK 以文件最后一行为叶；重写后必须显式追加空标记把叶钉回锚点父级，否则重开落在废弃兄弟分支上。
3. 复制的 header **不能写 parentSession**：历史列表按 parentSession 过滤子会话，写了会永久隐形，还会和真实子 Agent 语义混淆。
4. 轮边界以「下一条用户消息（含墓碑用户）之前」为准；只有用户消息没有回答的轮也必须落盘（SDK 自带的 branched session 在无 assistant 时不会写文件）。
5. 压缩记录 `firstKeptEntryId` 指向被删条目时，SDK 会静默丢掉整段历史，必须丢弃该记录。
6. 运行中/待回答的状态必须在服务端判定，不能只靠前端禁用。
