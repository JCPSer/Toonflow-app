# 需求矩阵：引用改为纯指针 + 画布平移卡顿

- 记录时间：2026-10-28 19:25
- 需求来源：
  1. 用户「引用到 agent 对话框的问题：不要发送原文了，都只发送指针和上游相关指针，以及其他必要信息，就是不要附上原文了」
  2. 用户「节点被点击后显示输入框的状态下，移动画布会非常卡顿」（附加报告）
  3. 用户「耗时角标没有挪出节点框」「右上角位置不对，明显偏离卡片很多」（角标位置修正）
- 代码基线：`b276708`

## 一、背景

### 1.1 引用把正文塞进上下文

画布节点引用有三条取数路径，都把正文直接放进 `AgentMention.value`：

- 输出引用（`createCanvasMention`）：文本类会 `readText` 读出完整正文，上限 100000 字符；
- 素材引用（`selectMentionAsset`）：`STRING` 类型素材同样读全文；
- 聊天附件：`mimeType === "text/plain"` 时把全文放进 `attachmentContents[].content`。

一个几万字的文本节点被引用一次，就吃掉大段上下文，且内容可能很快过期（用户改了节点正文，历史消息里还是旧快照）。

### 1.2 画布平移卡顿

用户感知是「选中节点出现输入框后变卡」。实测（复现 agent，Chromium 20x CPU 降速、26 节点 26 连线）表明**输入框不是主因**：

| 条件 | Paint/帧 | `#document` 重绘/帧 |
| --- | --- | --- |
| 未选中 | 3.0 | 1.0 |
| 单选（输入框可见） | 37.5 | 12.5 |
| 单选 + 关掉连线动画 | 3.0 | 1.0 |
| 未选中 + 强制 26 条边动画 | 256.0 | 15.9 |
| 单选 + 输入框 `visibility:hidden` | 38.1 | 12.7 |

双向闭环：关动画恢复到基线，不选中但强开动画比选中还惨。根因在 `index.vue:1388` 的边 class 生成——**只要节点被选中，所有直连边立刻挂上 `animated`**，触发 SVG `stroke-dashoffset` 无限动画；该属性不可合成，必须逐帧光栅化，且 edges SVG 不是独立层，失效冒泡到根层。

### 1.3 角标位置

角标挂在 `.cardContainer` 内 `top:4px;right:4px`（框内），用户要求移到框外。第一次改到节点根层 `bottom: calc(100% + 2px)`，因为把标题栏高度（20px 行高 + 8px 内边距 ≈ 28px）也算进去，恰好偏离卡片约 1/4 卡片高度（卡片最小 100px）。

## 三、非目标

- 不改节点引用的上游摘要（那 200 字预览是上一次需求明确要求的）。
- 不改画布 JSON 格式。
- 不引入新的工具；复用已有的 `read` 与 `getCanvasNodes`。

## 四、验收标准

1. 引用一个 5 万字文本节点，送出上下文里只有 `{ path, mimeType }`，无正文；序列化体积约 300 字节级。
2. 模型能依据 `path` 用 `read` 读到该文本节点的正文。
3. 拖入纯文本附件，上下文里不含正文。
4. 旧会话里 `value` 为纯字符串的引用仍能正常重发。
5. 选中节点后平移画布，连线虚线仍在流动，但不再出现明显卡顿（对比：改前 37.5 Paint/帧）。
6. 角标位于卡片上边框之外、靠右上角，不遮挡卡片内容、不压右侧端口。
7. 生成中每秒刷新不再导致 `nodeSkeleton` 重渲染（只有角标自身更新）。
