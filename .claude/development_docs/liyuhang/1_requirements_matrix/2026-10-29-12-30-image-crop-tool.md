# 需求矩阵：图片节点裁剪工具

- 记录时间：2026-10-29 12:30
- 提出人：liyuhang
- 涉及节点：`imageNode`（图片）、`imageGenerationNode`（图片生成）

## 一、需求背景

两个图片类节点已有「缩放 / 宫格切分 / 局部重绘 / 打光 / 多角度 / 全景图 / 标记」等后处理能力，但缺少最基础的**取景裁剪**：用户想把一张图里的一小块构图单独拿出来（比如从 4 宫格海报里取其中一格、从竖图里取方形头像、切掉边缘多余留白），只能导出到系统图片工具里裁完再拖回来。

裁剪与现有工具的关键差别：它是**几何精度操作**，需要看到大图、能拖手柄、能锁比例、能按像素对齐，靠参数面板或节点卡片内 240px 的小预览都做不准。

## 二、需求目标

1. 在两个图片类节点的工具栏提供「裁剪」入口，和现有后处理工具并列。
2. 弹窗内以接近原图尺寸可视化框选，支持比例锁定、像素级数值调整、键盘微调。
3. 结果直接替换当前节点输出（下游连线、节点文案都不变），可一键恢复。
4. 不破坏原文件、不影响其他节点对原图的引用。

## 三之二、边界与不做（评审补充）

| 场景 | 结论 |
| --- | --- |
| 撤销 / 重做 | 画布历史只快照结构与 label，裁剪结果与 `node.data.crop` 都不进撤销栈；只提供一层「恢复裁剪前」 |
| 复制 / 粘贴 / 创建副本 | `node.data` 整体深拷贝，副本会带上 `crop.previous/appliedUrl`；但显示与否由 `appliedUrl === 当前输出 url` 决定，跨项目粘贴只迁输出、不迁 `previous.url`，因此不会错误显示「恢复裁剪前」 |
| 动图（GIF/APNG/动态 WebP） | 经 canvas 只保留首帧，统一落成静态 PNG |
| EXIF / ICC / DPI | 只保像素，重编码会丢元数据；`<img>` 解码已按 EXIF 定向，不会出现宽高颠倒 |
| 透明通道 | 有 alpha 或未知格式一律落 PNG；格式判定以 `source.mimeType` 优先，避免 `.jpg` 里实为 PNG 时压成黑块 |
| 弹窗打开时删除节点 | 组件 `onBeforeUnmount` 中止任务并关闭；裁剪编码中删除由 `nodeEvent delete` 守卫拦下 |
| 多选 / 拖动节点 / 切画布 | 与 `imageScale` 一致，触发即关闭弹窗 |

## 四、明确不做（本次范围外）

- 任意角度旋转、90° 旋转。
- 上下翻转（只做左右镜像）。
- 工具栏独立翻转按钮（已确认放进裁剪弹窗）。
- 裁剪框拖出图片边界做「扩画布」。
- 多步裁剪历史（只保留一层恢复）。
- 圆形/圆角遮罩、羽化。
- 把裁剪生成为新节点（结果固定替换当前输出）。

## 五、验收标准

1. 两个节点都能看到「裁剪」按钮；无图时置灰。
2. 弹窗内可拖拽建立、拖动位移、八向改尺寸；框外变暗且框不会越界。
3. 选 1:1 后拖拽始终为正方形；点「自由」后恢复任意比例。
4. 数字框输入 200/100/800/600 后裁剪框精确落在该坐标；方向键与 Shift+方向键能微调。
5. 应用后节点显示裁剪结果，节点宽度随新宽高比自适应，下游沿用新图。
6. 「恢复裁剪前」能回到原图；上传新图/AI 重新生成后该按钮消失。
7. 裁完关闭再打开同一张图（已裁剪后的图）不会出现越界框。
8. 裁剪中删除节点、切换项目会被拦下并给出可读提示。
