# 需求矩阵：Agent 对话工具调用折叠

- 时间：2026-10-30 10:45（11:05 按首轮初审修订）
- 提出人：liyuhang
- 模块：`apps/web/src/components/agent/`（消息列表渲染 + 设置项）
- 代码基线：`0e5fda5` + 未提交的分组贴合 / 输入历史改动

## 1. 需求背景

Agent 会话里工具调用数量多时，每个调用独占一行，导致对话很长、滚动翻历史困难。用户希望工具调用信息可收起；正常问答（用户提问 + 助手正文）必须原样显示。

仓库现状（已核实）：工具调用数据在 `AgentMessage.parts[]` 的 `type:"tool"` 中；主 Agent 面板与画布 Agent 节点面板共用 `conversation/messageList.vue`，工具卡片由 `toolMessage.vue` 渲染（折叠态只显示标题，工具自带界面渲染在折叠容器之外）；浏览器工具不走 `toolMessage`，已按轮聚合到 `browserPanel`；设置存储为服务端 settings（`generalSettings` 自动保存，服务端 schema 为 `z.record` 放行未知字段）。

## 2. 需求目标

新增一个全局设置项，默认“折叠”：同一消息内连续的多个工具调用合并成一行摘要，点击展开逐个查看；问答正文不受影响；提问表单可用。

非目标：不改服务端、不改会话 JSONL、不改发送给模型的上下文、不改设置里的单 Agent 对话框与供应商生成对话框；不处理“思考”块；不跨消息按轮聚合。

## 4. 已确认决策

| 议题 | 结论 |
| --- | --- |
| 形态 | 折成一行摘要，点开看详情 |
| 组织方式 | 同一消息内连续工具调用合并成一行；单个工具不包 |
| 例外 | 提问卡片出现时单独显示；回答后恢复折叠 |
| 自带界面 | 一律折叠，展开才加载 |
| 思考块 | 不处理，保持现状 |
| 开关位置 | 设置里，全局开关 |
| 默认值 | 默认折叠 |
| 生效范围 | 仅 Agent 对话（面板/浮窗/画布节点面板） |
| 粒度差异 | 接受：实时一轮一行，刷新后可能按历史条目拆成几行 |

## 5. 需求边界

- 不动服务端与 `sessions.jsonl`；不改 `buildSessionContext()`。
- 不做 per-conversation 记忆。
- 不在 Agent 顶部工具栏加临时开关。
- 不合并“思考”块；不跨消息聚合。

## 7. 子代理初审记录（2026-10-30 11:00）

结论：方向成立，服务端 schema 实测放行；但首版有 7 处会导致验收不通过，已全部修订：

- R4 与方案自相矛盾（“回答后恢复折叠” vs “保持展开”）→ 统一为“回答后恢复折叠”，并要求客户端在非 running 事件里清除残留 `question`（服务端只在 running 事件带 `question`，客户端 `Object.assign` 不会删）。
- R6 事实纠正：`chat-reasoning` 默认 `v-show` 不卸载 → 改为 `v-if` 真正卸载；`liveMessageId` 不能当运行信号 → 用 `item.streaming || tools.some(status==="running")`。
- 新增 R11：最新行自动贴底会把刚展开的聚合行顶出视口 → 用户展开时跳过 `scrollToEnd`。
- 新增 R12：工具自带界面（画布聚焦、askUser）渲染在折叠容器外 → 口径定为“一律折叠，展开才加载”。
- R2 补充“单个工具不包一层”，避免把自带界面藏进折叠容器、收益为零。
- R3 补状态汇总优先级；R9 明确按钮保持现状（不隐藏 fork/delete）。
- 粒度差异（实时一轮一行 vs 刷新后按条目拆行）已确认接受并写入决策表。
