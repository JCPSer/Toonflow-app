# 需求矩阵：画布 Agent 节点之间真正通信与派活

- 时间：2026-11-15 19:40
- 类型：新能力（多 Agent 协作）
- 状态：待评审

## 1. 背景

画布上的 Agent 节点目前彼此隔离：每个节点一个会话，没有跨会话消息通道，也没有可调用的 nodeTools。用户明确不要「共享黑板节点」这类间接方案，要求 Agent 之间能真正派活、回传结果。

## 2. 已确认的产品决策

| 决策 | 选择 |
| --- | --- |
| 通信语义 | 异步派活：A 调用后立即返回，B 完成后结果回传 A 并触发 A 新一轮 |
| 目标范围 | 仅同一画布上的 Agent 节点，按 nodeId 定向 |
| B 忙时 | 排队，当前轮结束后执行 |
| 用户可见性 | 实时可见、可打断；节点状态同步 |
| B 的模型 | 会话上次模型 → 节点面板上次选择（需落盘）→ 派发方 A 的模型 |
| B 提问 | 允许，实时展示；没人回答则挂起，不自动超时 |
| A 收到结果 | 自动开始新一轮；A 正在运行时排到当前轮之后 |
| 限额 | 每画布 4 个后台派发并行；链路最多 8 跳；同一对节点 60 秒内相同消息去重 |

## 3. 需求矩阵

| 编号 | 需求 | 优先级 | 难度 | 风险 |
| --- | --- | --- | --- | --- |
| R1 | 新增 `sendToAgent` 工具：参数 `{ nodeId, message }`，立即返回任务 id，校验目标必须是同画布 Agent 节点、不能是自己 | 高 | 中 | 中：目标解析依赖画布实时数据 |
| R2 | 服务端派发服务：按目标会话排队；运行中不打断；每画布最多 4 个后台任务 | 高 | 高 | 高：与用户手动发送、文件锁、abort 语义交叉 |
| R3 | 目标 Agent 走完整运行时（工具、压缩、跨轮记忆），使用会话已有模型；无会话时按节点记录/派发方模型新建 | 高 | 中 | 中：模型与 nodeBinding 归属 |
| R4 | 目标 Agent 的画布工具在无面板打开时仍可用（持久画布 RPC） | 高 | 高 | 高：跨请求生命周期、多画布实例 |
| R5 | 结果回传：写入 A 的会话（标注来自 B、任务 id、跳数），A 空闲则自动开新一轮，运行中则 follow-up 排队 | 高 | 高 | 高：与用户消息交织、避免重复触发 |
| R6 | 实时可见：B 的面板显示 A 发来的任务与完整执行；节点状态运行中/等待；用户可停止 | 高 | 中 | 中：事件总线去重（面板自己发起的流 vs 后台流） |
| R7 | B 的提问进入全局提问横幅与 B 面板，回答后继续；挂起不影响其他任务 | 中 | 中 | 中：无面板时的提问投递 |
| R8 | 环路与风暴防护：最大 8 跳、自派发拒绝、同对同文 60 秒去重、每画布并发上限、停止时级联取消派生任务 | 高 | 中 | 中：误杀合法链式协作 |
| R9 | 失败回传：B 报错/被用户停止/超时都要把结构化结果回给 A，不让 A 永久等待 | 高 | 中 | 低 |
| R10 | 审计：会话里保留派发记录（谁派给谁、任务 id、跳数、状态），可在面板看到 | 中 | 低 | 低 |

## 4. 非目标（本期）

- 跨画布、跨项目派发。
- Agent 之间自由多轮闲聊（A 可多次派发实现多轮，但不是实时对话通道）。
- 用户自定义 Agent 角色/团队拓扑。
- 把子 Agent（subAgent）改造成画布节点。

## 5. 关键约束

- 同一工作区、同一画布；目标节点必须存在且未禁用。
- 画布 RPC 只在画布页面打开时可用；页面关闭时画布类工具调用应快速失败并回传明确错误。
- 不得绕过现有文件锁与运行中会话的所有权规则。
- 后台任务必须可被用户从 B 的面板停止；停止后回传「已取消」。
- 所有新增用户可见文案走 i18n。

## 8. 评审结论（子 agent + 架构修订）

- 原服务端 headless 方案被评为「需调整」：会话准入/所有权/取消/绑定/画布通道五件事会返工。
- 用户确认「页面关闭/刷新即中断」后，改为画布 dispatcher 架构；需求范围与四项产品决策不变。
- R4 调整为：画布工具由画布 dispatcher 在现有 `/api/agent` 流中执行，页面关闭即中断。
