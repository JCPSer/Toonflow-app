# 需求矩阵：视频节点「首帧 / 尾帧」可配置输出

- 时间：2026-10-31 09:35（v1，经 Grill 逐题确认）
- 提出人：liyuhang
- 模块：节点插件 `packages/nodes/videoNode`、`packages/nodes/videoGenerationNode`；宿主契约 `packages/nodeScaffold`
- 代码基线：`feat/exec-node`（`783aeda`）

## 1. 需求背景

视频节点（「视频」与「视频生成」）目前只有一路 `VIDEO` 输出。做「尾帧接下一段」这类链式续写时，用户必须手动点一次「截取尾帧」，生成一个**独立图片节点**，再手动连线。这个过程每次换视频都要重做一遍，且截出来的图是脱离视频节点的孤儿节点。

用户原始想法（2026-10-31）：

> 视频节点应该是插件形式吧，它只有一个视频输出。能不能这样，在插件配置里自定义输出项，另外新增首帧、尾帧？……要么就把首尾帧给输出出来，和视频放在一起（但是这样的话，如果视频分辨率较大，会占一些硬盘）。要么就是运行的过程中实时的生成首尾帧临时文件喂给下游。

### 1.1 仓库现状（已核实）

| 事实 | 依据 |
| --- | --- |

| 端口快照会同步进 `node.data.handles` 并随画布 JSON 持久化 | `packages/nodeScaffold/src/nodeSkeleton.vue:756` |

### 1.2 被否掉的方案：运行时临时文件

`outputs` 是**同步**响应式值，下游节点挂载即读 url。若改为「用到时才抽临时文件」，下游必须异步等待，属于宿主核心改动；且临时文件一经清理，重开工程、分支、分享导出、节点禁用重跑都会拿到空值。因此只采用「生成时落盘」。

## 2. 需求目标

1. 视频类节点可按实例开关「首帧」「尾帧」两路 `IMAGE` 输出端口。
2. 开关状态与帧文件随工程持久化，重开工程后端口、连线、图片都在。
3. 视频变化（重新生成 / 替换 / 切媒体历史）时帧自动跟随，绝不出现「视频是新的、帧是旧的」。
4. 帧以接近无损的 JPEG 落盘，体积远小于 PNG。

## 3. 非目标（本次不做）

- 不做「任意时间点」抽帧端口（只做首/尾两种）。
- 不改宿主核心（`nodeScaffold` / `nodeSkeleton` / 画布）行为；只依赖既有契约。
- 不把帧写入媒体历史，不让帧参与「分享导出」之外的任何新链路。
- 不修改现有「截取视频帧」菜单的行为（用户明确要求全部保留）。

## 5. 风险

| 风险 | 说明 | 缓解 |
| --- | --- | --- |
| R3 与 `useNode` 初始化顺序冲突 | savedOutputs 按**声明期 handles** 过滤，动态端口的值会在挂载时被丢掉 | 在调用 `useNode` **之前**按 `node.data.frameOutputs` 算出初始 handles 传入 |
| 4:4:4 JPEG 兼容性 | 部分解码器/下游模型对 4:4:4 子采样支持不一致 | 用应用内实际链路（`<img>`、图像节点、视频生成参考）验证；异常则回退 4:2:0 |
| 生成节点与视频节点逻辑漂移 | 两处各写一份抽帧 | 抽帧与端口维护抽到 `@toonflow/node-video` 共享模块 |
| 无视频轨/损坏素材 | 纯音频或下载失败的文件 | 失败即警告 + 端口置空，不阻塞 |
| 磁盘增长 | 每个视频多 2 张 JPEG | 关闭即删；单帧约 0.6–1.2 MB，远小于视频本体 |

## 6. 评审意见

### 第一轮：子 agent 架构评审（2026-10-31 09:50）

结论：**需修订后通过**。核心判断全部被证实（动态端口可行、不需改宿主、宿主会自动删悬空连线、`-sseof` 尾帧口径可复用）；同时纠正了 6 处会导致返工的设计。

| 轮次 | 意见 | 结论 |
| --- | --- | --- |
| 1 | R5 的 1 MB 体积阈值不成立：噪点素材实测 1.75 MB | 改为不设硬阈值，只记录实测值 |
| 1 | R8「端口留空」与方案「先抽帧再出端口」矛盾 | 拆成两条路径：开启失败不出端口；重抽失败留空端口 |
| 1 | R4 给「视频」节点写了「切换媒体历史」，该节点其实没有媒体历史 | 改为仅生成节点有；补上 `setVideo` 工具与「清除」入口 |
| 1 | R7「先清空再重抽」若发生在生成开始，失败/取消会让旧帧无端消失 | 改为「写入新视频的同一时刻」清空 |
| 1 | R9 关闭即删文件会破坏复制节点（共享同一路径） | 改为保留文件，只清值与端口 |
| 1 | R12 未说明分享导出会把帧重编码为 q3/420 | 在方案中注明导出后画质会降，属既有图片策略 |
