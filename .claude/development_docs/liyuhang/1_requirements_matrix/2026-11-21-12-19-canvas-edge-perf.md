# 需求矩阵：大型画布连线渲染优化

- 时间：2026-11-21 12:19
- 提出人：用户
- 现象：500 条以上连线的画布，平移/缩放时明显掉帧；节点数量不是主因。

## 1. 需求背景

画布基于 `@vue-flow/core@1.48.2`，节点必须常驻（`only-render-visible-elements=false`，节点里有视频/音频/编辑器状态，裁剪节点会丢状态），因此不能走 Vue Flow 自带的整体裁剪。已有优化覆盖了「拖动节点时冻结虚线动画」（2026-11-01）与「动画 10Hz 降频」，但平移/缩放没有专门处理。

## 2. 需求目标

同一张 500+ 边画布，平移/缩放的手感接近 100 边规模；不改变连线行为（点击断开、选中高亮、虚线流动、显隐开关），不改画布 JSON 与撤销历史。

## 3. 需求描述

| 编号 | 需求 | 优先级 | 难度 | 风险 |
| --- | --- | --- | --- | --- |
| R1 | 视口外的连线不生成 path，减少 SVG 元素、光栅化与命中测试 | P0 | 中 | 中：错裁会「丢线」，需要包围盒+外扩兜底 |
| R2 | 平移/缩放手势进行中，连线层降级：去掉透明命中路径、关闭虚线动画、不接收指针事件 | P0 | 低 | 低：手势结束后恢复，交互有 180ms 空窗 |
| R3 | 静止时每条边的透明命中带从 40px 缩到 28px | P1 | 低 | 低：点击断线的可点区域略小 |
| R4 | 不裁剪节点、不改 edges 数据、不影响自动保存/撤销 | P0 | 低 | 低：只加渲染层判定 |

## 4. 非目标

- 不改 `only-render-visible-elements`（节点必须常驻）。
- 不默认开启「画布合成优化」（`will-change` 会让缩放期间变糊，保留为用户设置）。
- 不改虚线动画频率、默认开关。

## 5. 验收标准

1. 500+ 边画布平移/缩放不再整片掉帧；静止时连线完整显示，无闪烁、无错裁。
2. 点击连线仍能弹出断开按钮；隐藏连线、选中高亮、虚线流动行为不变。
3. 画布保存内容、撤销/重做快照与改动前一致（edges 无新增字段）。
4. 单元测试覆盖视口框换算与相交判定。

## 6. 评审意见（待填写）

| 级别 | 意见 | 处理 |
| --- | --- | --- |
| P1 | `.viewportMoving` 里对 `.vue-flow__edges` 的 `pointer-events:none` 无效：真正可点的是子元素 `g.vue-flow__edge`（库样式 visibleStroke），外层 svg 本来就是 none | 已改为 `.vue-flow__edge` |
| P2 | `interactionWidth` 40→28 在 min-zoom 0.2 时屏幕命中带只剩 5.6px，缩小视图下点不中断线 | 已回退为 40，命中开销交给手势降级 |
| P2 | 注释称滚轮缩放没有 sourceEvent 导致钩子跳过，实际 `zoom.scaleBy` 第 4 个参数传了 event | 注释改为「watch 覆盖程序化改动，不依赖事件参数」 |
| P2 | culledEdge 坐标非有限数会被静默裁掉；`inheritAttrs:false` 会吞掉未来 slot 新字段 | 已加 `Number.isFinite` 保护；改为透传 `$attrs` |
| P2 | 尺寸为 0 时清空 viewBox 会让所有边全量重建 | 已改为保留上一帧的框 |
| P2 | 旧画布若显式存 `type:"default"` 会绕过裁剪 | 已核查数据目录无此类边；不补 `#edge-default`（bbox 近似对默认贝塞尔不成立），留作已知限制 |
| P2 | 外扩 50% 的收益需实测（渲染约 4 倍视口面积） | 保留 0.5 保安全，后续按性能 trace 再调 |

结论：P1 修复、P2 采纳，通过。
