# 需求矩阵：视频节点让 Agent 查看视频内容

- 时间：2026-11-01 13:50
- 提出人：liyuhang
- 状态：待评审

## 1. 需求背景

Agent 在画布上处理视频时，缺少「看视频」的手段：

- 视频节点（`packages/nodes/videoNode`）与视频生成节点（`packages/nodes/videoGenerationNode`）只通过 `setFrameOutputs` 提供首帧/尾帧两路输出（`frameOutputPlan.ts` 的 `FRAME_OUTPUTS` 写死 `first`/`last`），Agent 只能拿这两张静帧下结论。
- Agent 虽可用内置 `ffmpeg` 工具自行 seek 截帧，但系统提示没有引导，且一次只能看一个时间点，多帧对比要反复调用、反复读图，成本高且不稳定。
- Agent 无法主动把整段视频作为视频输入发给模型：只有用户把视频作为附件或引用视频节点输出时，运行时才会以内联视频发给模型（`apps/server/src/agent/runtime/index.ts:232`）。
- 系统提示已明确要求「静帧不代表看过完整视频」（`apps/server/src/agent/runtime/prompt.ts:31`），现状缺乏满足该要求的低成本手段。
- 已有「逐帧拉片」节点（`packages/nodes/frameAnalysisNode`）能力重（场景检测 + 生成结果节点 + 可选 AI 标注），不适合 Agent 随手的「看一眼」。

## 2. 需求目标

让两个视频节点的 Agent 以低成本、按需方式查看视频内容：

1. 一次调用拿到覆盖全片的均匀多帧「宫格联系表」，快速把握构图、动作、转场与整体节奏。
2. 需要细节时按时间点取全分辨率单帧。
3. 不新增画布节点、不改动现有首尾帧端口与逐帧拉片链路。
4. 产物可控，不在项目里无限堆积。

## 3. 需求描述

| 编号 | 需求 | 说明 | 优先级 | 难度 | 风险 |
| --- | --- | --- | --- | --- | --- |
| R1 | 宫格联系表工具 | 两个视频节点各提供一个 Agent 工具：按 4/9/16 帧（默认 9）均匀抽帧拼成单张宫格，返回图片工作区路径、宫格行列、各格近似时间点阵、时长与分辨率 | P0 | 中 | 中：ffmpeg 滤镜链与时长探测失败时的降级 |
| R2 | 按时间点截帧工具 | 一次接受 1–6 个时间点，逐个输出全分辨率 JPEG，返回各自路径 | P0 | 低 | 低 |
| R3 | 状态防护 | 节点还没有视频时报明确错误；视频生成节点正在生成、视频节点正在上传/导出时直接拒绝，避免 Agent 拿旧视频下结论 | P0 | 低 | 低 |
| R4 | 产物落地与返回 | 产物写入 `assets/<nodeId>/inspect/`，工具返回工作区相对路径与元信息；Agent 用 `read` 打开图片 | P0 | 低 | 低 |

| R6 | 不回归 | 首尾帧端口、逐帧拉片节点、`setFrameOutputs` 语义不变 | P0 | 低 | 低 |
| R7 | 文档归档 | 需求/方案/测试/记忆与索引齐全 | P1 | 低 | 低 |

### 非目标（本期不做）

- 不做整段视频内联给模型（依赖模型能力、体积与计费，另行评估）。
- 不做音频理解（音轨转写已有独立能力，不在本次范围）。
- 不新增面向工作区任意视频的通用工具（素材库视频仍用现有 ffmpeg 工具）。
- 不在宫格上烧时间戳（避免依赖宿主字体）。
- 不为「查看」新增节点内 UI 按钮。

## 4. 已确认的关键取舍

| 决策点 | 结论 |
| --- | --- |
| 能力范围 | 多帧序列看图 + 按时间点按需截帧 |
| 产出形态 | 宫格单图（默认 3×3） |
| 适用范围 | 只挂两个视频节点，不做通用工具 |
| 生成中行为 | 直接拒绝，提示等生成结束 |
| 时间戳 | 不烧图，返回时间点数组 |
| 单次截帧点数 | 最多 6 个 |
| 清理口径 | 查看前清同类产物 + 退出/关窗时清 |

## 5. 验收标准

1. 对已有视频的视频节点调用宫格工具，`assets/<nodeId>/inspect/` 下生成 1 张宫格图；返回的行列数、帧数、时间点数组与图片实际格数一致，Agent `read` 后可正常打开。
2. 调用截帧工具传入 1–6 个时间点，得到对应数量的单帧；重复时间点去重后执行，越界或超过 6 个时报可读错误。
3. 无视频节点调用任一工具返回「节点还没有视频」类错误，不产生空目录与残留文件。
4. 视频生成节点生成中调用被拒绝；生成结束后可正常调用。
5. 重复调用宫格工具不会累积多张宫格；重复调用截帧工具不会累积超过 6 张单帧。
6. 退出项目、关窗/⌘Q 时尽力清理对应节点的 `inspect/` 目录；清理超时或失败不影响退出流程。
7. 首尾帧输出端口与逐帧拉片节点行为不变。
