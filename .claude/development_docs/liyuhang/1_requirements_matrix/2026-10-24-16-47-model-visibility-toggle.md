# 需求矩阵：模型显示/隐藏开关

## 一、需求背景

设置里配置的文本/媒体供应商动辄带几十个模型（中转站「获取模型」一次拉回全量）。用户实际只常用其中几个，其余长期占着画布节点的模型下拉框，选起来又长又乱。直接删除有代价：删掉后想再用要重新拉取，本地手改的标签和推理档位也一起丢。

需要一种**不删除、只隐藏**的机制，让下拉框回归干净。

## 二、需求目标

1. 设置页可为**供应商**和**模型**分别设置「在节点中显示」，默认全部显示，不改变任何现有配置的可读性。
2. 供应商的隐藏优先级高于模型：供应商隐藏时，其下模型即使处于启用状态也不出现在下拉中。
3. 隐藏不破坏既有项目：画布节点、智能体配置里**已经选中**的隐藏模型仍然出现在对应选择器中，并标注「已隐藏」，避免静默失效。
4. 隐藏状态在「获取模型」重新拉取后**保留**（按 id 匹配）。
5. 不做批量操作。

## 三、需求描述（R 编号）

| 编号 | 需求 | 说明 | 优先级 | 难度 | 风险 |
| --- | --- | --- | --- | --- | --- |
| R1 | 供应商级隐藏开关 | 文本模型面板、媒体模型面板的供应商卡片上各一枚「在节点中显示」开关 | P0 | 低 | 官方 tfRouter 也可隐藏，需确认可接受 |
| R2 | 模型级隐藏开关 | 文本供应商「编辑」抽屉里的模型行、媒体「编辑模型」弹窗里的模型卡片，各一枚开关；开关即时生效，不随「取消」回滚 | P0 | 低 | 同一弹窗内「保存」只管模型数据、开关只管显示状态，两种语义需要在 UI 上区分清楚 |
| R3 | 供应商优先 | 可见性 = 供应商可见 && 模型可见，服务端一次算好 `hidden` 字段下发 | P0 | 低 | 无 |
| R4 | 已选中项保留并标注 | 节点下拉、智能体模型选择器：当前选中项即使被隐藏也保留，标签追加「（已隐藏）」 | P0 | 中 | 需改动 8 个节点包与 1 个选择器组件，并重建 node UMD |
| R5 | 影响范围 | 画布节点下拉（文本/图片/视频/音频/3D/拉片/出错重选）+ 智能体与对话的模型选择器；`modelChoices` 等**查表**用途不过滤 | P0 | 中 | 查表过滤会导致选中项标签丢失 |
| R6 | 持久化与刷新保留 | 隐藏状态单独存 `settings.modelsHidden`，不塞进供应商配置对象；「获取模型」按 id 合并保留 | P0 | 中 | 媒体供应商配置对象会直接传给插件运行时，不可混入自定义字段 |
| R7 | 缓存失效 | 保存隐藏状态后节点模型缓存立即失效，下拉刷新 | P0 | 低 | 媒体侧当前只触发 provider-config-changed，未清模型缓存 |
| R8 | 设置页反馈 | 供应商卡片显示「N 个模型 · 已隐藏 M」，隐藏态卡片有视觉区分 | P1 | 低 | 无 |
| R9 | 不做批量 | 不提供「全部隐藏/显示」 | P2 | — | 后续可加 |

## 四、明确不做

- 不删除、不改动任何模型/供应商数据本身。
- 不隐藏 `modelChoices`（查表用）与历史记录中的模型名。
- 不做批量操作、不做拖拽排序。
- 不改变服务端 `getConfiguredModel` 的解析逻辑：隐藏的模型依然可以被已保存的任务调到。

## 五、关键风险与待定

| 风险 | 说明 | 处置 |
| --- | --- | --- |
| 已建项目命中隐藏模型 | 用户画布 17 个节点，可能正在用某个准备隐藏的模型 | R4 保证仍可选择与运行；标签标注「已隐藏」 |
| 媒体配置对象污染 | `mediaProviderConfigs[id]` 原样传入插件运行时 | 隐藏状态一律走 `settings.modelsHidden` 旁路 |
| 节点 UMD 需重建 | 过滤逻辑在 `groupNodeModels`，8 个节点包要重新打包 | 逐包 `vite build`，产物同步到 `data/nodes` |
| 智能体选择器分叉 | 若只改节点不改 `modelPopover`，两边表现不一致 | R5 统一处理，同一套「已选中保留」规则 |
