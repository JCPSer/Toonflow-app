# 需求矩阵：退出前检查运行中节点

- 时间：2026-11-01 12:10
- 分支：`feat/exec-node`
- 提出人：用户

## 1. 需求背景

当前三条离开当前项目的路径，对「节点正在跑」的处理不一致：

- 顶栏「退出项目」按钮 / 画布 Esc（`pages/workspace/exitProject.ts`）：只弹「是否退出当前项目并返回首页？」，不检查运行态；确认后直接 `router.push("/home")`，节点靠卸载时的 `AbortController` 被动中断。
- 画布菜单「切换项目」（`canvas/index.vue` `switchProject`）：已有「有节点正在运行，切换项目会中断」确认。
- 关闭窗口 / ⌘Q / Dock 退出（`apps/desktop/src/index.ts` `will-close`、`before-quit`）：只等前端 flush（最长 4s）就放行，**没有任何确认，用户无法取消退出**。

结果：用户可能在批量生成或 Agent 长任务途中误点退出或误关窗口，任务被静默中断且没有挽回机会。

## 2. 需求目标

- 离开当前项目、关闭应用前，若存在运行中的节点，必须提示用户并允许取消。
- 「运行中」判定覆盖所有画布实例（含后台画布），不区分当前是否可见。
- 提示只在确有运行中节点时出现，平时完全无感，不引入设置开关。
- 不改变现有保存闸门（flush）行为，只在保存闸门前增加一道确认。

## 4. 交互设计

### 4.1 退出项目

现有确认框保留为第一层？——不保留两层弹窗。改造为单一弹窗：

- 无运行中节点：`是否退出当前项目并返回首页？` → 按钮「取消 / 退出项目」
- 有运行中节点：`当前有 N 个节点正在运行，退出项目会中断它们的任务。是否仍要退出？` → 按钮「留在此页 / 仍然退出」，警告色

### 4.2 关闭窗口 / ⌘Q

- 有运行中节点：同一文案（标题「退出 Toonflow」），按钮「留在此页 / 仍然退出」。
- 选「留在此页」：窗口不关，应用不退出。
- 选「仍然退出」：照常 flush 后关闭。

## 5. 不在本次范围

- 不做「退出前自动停止所有节点再退出」的独立动作为按钮（卸载时的 abort 仍是实际中断手段）。
- 不记忆/不提供「不再提醒」。
- 不展示节点名称、画布名称。
- 不改变后端任务取消接口。
- 更新重启（应用内更新）不做运行中确认：更新由用户主动发起，且更新器有自己的退出审批流程；在其中插入可取消的确认会破坏更新状态机。
- 分享包导入后自动切换项目、MCP 程序化打开项目不做确认：前者是导入后的明确后续动作，后者弹模态框会阻塞调用方。
- 画布标签关闭、画布文件删除不做确认：本身就是卸载实例并中断任务的操作，与项目退出无关。

## 6. 验收口径

1. 三个画布各跑一个节点（含后台画布），点「退出项目」：提示「有 3 个节点正在运行」，选「留在此页」后仍在工作区，节点继续跑。
2. 无节点运行：退出项目仍是原来的确认框，不出现数量提示。
3. Agent 节点正在向用户提问（未回答）时退出，同样计入数量并提示——无论提问是否已在面板里看到；只是「上一轮已结束、停在 waiting 空闲态」的 Agent 节点不计入。
4. 有节点运行时 ⌘Q / 点窗口关闭：弹出提示；选「留在此页」窗口不关，选「仍然退出」正常退出。
5. 在关窗提示框停留 30 秒以上（超过原 4 秒 flush 超时），不会被主进程自动关闭。
6. 切换项目提示的数量与退出项目一致。
7. 首页/设置页（无工作区）关窗不受影响，行为与现在一致。
