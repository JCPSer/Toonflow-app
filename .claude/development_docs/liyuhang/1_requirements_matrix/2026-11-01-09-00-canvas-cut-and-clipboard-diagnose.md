# 需求矩阵：画布 ⌘X 剪切 + 剪贴板复制失败诊断

- 时间：2026-11-01 09:00
- 分支：`feat/exec-node`
- 提出人：用户

## 1. 需求背景

用户反馈两件事：

1. 画布不支持传统剪切快捷键：现有快捷键只有复制（⌘C）与粘贴（⌘V），`defaultCanvasShortcuts` 中没有 cut；按 ⌘X 只会落到 WebView 原生剪切（画布无文本选区时什么也不发生）。
2. 在画布 Agent 节点的问答框附近复制文本时，会提示「复制失败，请重试」，「但其实是复制成功了的」。代码里这句提示只来自 `conversation.vue` 的 `copyMessage`（复制消息/工具结果按钮），`writeClipboardText` 在桌面端调用 `/api/desktop/clipboard/write`。本地用同源请求直连该接口可以正常写入并回读，无法稳定复现 WebView 里的失败。

## 2. 需求目标

- 画布支持 ⌘X 剪切节点：复制成功后删除，可撤销；复制失败不删除。
- 剪贴板复制的假失败先补诊断日志，能对上「客户端失败」与「服务端写入」两条记录，再决定修法。

## 3. 需求描述

| 编号 | 需求 | 优先级 | 难度 | 风险 |
| --- | --- | --- | --- | --- |
| R1 | ⌘X = 复制选中节点到剪贴板 + 删除；删除进入画布历史，⌘Z 可恢复 | P0 | 中 | 复制/删除两步非原子，需保证失败不删 |
| R2 | 剪切必须支持设置页自定义（与复制/粘贴同一套快捷键配置） | P1 | 低 | 新增字段的默认值/旧配置兼容 |
| R3 | 输入框或正文有文本选区时，⌘X 走原生剪切，不剪节点 | P0 | 中 | 事件 target 判定不准会误删节点 |
| R4 | 焦点在 Agent 节点面板里且没有选文字时，⌘X 与 ⌘C/⌘V/Delete 一样作用于选中节点 | P2 | 低 | 面板语境白名单 |
| R5 | 复制失败（节点 copy 钩子/文件/系统剪贴板写入失败）时保留节点并提示原因 | P0 | 低 | 否则内容丢失 |
| R6 | 图片节点 ⌘X：先复制图片，再删除节点 | P1 | 低 | 与现有「复制图片」分支保持一致 |
| R7 | 复制假失败：服务端记录写入请求/成功/异常与桌面桥拒绝原因，客户端失败时上报状态码与原因（不含正文），用请求 id 关联 | P0 | 中 | 日志泄露正文/噪声 |
| R8 | 诊断不改变现有成功路径；不引入测试文件 | P0 | 低 | 违反 AGENTS.md 测试边界 |

## 4. 不在本次范围

- 不直接修改复制失败的判定（不加回读校验、不改回退逻辑）；先拿日志再定。
- 不新增画布「剪切」按钮或右键菜单项，只做快捷键与原生 cut 事件。
- 不改文档面板文件树的剪切逻辑。

## 5. 验收口径

1. 画布选中节点按 ⌘X：节点消失，⌘V 能粘贴回来，⌘Z 能恢复删除。
2. 节点复制失败时：节点仍在，出现失败提示，不产生删除。
3. 在输入框/正文选中文字按 ⌘X：剪切的是文字，节点不受影响。
4. 设置页「快捷键」里能看到「剪切到剪贴板」并可改键。
5. 复现复制失败后，`<数据目录>/logs/agent.log` 里能用同一个 `clipboardId` 对上 request/done 或 error 与 clientError，且日志不含正文。
6. 原有 ⌘C/⌘V/Delete/撤销行为不变。
