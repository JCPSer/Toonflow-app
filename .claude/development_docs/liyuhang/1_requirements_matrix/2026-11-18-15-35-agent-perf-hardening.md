# 需求矩阵：多 Agent 场景的剩余卡顿点优化

- 时间：2026-11-18 15:35
- 范围：上下文统计、面板历史传输、画布保存重试

## 需求背景

事件总线解决了 WebKit 6 连接耗尽，但多 Agent 下仍有可感知卡顿：大会话每次 `message_end` 都调用 `buildSessionContext()` 全量物化消息；面板一次返回整段历史（含数十 KB 工具结果）；外置盘上画布保存的 EBUSY 重试窗口只有约 0.4 秒。

## 需求目标

1. 上下文统计不再周期性全量构建消息，降低多 Agent 流式时的主线程占用。
2. stats 发送合并，减少服务端到前端的重复计算与 JSON 传输。
3. 面板历史只截断展示副本中的超长工具结果/思考块，降低一次性 JSON 体积与前端解析成本。
4. 画布保存对慢盘/锁冲突有更长的退避窗口，减少误报「画布保存失败」。

## 需求描述

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| R1 | 增量上下文统计 | `getAgentContext` 直接在分支条目上估算，不再 `buildSessionContext()`；保留压缩摘要、尾部条目、usage 口径 |
| R2 | stats 节流 | 750ms 合并；运行收尾强制立即发送；不丢最终数值 |
| R3 | 展示截断 | 工具结果 32KB、思考块 64KB，超出附截断说明；只影响 `/api/agent/get` 展示，不影响会话文件与模型上下文 |
| R4 | 保存重试 | 画布保存使用 6 次、120ms 起的指数退避（最坏约 4 秒）；其它写文件保持原策略 |

## 优先级 / 难度 / 风险

- 优先级：P2（体验优化）。
- 难度：低—中。
- 风险：统计口径偏差会影响自动压缩触发点；截断可能让用户看不到完整工具输出（需提示）；节流可能导致进度条略滞后。

## 验收标准

1. 大会话（30 万 token 以上）连续流式时，stats 事件不超过约 1.3 次/秒。
2. 上下文 tokens 与修改前同口径（允许尾部估算的少量差异），压缩阈值百分比不变。
3. 面板历史中超过阈值的工具结果带截断说明，会话文件保持完整原文。
4. 外置盘偶发 EBUSY 时，画布保存能在数秒内重试成功而不是立刻报错。
5. 服务端全量单测、web 单测与构建通过。
