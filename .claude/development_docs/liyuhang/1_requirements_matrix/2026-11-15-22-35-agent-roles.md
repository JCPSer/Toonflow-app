# 需求矩阵：Agent 预制角色（可复用的初始上下文）

- 时间：2026-11-15 22:35
- 类型：新能力
- 状态：待评审

## 1. 背景

画布上每个 Agent 节点现在只有「通用」一种身份。用户按职责拆分 Agent（导演、分镜、提示词撰写、提示词审核）时，每次都要新建节点并手写一遍初始上下文，重复劳动。需要一套可复用的角色预置：角色 = 名称 + 可选描述 + 一段系统提示词，选择后作为该节点的初始身份。

## 2. 已确认的产品决策

| 决策 | 选择 |
| --- | --- |
| 提示词关系 | 保留软件自带系统提示词，但角色提示词优先；冲突时以角色为准 |
| 管理入口 | 在 Agent 节点插件内（画布 Agent 面板）增删改角色 |
| 角色库范围 | 全局角色库，跨项目复用 |
| 选择器位置 | 模型/思考强度弹层内，其下方追加「角色」 |
| 生效范围 | 只作用于画布 Agent 节点；右侧全局 Agent 面板不出现 |

## 3. 需求矩阵

| 编号 | 需求 | 优先级 | 难度 | 风险 |
| --- | --- | --- | --- | --- |
| R1 | 全局角色库：角色含 id、名称（≤40）、描述（可选）、系统提示词（≤20000），存于设置（settings.agentRoles），最多 50 个 | 高 | 低 | 低 |
| R2 | 角色管理界面：Agent 节点面板内可新增、编辑、删除、重命名角色；保存即全局生效 | 高 | 中 | 低 |
| R3 | 节点角色选择：模型弹层「思考强度」下方追加「角色」，含「通用」与全部角色；选择写入 node.data.agentRoleId | 高 | 中 | 中：与模型落盘现状不同，角色要持久化 |
| R4 | 运行时组合：角色提示词置于系统提示最前，其后是全局自定义/默认系统提示，再是工具、环境、AGENTS、记忆；冲突以角色为准 | 高 | 中 | 中：顺序与占位符处理 |
| R5 | 派发一致性：dispatcher 跑目标节点时使用该节点的角色 | 高 | 低 | 低 |
| R6 | 切换角色只影响后续轮次，不改写既有会话历史 | 高 | 低 | 低 |
| R7 | 角色被删除时，引用节点回退「通用」且给出提示 | 中 | 低 | 低 |
| R8 | 不继承：子 Agent / 派发链的下游节点各用自己的角色，不自动继承上游 | 中 | 低 | 低 |

## 4. 非目标

- 角色绑定默认模型/思考强度（本期只做提示词）。
- 角色绑定技能白名单、工具权限。
- 角色提示词内变量插值/模板。
- 右侧全局 Agent 面板、文本节点 Agent 的角色选择。

## 5. 关键约束

- 角色提示词不拼接进默认正文，而是独立段落放在最前，标明优先级。
- 角色选择必须随每次请求下发，服务端按 id 解析，不信任前端拼好的完整提示词。
- 角色库变更不影响正在运行的轮次。
- 不修改既有 `agentSystemPrompt` 设置语义。
