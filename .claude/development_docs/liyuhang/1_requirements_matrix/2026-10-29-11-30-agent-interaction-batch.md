# 需求矩阵：Agent 交互六项改造

- 记录时间：2026-10-29 11:30
- 用户：liyuhang
- 关联：`2_requirements_solutions/2026-10-29-11-30-agent-interaction-batch.md`

## 一、需求背景

Agent 对话是这套产品的核心入口，但当前存在一个静默失效的缺陷（模型下拉不可见），以及若干交互缺口：语音按钮无法关闭、Agent 节点不能被引用、节点面板关掉就丢草稿、没有目标循环、生成中无法继续编辑或排队发送。

## 二、需求描述与优先级

| 编号 | 需求 | 优先级 | 难度 | 风险 |
| --- | --- | --- | --- | --- |
| R1 | 恢复 Agent 对话框的模型下拉（浮动面板与节点面板都要） | P0 | 低 | 低 |
| R2 | 语音输入按钮可在「媒体生成控制」中关闭 | P1 | 低 | 低 |
| R3 | Agent 节点可被 @ 引用，并带会话产出文件索引 | P1 | 中 | 中 |
| R4 | 节点面板关闭再打开，输入内容保留（内存，重启清空） | P1 | 低 | 低 |
| R5 | 指令模式：`/compact`、`/goal` 及 stop/reset/off 子命令，目标未达成时自动循环 | P0 | 高 | 高 |
| R6 | 生成中可继续编辑；发送进入待发送队列；另有立即打断发送 | P0 | 中 | 中 |

## 三、R1 根因（已定位）

`conversation.vue` 的三个可选布尔 prop（`showModelPicker`、`acceptPending`、`autoFocus`）没有默认值。Vue 对 Boolean 类型 prop 的缺省值是 `false`，于是 `showModelPicker !== false` 恒为假 —— 模型下拉、首页待发消息接收、打开即聚焦三者同时静默失效。**这是数据驱动的结论，不是猜测**：在运行中的应用里实测 `.senderActions` 首个节点是注释占位，且 `modelPopover` 数量为 0；修好后同一位置出现 2 个模型按钮。

## 四、R5 已确认的语义（grill 结论）

- 判定方式：每轮结束由模型自评，达成时输出 `[[GOAL:DONE]]` 标记；未达成自动进入下一轮。
- 轮次上限：默认 10，超过则自动暂停并提示。
- 子命令归并为四类语义：`stop` 暂停（保留目标）、`reset [新目标]` 重置轮次或改目标、`off|none|cancel` 清除目标、无参数查看状态；额外提供 `help`。
- 作用域：会话级（按会话文件存 `.agent/goals/<sessionFile>.json`）。
- 打断后重新打开对话要继续循环（激活时自动补跑一次）。

## 五、R6 已确认的语义（grill 结论）

- 生成中不锁输入框，可继续编辑与添加附件/引用。
- 发送按钮在生成中变为「加入待发送队列」；本轮自然结束后自动发队首。
- 另一个按钮「打断并立即发送」：中止当前轮后立刻发这条。
- 用户手动点「停止」时不自动续发队列（避免"点了停止还在发"）。

## 六、R3 的设计取舍

不给 Agent 节点加输出端口，只做 `@` 引用 + 文件索引：引用内容是最近一轮回复摘要 + 该会话里出现过且仍存在的文件（路径/大小/扩展名），模型需要正文时按路径 `read`。这样不改画布拓扑与连线规则。

## 七、非目标

- 斜杠命令的弹出式自动补全菜单（本轮只做输入拦截 + `/goal help` 提示）。
- `/goal` 的独立评审 agent（用户选择模型自评）。
- 语音开关迁移到通用设置（用户要求放媒体生成控制）。

## 八、验收标准

1. 浮动 Agent 面板与画布 Agent 节点面板都能看到模型下拉，切换生效。
2. 关闭「显示语音输入按钮」后，按钮消失且长按输入框不再启动语音。
3. `@` 列表里能选到 Agent 节点，引用内容含会话摘要与文件索引。
4. 节点面板输入一半关闭，再点开内容还在；重启应用后清空。
5. `/goal 写一段文案` 后每轮结束自动回顾，达成时停止并提示；`/goal stop|reset|off` 行为符合上表。
6. 生成中可以继续打字、入队、打断发送；队列条目可删除与立即发送。
