# 需求矩阵：节点提醒（音/通知）、分组框选语义、批量入素材库

- 记录时间：2026-10-29 15:07
- 提出人：liyuhang
- 关联画布：`apps/web/src/pages/workspace/panels/canvas/`

## 一、需求背景

画布上一条链路跑起来后，人往往切去干别的事：长任务结束后没有任何提示，回来才发现早就跑完了或者早就失败了；Agent 节点停下来等输入时同样容易错过。另一方面，分组把整块矩形都当成自己的地盘，导致组内空白无法起手框选、一擦就整组选中；框选出一批图片/视频后又只能一张张手动存进素材库。

## 二、拷问结论（已与用户确认，作为需求基线）

| 决策点 | 结论 |
| --- | --- |
| 提示音触发范围 | 单节点执行耗时 **> 30 秒** 的完成事件；文本/工具节点只要超 30 秒也算，不超就不响 |
| 提示音实现 | WebAudio 现场合成双音，不引入音频文件 |
| 前台是否响 | 做成设置项：**总是 / 仅应用不在前台时 / 关闭**，默认「总是」 |
| 失败音 | 区别于成功：成功上行双音、失败下行双音 |
| 连续完成 | 1 秒内的多次完成合并成一次（文案写「N 个节点已完成」） |
| 系统通知事件 | 慢节点完成、节点失败/超时、Agent 提问/等待输入 |
| 系统通知形态 | **只做桌面应用**；浏览器打开 127.0.0.1:50095 时不发系统通知 |
| 通知点击 | Electrobun `showNotification` 只有 title/body/subtitle/silent，**没有点击回调**（已查协议与文档）。因此改为：通知只负责把人叫回来；回到应用后画布顶部出现「N 个节点已完成 / M 个 Agent 在等你」横幅，点横幅条目才定位到具体节点 |
| 开关 | 设置项（提示音、系统通知各自开关）+ 画布工具条快捷静音 |
| 分组框选判定 | 该组**全部后代节点**都在框内才选中分组；空组不参与框选 |
| 分组部分被框到 | 只选中被框到的子节点，分组本身不选中 |
| 分组内容区空白拖拽 | 拉框选节点（不再是整组移动） |
| 分组移动/选中 | 只能在标题栏（标题栏点击区域要放大，不能太小）；缩放手柄保留 |
| 批量入素材库入口 | 选中工具栏出现「加入素材库」按钮，仅在选中项全是图片/视频节点时可用 |
| 取哪张产物 | 每个节点取当前展示的那一张 |
| 文件处理 | 复制进素材库目录，保证源节点被删也不失效 |
| 目标库 | 当前项目库 |
| 入库文件名 | 「节点名 + 序号」（如 `图片节点 1.png`），不用 `image<uuid>.png` |
| 重名冲突 | 自动加序号（`xxx 2.png`），不覆盖、不中断整批，结束后汇总 |

## 三、需求矩阵

### R1 节点完成提示音

- 背景：长任务结束无感知。
- 目标：超过 30 秒的节点执行结束时有声音反馈。
- 描述：在节点执行生命周期的统一出口判定「本次执行时长 > 30s」，触发提示音；成功与失败音型不同；1 秒内多次合并；受设置项与快捷静音控制。
- 优先级：P1
- 难度：低
- 风险：低。需确认浏览器/WebView 在无用户手势后是否允许 AudioContext 发声（首次交互后已解锁即可）。

### R2 系统通知（仅桌面应用）

- 背景：应用不在焦点时，完成与提问都无从得知。
- 目标：窗口失焦时用系统通知把用户叫回来；回应用后由画布横幅承担「定位到哪个节点」。
- 描述：慢节点完成、失败/超时、Agent 提问三类事件，在窗口失焦时发系统通知（原生 `Utils.showNotification`，无点击回调）；回应用后画布顶部横幅列出未读事件，点击定位节点（Agent 提问直接打开对话面板并滚到提问那条）；受设置项与快捷静音控制；web 模式不发。
- 优先级：P1
- 难度：中（依赖桌面壳的 native 通知能力，待探查结论确认走 RPC 还是 Web Notification）
- 风险：macOS 通知权限被拒后静默失效，需要一次性引导；Electrobun 无点击回调，只能靠系统默认行为把应用带到前台，定位能力必须由画布横幅兜住；通知走「webview → 主进程」的 host message，桌面主进程代码需重新打包并**重启应用**才生效。

### R3 分组框选与命中区域

- 背景：分组矩形整块可命中，导致组内空白无法框选、轻微擦到就整组选中。
- 目标：分组只在「真的被完整框住」时才被选中，且组内空白回归画布语义。
- 描述：
  - 3a 框选：分组不按矩形相交判定，改为「全部后代节点都在框内」；只框到部分子节点时只选子节点；空组不参与框选。
  - 3b 命中：分组内容区空白穿透到画布——单击等于点空白（清选区），拖拽等于框选，中键/空格仍是平移；子节点命中不受影响。
  - 3c 分组自身交互（单击选中、拖动整组、右键菜单）收敛到标题栏；标题栏命中高度放大到不小于 26px 并加 hover 底色；四角缩放手柄保留。
- 优先级：P1
- 难度：中高（框选判定在 Vue Flow 内，需要沿用现有 `patches/vueFlowCore.patch` 机制改 dist）
- 风险：
  - 改第三方 dist，升级 Vue Flow 时补丁需重新落；须在补丁里写清 ACT 注释。
  - 组体 pointer-events 穿透会影响既有的「组内连线穿透探测」与「组内右键转发」，需逐个回归（连线可点中、右键菜单不丢项、拖动组仍可用）。
  - 嵌套分组时「全部后代」要递归，不能只看直接子节点。

### R4 框选图片/视频节点批量加入素材库

- 背景：批量产出后只能一张张手动存。
- 目标：框选一批图片/视频节点，一次复制进当前项目素材库。
- 描述：选中工具栏新增「加入素材库」，仅当选中根节点全部为图片/视频节点时可点；每个节点取当前展示的那张产物；文件复制到项目素材库目录并写入素材索引；给进度与结果反馈；同名/重复需要确定策略。
- 优先级：P2
- 难度：中
- 风险：批量复制是写盘操作，节流不当会重演「执行期全接口卡死」；素材库索引若要求文件已在库目录内，必须先复制再登记。

## 四、非目标

- 不做站内消息中心、不做历史通知列表。
- 不做自定义提示音上传。
- 不改动素材库的既有单张导入语义。

## 五、验收要点

1. 跑一个 40 秒的图片节点：结束时响一次上行双音；同一秒内第二个慢节点完成只响一次并合并文案。
2. 失败节点响下行双音；手动停止不响。
3. 切到别的应用跑同一节点：收到系统通知；切回应用后画布顶部出现「1 个节点已完成」，点条目选中并定位该节点。
4. Agent 节点停下来提问且窗口失焦：收到通知；切回后横幅出现「Agent 正在等你回答」，点条目打开对话面板并定位到提问那条。
5. 拉框擦到分组一半：只有被框到的子节点被选中，分组边框不变色。
6. 拉框包住组内全部节点：分组与子节点一起被选中。
7. 在分组内容区空白按下左键拖动：出现选择框，而不是整组跟着动。
8. 单击分组内容区空白：清除选区，不选中分组。
9. 单击分组标题栏 / 拖标题栏：选中并移动整组。
10. 框选 5 个图片节点 → 工具栏「加入素材库」可点 → 执行后项目素材库出现 5 个文件，源节点文件不动也仍可预览。
11. 框选中混入一个文本节点 → 「加入素材库」置灰。
