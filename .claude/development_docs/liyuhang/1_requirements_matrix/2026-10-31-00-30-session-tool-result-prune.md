# 需求矩阵：按轮次淘汰会话文件里的旧工具结果

- 时间：2026-10-31 00:30
- 提出人：用户（承接「复制/体积滚雪球」优化链）

## 1. 背景（实测数据，用户真实工程 `蕾姆Rem`）

| 项 | 数据 |
| --- | --- |
| `.agent/sessions` | 52MB；最大单文件 7.48MB |
| 该会话构成 | 工具结果 3.96MB（2085 条，均值 1.9KB）、assistant 工具调用参数 2.78MB、base64 图片 0、死分支 0 |
| 工具结果分布 | >4KB 的 157 条占 2.2MB；≤2KB 的 1683 条占 1.08MB；95% 的工具字节在最近 100 条之外 |
| `.agent/attachments` | 105.6MB，291 个被引用，未被引用的仅 0.1MB（孤儿回收无收益） |

现有机制 `microCompactMessages()`（`agent/runtime/requests.ts`）：上下文超过模型窗口一半时，把**最近 3 个用户轮以外**的旧工具结果压成一行指针，
但注释写明「只改本次请求的副本：会话文件、UI 历史保持原样」。即：这些内容模型早就不看，磁盘上却完整留着。

补充事实（已核对 SDK 源码 `finalizeExecutedToolCall` → `createToolResultMessage`）：`afterToolCall` 返回的内容会**直接写进会话条目**，
所以超过阈值的工具输出早就是指针形态，本轮不涉及该路径。

## 2. 需求目标

1. 把「模型已经看不到的旧工具结果」在磁盘上同步淘汰，会话文件体积下降。
2. 淘汰口径与 `microCompactMessages()` 完全一致，**模型可见内容零变化**。
3. 不破坏会话文件结构：条目 id / parentId / 分支链不变，只是某条消息的 content 被替换。

## 3. 需求描述

| 编号 | 描述 | 优先级 | 难度 | 风险 |
| --- | --- | --- | --- | --- |
| R1 | 运行结束时（会话已 dispose、仍持有文件锁）重写会话文件，把最近 3 个用户轮之外的旧工具结果替换为指针 | P0 | 中 | 中（重写整文件；与 COW 共享断开） |
| R2 | 淘汰口径抽成共享纯函数，与 `microCompactMessages()` 复用同一套判定，避免两处漂移 | P0 | 低 | 低 |
| R3 | 无变化时不重写；写失败只告警，不影响本轮结果 | P1 | 低 | 低 |
| R4 | 不备份被淘汰的原文到 artifacts（否则「挪个地方」不省盘），指针文案与 microcompact 一致 | P1 | 低 | 中（回退到被淘汰位置时看不到原文） |

## 4. 不在本次范围

- assistant 工具调用参数（2.78MB）：改它会影响工具调用重放，单独评估。
- 冷存压缩（zstd 10x）：只对闲置会话有效，需改会话读取路径，后置。
- 阈值默认值调整（20KB → 4KB）：全局策略变更，与本次的「模型零变化」原则冲突，另议。
