# 需求矩阵：Agent 派发队列可视化与撤销

- 时间：2026-11-17 21:34
- 范围：画布内 Agent 互派任务的排队队列（`apps/web/src/pages/workspace/panels/canvas/agentDispatcher.ts`）

## 需求背景

Agent 之间互派任务时，队列只存在于页面内存里，界面上仅有一根 `queued` 状态的关系箭头。用户看不到队列里有几条、谁发给谁、什么内容、等了多久，也无法区分「排队中」与「被丢弃」。另外两处静默行为加剧了这种不可见：同一发送方的新消息会直接替换旧的排队消息（旧消息无任何提示），60 秒去重窗口内的重复消息会被静默丢弃。用户明确选择「可见 + 撤销」，不做插队。

## 需求目标

1. 让排队队列在画布上可见：条数、顺序、发送方 → 接收方、消息摘要、等待时长、当前阻塞原因。
2. 让「消息被替换 / 重复消息被忽略」这类静默行为有提示。
3. 允许用户撤销某条尚未开始的排队任务，并通知原派发方、释放去重键。
4. 不改变现有派发/打断/并发语义；不引入后端接口；队列仍随画布页面关闭而丢弃。

## 需求描述

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| R1 | 队列徽标 | 画布左下角常驻小徽标，显示排队条数；有新提示时带圆点。 |
| R2 | 队列列表 | 展开后按出队顺序列出条目：`发送方 → 接收方`、消息摘要、已等待时长、阻塞原因。结果回传类条目单独标注且不可撤销。 |
| R3 | 替换提示 | 同一发送方对同一节点的旧排队消息被新消息替换时，列表内出现一条限时提示。 |
| R4 | 去重提示 | 60 秒窗口内被去重丢弃的重复消息，出现一条限时提示（同一键只提示一次）。 |
| R5 | 撤销排队任务 | 每条 `task` 条目可撤销：二次确认后从队列移除、收掉箭头、释放去重键、给原派发方写「排队中被撤销，尚未开始执行」的通知（不触发其自动运行）。 |
| R6 | 语义边界 | 不提供插队/立即发送；不持久化队列；不改变打断规则与并发上限。 |

## 需求优先级

P2（体验/可诊断性）。不阻塞既有功能，但直接解决「排队看不见、消息静默丢失」的信任问题。

## 需求难度

低—中。全部改动集中在 web 端：dispatcher 暴露只读快照与撤销动作、新增一个画布浮层组件、补单测；无服务端改动。

## 需求风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 撤销后同内容重发被 60 秒去重吞掉 | 用户以为撤销后又发不出去 | 撤销时释放 `dedupe` 键（与现有替换逻辑一致） |
| 撤销通知触发父 Agent 自动运行 | 违背「停止不自动续跑」 | 复用 `/api/agent/note`，只写会话不运行 |
| 队列快照与真实队列不同步 | UI 显示幽灵任务 | 所有队列变更点统一调用 `syncQueueView()`；替换/撤销/出队/停止/dispose 均覆盖 |
| 结果回传被误撤销 | 父 Agent 永远收不到结果 | 结果条目不可撤销（仅展示） |
| 徽标遮挡画布操作 | 影响点击 | 左下角、z-index 5、`pointerdown/wheel` 阻断冒泡，与现有横幅一致 |

## 验收标准

1. 目标节点忙时派发两条消息：徽标显示 2，展开可见两条及等待时长、阻塞原因。
2. 同一发送方再发一条：旧条目消失，出现替换提示；徽标数不变。
3. 撤销一条：条目消失、箭头收掉；原派发方会话新增一条取消 note；60 秒内原样重发可正常入队。
4. 队列为空且无提示时徽标消失；关闭/切换画布后队列清空不残留。
5. 既有 dispatcher 单测全部通过，新增用例覆盖快照、替换提示、撤销（含去重键释放与通知）。
