# 需求矩阵：Agent 节点「创建副本」允许在源会话运行中立即克隆

- 时间：2026-10-30 14:59
- 提出人：liyuhang
- 模块：`apps/server/src/agent/runtime/sessions.ts`（`cloneAgentSession`）、`apps/web/src/pages/workspace/panels/canvas/components/agentNodePanel.vue`（调用侧，预期只保留兜底）
- 代码基线：当前工作区（未提交）

## 1. 需求背景

用户把 Agent 节点「创建副本」后，只有在副本面板**第一次打开**时才真正克隆会话（节点复制只写 `agentSessionCloneFrom` 指针）。克隆接口 `POST /api/agent/clone` → `cloneAgentSession()` 在源会话运行中直接抛 409「会话正在运行，请先停止再复制」，前端收到 409 后弹「源会话正在运行，请等这一轮结束后再打开这个副本」并关闭面板。用户的实际感受就是：**源 Agent 还在回复时，副本建不出来，必须等这一轮跑完**。

仓库现状（已核实）：

- 节点复制/拖拽复制/画布另存/跨工程粘贴都走 `agentSessionCloneFrom` 指针（`packages/nodes/agentNode/src/index.vue:92-96`、`apps/web/src/pages/workspace/panels/canvas/canvasFiles.ts:125-129`），克隆时机统一是「副本面板首次打开」（`agentNodePanel.vue:208-218`）。
- `cloneAgentSession` 当前用 `readFile` 逐字节拷贝源 jsonl，再追加一条 `session_info`（名字 + 「· 副本」），注释给出的理由是「会话运行中文件还在追加，逐字节拷贝可能截断在行中间」。
- 运行中的会话在服务端有内存态：`activeSessions`（`getActiveAgentSession`）持有 SDK 的 `SessionManager`，其 `getEntries()` 返回浅拷贝的内存条目，`entryOffset` 记录本轮开始时已有的条目数（`apps/server/src/agent/runtime/index.ts:142`）。
- SDK 写盘：新会话在**首条助手消息之前完全不落盘**（首次 flush 用 `openSync("wx") + writeFileSync` 一次写全量，`session-manager.js:743-763`），之后才是 `appendFileSync` 逐条追加（`:745/:766`）。条目一旦出现在内存里就是完整条目；未完成的助手回复只在 `streamingMessage` 里，不进入条目。
- 会话文件里用自定义条目 `toonflowAgentNode` 标记节点会话，历史列表据此隐藏（`listAgentSessions`，只扫文件前 8 KB）。
- 节点会话第一轮运行时，标记是在 `entryOffset` 计算**之前**追加的（`index.ts:121-129` 早于 `:142`），因此在 `getEntries().slice(0, entryOffset)` 之内，快照天然保留它。
- 运行中的会话在收尾阶段（最终回复已落盘、`run()` 还没 `unregister()`，其间还有自动压缩、计时统计、子 Agent 状态更新）仍然能被 `getActiveAgentSession` 命中，此时 `entryOffset` 仍停在本轮开始前。

## 2. 需求目标

源 Agent 正在回复时，副本依旧可以随时创建并打开；副本内容是**截至克隆时刻最近一次完整轮次**的对话，不包含进行中的那一轮。

非目标：不放开消息分支（fork）、删除、回退、压缩；不改「首次打开副本时才克隆」的时机；不复制子 Agent 会话文件；不在副本里添加任何提示标记；不改前端交互（409 提示保留为兜底）。

| --- | --- | --- | --- | --- | --- |

| R11 | 回复已经结束、但运行还没完全收尾（自动压缩/计时/子 Agent 状态更新中）时克隆，副本必须包含**刚完成的那一轮** | P0 | 低 | 中（`entryOffset` 永不推进） | 面板显示完整回复后立刻复制并打开副本，最后一条回复在副本里 |

补充场景口径（并入上表验收）：

- **单轮多步工具循环中克隆**：按「整轮丢弃」处理——本轮已产生的工具调用与中间回复都不进入副本（与 R2 一致）。
- **停止/打断后克隆**：走未运行路径，允许包含 `stopReason=aborted` 的半条助手消息（SDK 构建上下文时会跳过它）。
- **子 Agent 场景**：副本条目仍引用源会话的子会话文件；子 Agent 正在运行时，副本会把它显示为运行中（与停用前行为一致，本次不处理）。

## 4. 已确认决策（本次问答）

| 议题 | 结论 |
| --- | --- |
| 副本内容边界 | 只到上一条完整回复：进行中这一轮（含刚发出的用户消息）整体丢弃 |
| 作用范围 | 只放开 `/api/agent/clone`（节点创建副本、拖拽复制、粘贴、画布另存、跨工程粘贴共用）；fork/删除/回退/压缩仍要求先停 |
| 空对话边界 | 源会话还没有完整回复时照样建副本，副本从空对话开始 |
| 克隆时机 | 维持「副本面板首次打开时克隆」，复制动作本身仍然瞬时 |
| 副本标记 | 不加任何系统提示，副本就是一段普通对话 |

## 5. 边界与风险

- **截断点**：以 `active.entryOffset`（本轮开始前的条目数）为界；标记在该点之前写入，天然保留（R4 是断言，不需要补写）。
- **收尾窗口**：回复结束到 `unregister()` 之间 `entryOffset` 仍停在本轮开始前，直接截断会丢掉刚完成的整轮，必须用 `active.session.isIdle` 区分（R11）。
- **重发（resend）中途**：`branch()` 只改叶指针、不产生条目，快照停在重发前那一轮；副本看到的是被弃用的旧分支，语义可接受。
- **运行中追加消息（steering）**：只对子 Agent 会话开放（普通节点会话运行中再发消息直接 409），不在本次范围。
- **内存 vs 磁盘一致性**：运行中克隆改用内存条目快照，避免逐字节读盘与追加写并发；条目对象与 SDK 共享引用，切片与序列化必须在同一个同步块内完成。
- **首轮不落盘**：首条助手消息之前磁盘上没有文件，运行中克隆不能依赖 `stat`/`readFile`（R3）。
- **子 Agent**：副本条目仍引用源会话的子 Agent 文件（现状如此，本次不改），运行中的子会话文件不会被复制或截断。
- **多进程部署**：`activeSessions` 是进程内 Map，现有代码已注明多进程需共享会话所有权；本次不改变该约束。
- **前端 409 分支**：改造后正常流程不会再返回 409（会话被删是 404、刚停止仍走内存路径），前端提示保留为不可达的兜底，文案不改。

## 6. 评审意见

### 6.1 子 agent 初审

- 结论：**不通过 → 已整改（复审通过）**（两个子 agent 独立评审，结论一致）
- 必须修改项与整改：
  1. **事实写反**：标记在 `entryOffset` **之前**追加（`index.ts:121-129` 早于 `:142`），快照天然保留它；「截断会切掉标记、需要补回」不成立。→ 删除补回逻辑，R4 改为断言；测试验证「标记在 cut 之前不重复追加」。
  2. **数据丢失（必现窗口）**：最终回复已落盘、`run()` 还没 `unregister()` 时，`entryOffset` 仍停在本轮开始前，会整轮丢掉用户已看到的回复。→ 新增 R11，改用 `active.session.isIdle` 判定：已结束取全量，正在跑才截断。
  3. **首轮磁盘无文件**：SDK 首条助手消息之前不落盘，`stat` 会 404，前端收到 404 会清掉待克隆指针。→ R3 改为显式覆盖「磁盘无源文件」，实现用 `ENOENT && 有 active` 兜底。
  4. **命名来源**：首轮纯文本消息不会写 `session_info`，用快照算名字会得到「新对话 · 副本」。→ 名字改用全量条目（首条用户消息兜底）。
  5. **steering/resend 风险不成立**：普通节点会话运行中再发消息一律 409，steering 只对子 Agent 开放。→ 从风险清单删除并说明。
  6. **快照与序列化必须同步**：条目对象与 SDK 共享引用。→ 列为实现约束（同一切片、序列化之间不得有 await）。
- 建议项采纳：确认条目必须原样直传（不按消息重建）；运行中路径不得对源会话加锁（run 全程持锁，非阻塞锁会直接 409）；停止后克隆允许包含 `aborted` 条目；`await stat` 之后重新取一次 active，避免拿到过期快照。
