# 需求矩阵：媒体供应商支持重命名（显示名称）

- 时间：2026-10-30 15:37
- 提出人：liyuhang
- 模块：`apps/server/src/modules/mediaGeneration/media/provider.ts`、`apps/server/src/routes/providers/media/rename.ts`（新增）、`apps/web/src/components/settings/panels/mediaModel/index.vue`、`apps/web/src/components/settings/panels/mediaModel/renameProviderDialog.vue`（新增）
- 代码基线：当前工作区（未提交）

## 1. 需求背景

用户反馈：媒体供应商装好之后名字改不了。

仓库现状（已核实）：

- 媒体供应商的名字来自供应商 `.ts` 文件里 `export default` 对象的 `label` 字面量（`provider.ts:196`、`:202`）。设置页卡片显示的就是它（`mediaModel/index.vue:11`），节点下拉的分组标题也来自它（`listMediaModels` 返回 `providerLabel`，`generation.ts:46`；节点侧 `groupNodeModels.ts:14-15` **按 `providerId` 分组**、`providerLabel` 只作标题）。
- 供应商 ID 是源码里的 `id` 字段，文件名必须等于 `${id}.ts`（`provider.ts:220` `fileName !== `${id}.ts`` 即报错），`readProvider` 又从文件名反推 id（`:249`）；`label` 与 ID 解耦。
- 后端现有写接口只有四条：add（安装）、save（**只替换 `models` 源码区间**，`provider.ts:295-318`）、models（获取模型列表）、delete。没有任何接口能改 `label`。
- 前端「编辑媒体供应商」对话框（`editProviderDialog.vue`）只有连接配置表单 + 模型列表，没有供应商名字段；模型自己的显示名可以逐个编辑（走 save 的 models 区间替换）。
- 对照组：语言模型的自定义供应商在添加/编辑弹窗里同时有「Provider ID」和「显示名称」两个字段（`languageModel/addCustomProviderDialog.vue:16-17`），但它改的是 **ID** 并附带孤儿隐藏记录清理（`:428-429`），不能直接类推到媒体供应商的 label。
- 路由表按「编号只增、import 追加在列表末尾、`app.use` 注册在对应分组内」维护（最近三次追加在 `router.ts:166-168`），新增接口不需要重排既有编号。
- 安装同名供应商**不会覆盖**：`addMediaProvider` 用独占写，文件已存在直接 409「已安装，请在设置中编辑，或先删除后重新安装」（`provider.ts:285-290`）；`force` 对 provider 无效。升级只能先删除再安装，而删除会同时清掉 `mediaProviderConfigs[id]`（`:381`）与隐藏记录（`:382`）。
- 已挂载的媒体节点只在 `toonflow:plugin-installed`（`detail.type === "provider"`）或 `toonflow:provider-config-changed` 事件里重新取模型（如 `imageGenerationNode/src/index.vue:260-276`），清 `modelCache` 本身不会通知节点。

## 2. 需求目标

在「设置 → 媒体模型」的供应商卡片上提供「重命名」，只改显示名称：改写该供应商 `.ts` 源码里的 `label` 字面量，ID、文件名字、模型列表、连接配置、已选模型、隐藏设置全部不受影响。

非目标（本次不做）：

- 不改供应商 ID / 文件名，不做节点里已保存 `[providerId, modelId]` 选择的迁移。
- 不改语言模型供应商（它已经能改 ID 与显示名）。
- 不改图标、readme、版本号、排序规则。
- 不做「一个供应商多套账号配置」。
- 不给 `addMediaProvider`（安装/插件市场/AI 生成/引导页）补重名校验——本次「禁止重名」只约束重命名入口。
- 不给 MCP / Agent 工具增加 `rename` 操作（当前 MCP 媒体供应商只有 list/add/save/delete）。
- 不做跨窗口/多标签实时同步（另一个窗口保持旧名到刷新，与现有保存逻辑一致）。

## 4. 已确认决策（本次问答）

| 议题 | 结论 |
| --- | --- |
| 改什么名 | 只改显示名称（`label`） |
| 入口位置 | 供应商卡片操作区加「重命名」按钮 |
| 存储方式 | 改 `.ts` 源码里的 `label` 字面量（单一事实源）。同名供应商已安装时重装会被 409 拒绝，升级须先删除再安装，而删除会丢 API Key、隐藏设置与自定义名字——已知并接受 |
| 官方供应商 | tfRouter 也可改名 |
| 重名口径 | 新名字与其它供应商名字**严格相同**才算重名（大小写不同不算）；只约束重命名入口 |
| 名字限制 | trim 后 1–200（UTF-16 码元），禁换行、控制字符与不可见字符 |
| 弹窗形式 | 独立小弹窗（不用 `ElMessageBox.prompt`） |

## 5. 边界与风险

- **源码区间**：`label` 必须是字符串字面量或无插值模板字面量（`provider.ts:202` + `literal()` 约束），且可能被 `unwrap` 包裹（`as const`、括号、`satisfies`、类型断言）；替换必须取 **unwrap 后**的值表达式区间，禁止文本搜索。替换值统一用 `JSON.stringify` 生成双引号字符串，避免引号/反斜杠/`${` 转义问题。
- **编码与元数据**：只保证 UTF-8 编码文件「除 label 区间外内容不变」；`readFile(utf8)` 对非 UTF-8 文件会产生替换字符，原子写会把文件权限重置为 0600（`packages/file/src/index.ts`），mtime/inode 也会变——这些不在保证范围。
- **重名判定范围**：只比较「可正常解析的已安装供应商」的显示名；`loadError` 的供应商名字回退成 id、revision 为空，既不可信也不可重命名，按跳过处理。
- **重名只约束重命名**：安装/插件市场/AI 生成仍可装出同名供应商；两个不同文件并发改成同一新名也不原子（锁是文件粒度），可能同时通过——均为已知限制。
- **重装/升级**：同名供应商在安装时直接 409，不会静默覆盖；要升级必须先删除，删除会连带清掉 API Key、隐藏设置与自定义名字——这是选择「改源码」的实际代价。
- **并发**：与 save/delete 一致，读文件前加锁、锁覆盖读-校验-写，并用 revision 做乐观锁；锁只有进程内文件粒度，不覆盖跨进程。
- **不碰其它键**：`settings.mediaProviderConfigs`、隐藏设置、节点已选模型都以 id 为键；服务端报价缓存键含源码 revision（改名后自然过期 30 秒），余额账户键与 label 无关。
- **展示面**：设置卡片、编辑弹窗标题、开发者调试弹窗、余额卡片、节点错误文案都会跟随 label 显示；「添加供应商」弹窗里的内置包列表来自 `@toonflow/providers` 源码，改名后仍显示包内旧名，属预期。
- **列表展示**：卡片第二行仍显示文件名（`fileName`）。重命名入口禁止重名后，改名不会制造同名卡片；安装入口仍可能装出同名（见 R4 已知限制）。
- **409 文案是契约**：前端用 message 是否包含「已被修改」区分「revision 过期」与「重名」（两者都是 409）；该文案在服务端与前端注释中标注为契约，测试断言覆盖，改文案需同步两侧。
- **错误文件**：`listMediaProviders` 对坏文件返回 `loadError` + 回退 label=id（`provider.ts:271-277`），前端禁用重命名，服务端 `parseProvider` 也会先失败并返回 400。
- **i18n**：静态文案沿用仓库现状硬编码中文，含参动态文案（重名）用 `t` 模板。

## 6. 评审意见

### 6.1 子 agent 初审

- 结论：**不通过 → 已整改（复审通过）**
- 必须整改项与整改：
  1. **R5 锁范围**：原写「写文件前加锁」，会留下读-校验-写之间的 TOCTOU。→ 改为「读文件前加锁，覆盖读-校验-写」，实现按此落地（与 save/delete 一致）。
  2. **R6 刷新链路不足**：只清 `modelCache` 不会通知已挂载节点，节点只监听 `toonflow:plugin-installed` / `toonflow:provider-config-changed`。→ R6 改为「先 `invalidateNodeModels("media")` 再派发 `toonflow:provider-config-changed`」。
  3. **「重装覆盖名字」事实错误**：`addMediaProvider` 是独占写，同名直接 409，`force` 对 provider 无效；真正的路径是先删除再安装，代价是 API Key + 隐藏设置 + 名字一起丢。→ 已改写 §1、§5 与决策表。
  4. **R2 未定义区间定位方式**：→ 明确「AST 顶层 label 属性值表达式（unwrap 后），禁止文本搜索」，并覆盖 `as const`/括号/引号/模板字面量。
  5. **「禁止重名」被夸大**：add 侧不校验、跨文件并发不原子。→ R4/§5 收窄为「仅重命名入口」，并写明已知限制。
- 采纳的 P2 建议：C1/`U+2028`/`U+2029`/零宽空格/bidi 覆盖符一并拒绝（保留 ZWJ 组合 emoji）；长度口径写明 UTF-16 码元；「字节不变」收窄为 UTF-8 文件 + 不含文件元数据；补充 404（文件被并发删除）；409 文案统一为「再重命名」；无操作不弹成功提示；补 MCP/Agent、添加弹窗、跨窗口等非目标与展示面说明；新增含 `"`、`\`、`${`、中文、emoji 的转义验收。
- 事实勘误：分组键是 `providerId`、`providerLabel` 仅作标题；价格缓存键含源码 revision；路由追加位置为 `router.ts:166-168`；语言供应商改名改的是 ID，不能直接类推。
- **复审结论：通过，无 P0/P1**。复审 8 条 P2 的处理：不可见字符从枚举改为 `\p{Cc}`/`\p{Cf}`/`\p{Zl}`/`\p{Zp}` 判定并放行 ZWJ；R3 写明首尾 trim、内部拒绝；§5 同名卡片表述修正；R10 改为「图标按钮必须有 `aria-label`、文字按钮以文字为准」并保留回车手测；R2 补转义验收；409 文案标注为契约并加两侧注释；测试文档同步；方案残留「重名 → 400」改为 409。
