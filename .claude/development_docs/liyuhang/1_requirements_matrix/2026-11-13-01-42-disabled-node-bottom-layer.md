# 需求矩阵：禁用节点恒在画布下层

- 时间：2026-11-13 01:42
- 模块：画布（`apps/web/src/pages/workspace/panels/canvas/`）
- 状态：已实施

## 1. 需求背景

画布上被禁用的节点（`node.data.disabled === true`）和被启用的节点混排。Vue Flow 的节点层叠顺序由 `node.zIndex`（默认 0）决定，相同 z 时按 DOM 顺序，也就是后加入的节点在上。禁用一个后加入的节点后，它会盖住更早加入的启用节点，视觉上让人以为禁用节点仍占着主层，也容易误点到它。

## 2. 需求描述

禁用节点应始终渲染在启用节点的下层；被选中或拖动时允许临时浮起（否则被盖住的区域无法看见也无法操作）。分组（canvasGroup）内的禁用节点跟随分组层级，不强行压到分组之下。

## 3. 需求矩阵

| # | 描述 | 优先级 | 难度 | 风险 |
| --- | --- | --- | --- | --- |
| R1 | 禁用节点渲染在启用节点之下（同级/同画布） | P1 | 低 | 中（负 z-index 的层叠上下文风险） |
| R2 | 选中/拖动禁用节点时仍能浮到未选中的启用节点之上，保证可操作 | P1 | 低 | 低 |
| R3 | 分组内的禁用节点不被分组底色/边框盖住（沿用 Vue Flow 的父子 z 计算） | P2 | 低 | 中（若强行压底会不可见） |
| R4 | 加载画布、撤销/重做、粘贴、禁用/解禁后层级都要正确（不能只在切换时生效一次） | P1 | 中 | 中（节点对象会被整体替换） |
| R5 | 派生层级不污染项目文件、撤销快照和保存节流 | P2 | 低 | 低 |

## 4. 非目标

- 不改禁用节点的视觉样式（标题隐藏、徽标等既有行为不变）。
- 不改连线（edge）的层叠与 `edgeDisabled` 样式。
- 不新增设置项（写死）。
