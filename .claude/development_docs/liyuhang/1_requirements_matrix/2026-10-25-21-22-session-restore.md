# 需求矩阵：会话恢复（窗口几何 / 上次画布 / 面板布局 / 吸附）

## 一、需求背景

Toonflow 目前每次启动都是"全新开始"：主窗口按固定规则居中创建，进入项目固定打开根目录排序第一的画布，左右侧面板的显隐与 Agent 面板布局全部丢失。用户每次都要重新摆一遍窗口、找回到上次那张画布、重新拉开面板，打断创作连续性。

用户原话：「我希望软件打开能够记住上次的大小，进入项目时打开上次的画布，要记住素材库控件、agent控件的位置、网格连线、吸附等状态」。

## 二、需求目标

一次会话结束后，再次打开软件并进入同一项目，应当回到"离开时的工作现场"：
窗口几何一致、进入项目自动回到上次那张画布、画布视图（平移/缩放）一致、左右面板位置宽度显隐一致、吸附开关一致。画布节点与连线本身必须与离开时完全一致。

## 三、现状盘点（调研结论，带出处）

| 项 | 现状 | 是否已满足 |
| --- | --- | --- |

| 画布节点/连线/viewport | 已随画布 JSON（`toonflowCanvas:true`）落盘，500ms 防抖（`canvas/index.vue:746-768,842`）；切画布、离开项目有 flush（`canvas/index.vue:844-863`、`workspace/index.vue:286-315`） | 是 |
| 进入项目打开哪张画布 | 固定取根目录按名称排序的第一张；无画布则新建「画布1」（`canvasMenu.vue:287-343`），不记上次 | 否 |
| 吸附（snap）开关 | 内存 `snapEnabled = ref(false)`（`canvas/index.vue:257`），不落盘；网格固定 16px | 否 |
| 素材库面板（左） | 宽度/停靠/id 走 Pinia→服务端 settings（按项目，`stores/assetLibrary.ts:101-105`）；浮层位置用浏览器 localStorage（`floatingPanel.vue:93-125`） | 部分 |

**桌面端关键约束**：主窗口 URL 端口是随机分配（`apps/desktop/src/connection.ts:98-103`），localStorage 以 origin 隔离，**端口一变 localStorage 就是空的**。因此凡是"要跨启动记住"的东西，都不能放 localStorage，必须走服务端 settings（`settings.json`）。

## 五、需求边界（本期不做）

- 不记忆"上次打开的项目"（用户已明确：启动停在首页，点项目时恢复画布）。
- 不记忆首页侧栏折叠、工作区 canvas/document 面板切换（用户未提，避免副作用）。
- 不做网格大小可配置、不做"每个画布独立吸附设置"。
- 不做多窗口。

## 七、评审记录

### 7.1 初审（子 agent，2026-10-25 21:40）：需修改后通过

**阻断项及处理**

| # | 问题 | 处理 |
| --- | --- | --- |
| B1 | 窗口几何不能走服务端 settings：窗口创建时页面还没加载；remote 模式下 settings 被代理到远端，不代表本机 | 采纳。窗口几何改为主进程本地文件 `data/windowState.json`（与 `data/settings.json` 同级），新增决策 D6 |
| B2 | 最大化/最小化/全屏时 `getFrame()` 返回的是当前 frame，直接存会污染"还原尺寸" | 采纳。维护 `normalBounds`（仅在非最大化/非最小化/非全屏时更新）+ `maximized` 标记；启动先按 normalBounds 建窗再 `maximize()` |
| B3 | R7 只挂 `will-close` 覆盖不到 Cmd+Q / 菜单退出（走 `mainWindow.close()` 不触发 veto）/ Dock 退出 / 更新重启 | 采纳，R7 风险上调为高。菜单退出改走 `requestClose()`，并评估 `before-quit`；关闭闸门需覆盖四条路径 + 2s 超时强制关闭 |

**重要项及处理**

| # | 问题 | 处理 |
| --- | --- | --- |
| I1 | resize/move 拖动期间持续触发，无节流 | 采纳。事件只更新内存 pendingFrame，300-500ms trailing debounce 后再判定是否更新 normalBounds；关闭时同步落盘 |
| I2 | `setFrame` 到不存在的显示器坐标不会自动纠偏 | 采纳。用 `Screen.getAllDisplays()` 做交集最大化 + 尺寸不超过 workArea；无交集则居中主屏；注意 macOS 负坐标合法 |
| I3 | settings 保存是整份覆盖，且每次保存都会触发 `refreshProviderModels` / `reloadMcpRuntime`；面板拖动会变成每帧一次全量 PUT | 采纳。会话状态走独立的轻量接口（按 key 深合并、无副作用），不复用 settings 保存链路 |
| I4 | 跨客户端（移动端/远端）并发写 settings 会互相覆盖 | 采纳。独立接口按 key 合并，天然规避整份覆盖 |
| I5 | D2 与已评审通过的素材库需求 R2/R15（面板按项目记忆）冲突 | **待用户确认**（见 8.1） |
| I6 | R2 恢复路径与现有代码不匹配：`initialCanvasId` 要求目标已在 `canvases` 列表里，子目录画布不可用；且"只有子目录画布"的项目按现有规则不打开任何画布 | 采纳。恢复走 `activateCanvas(savedPath)` 链路并校验项目相对路径（拒绝 `..`/绝对路径）；指针需在画布重命名/移动时同步、文件不存在时清除。子目录回退语义**待用户确认**（见 8.2） |
| I7 | 浮层位置存 localStorage，端口随机导致跨启动必然丢失，不存在"迁移" | 采纳。改为会话状态接口存储；同一次运行内旧值可读一次做迁移，不指望跨启动 |
| I8 | 面板缺字段清单与写入触发点 | 采纳。每面板明确字段：`visible/width/height/docked/floating{left,top}`；写入触发点为 pointerup / change，不做持续 watch |
| I9 | D1 的"存本机 settings"在 remote 模式下不成立 | 用户已选"存项目目录文件"，该问题自然消解，无需 settings 承载画布指针 |

**建议项吸收**

- 画布视图偏好合并为一份：`snap` / `showEdges` / `showMap`（均为内存 ref），全机共享（建议-1 采纳）。
- 不恢复：`activePanel`（canvas/document）、首页素材库筛选态、多画布 entries、`selectedTool`、侧栏折叠、网格大小、多窗口、上次项目（建议-2/3/4 采纳）。
- 画布指针与 activePanel 解耦：即使上次停在文档面板，仍记录当前画布（建议-2 采纳）。
- 恢复子目录画布后展开父目录并高亮（建议-6，低优先级，纳入 R2 验收）。
