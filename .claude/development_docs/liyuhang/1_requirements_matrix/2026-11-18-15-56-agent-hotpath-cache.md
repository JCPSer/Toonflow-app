# 需求矩阵：Agent 剩余热点缓存与画布写入统一

- 时间：2026-11-18 15:56
- 来源：上一轮优化后的剩余风险盘点（评审 P2-5 热点）

## 需求背景

连接池与上下文统计已优化，但三类开销仍按「会话数量 / 会话体积」线性增长：

1. 打开 Agent 历史面板：`getAgentSession` 对非运行会话每次整文件读取、全量 parse、全量投影，响应体截断只减传输不减解析。
2. 历史会话列表：`SessionManager.list` 逐行读完全部会话文件，之后每个文件再读 8KB 判断节点标记。
3. 画布其它写入路径（复制画布、新建画布、文档节点回写）仍是默认 4×60ms 重试，Agent 持锁写入时仍可能报「保存失败」。

另外 `getAgentStats` 与 `getAgentContext` 每次 flush 各自遍历一遍 branch，可合并为一次。

## 需求目标

1. 非运行会话的历史面板读取按「文件 size + mtime」缓存投影结果，重复打开不再全量解析。
2. 会话列表整体缓存（短 TTL + 变更失效），节点标记判定按文件 mtime 缓存。
3. 画布所有 JSON 写入统一使用 6×120ms 退避策略。
4. stats 每次刷新只取一次 branch，供统计与上下文估算共用。

## 需求描述

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| R1 | 历史面板投影缓存 | 仅缓存非运行会话；size+mtime 不变直接复用；LRU 上限 6 条、超过 8MB 的文件不缓存；删除/重写导致 stat 失败即失效 |
| R2 | 会话列表缓存 | 原始 `SessionManager.list` 结果按 cwd+directory 缓存 5 秒；创建/克隆/删除/重命名会话时主动失效 |
| R3 | 节点标记缓存 | `hasAgentNodeMarkerOnDisk` 按 path+size+mtime 缓存布尔值，避免每次列表都读 8KB |
| R4 | 画布写入统一 | 复制画布、新建画布、文档节点回写使用同一 `CANVAS_WRITE_RETRY`（6 次、120ms 起） |
| R5 | branch 单次遍历 | `getAgentStats` / `getAgentContext` 增加可选 branch 参数，emitStats 与 getAgentSession 传一次 |

## 优先级 / 难度 / 风险

- 优先级：P2（性能优化，用户明确要求全做）。
- 难度：中（缓存失效与内存上限是主要复杂点）。
- 风险：缓存返回同一对象，若有调用方修改返回值会污染缓存；会话列表短 TTL 可能短暂显示旧数据；缓存占用内存。

## 验收标准

1. 同一大会话历史面板第二次打开耗时接近首次的 1/10（本地 5MB 会话验证）。
2. 连续打开历史列表不重复读全部会话文件（日志/计时验证）。
3. 复制画布、新建画布在 Agent 持锁期间能重试成功，不再立即报错。
4. 运行中的会话始终实时（不进缓存）。
5. 服务端全量测试、web 单测、typecheck、构建通过。
