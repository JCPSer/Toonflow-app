# 需求矩阵：素材库全面整改（商用标准）

- 时间：2026-10-25 02:39
- 提出人：用户
- 现状结论（调研）：只有全局库（`<数据目录>/assets`），纯物理目录、无元数据、无回收站、无上传入口、无批量、无拖拽移动、面板宽高硬编码；画布内是左上角浮层而非左侧面板；首页管理页可建目录/重命名/移动/删除/下载，但缺新增素材能力。

## 一、需求背景

素材库是画布节点的素材来源，也是产物的沉淀地。现在它只是一个"只读的目录树 + 文件列表"：不能上传、不能拖拽整理、不能批量操作、删除即永久消失、没有标签和搜索，且全局一份，项目之间无法隔离。用户判定"对素材的管理不及格"，需要按可商用标准整改。

## 二、需求目标

1. 双层素材库：**本项目**（`<项目>/library/`，随项目走）+ **全局**（`<数据目录>/assets`，跨项目共享），树根并列，互不迁移。
2. 目录树支持拖拽移动（目录拖目录、文件拖目录），支持在任意目录下新建子目录。
3. 面板支持两种形态（浮层 / 左侧停靠）与两种视图（树形 / 文件夹），宽高可拖拽并记忆。
4. 顶部固定工具栏：上传、新建目录、排序、视图切换、搜索、批量、回收站。
5. 管理页具备完整的增删改移、导入上传、标签备注、收藏、回收站恢复。
6. 删除有回收站；被引用的素材阻止删除并指出引用位置。

## 四、明确不做（本期）

- 不做素材版本历史、内容去重（哈希比对）与自动标签。
- 不做跨库拖拽搬家（只允许复制收藏）。
- 不做云端同步、多设备冲突合并。
- 不做素材在线编辑（裁剪/调色），只做管理。
- 不迁移现有全局素材到项目库（用户已确认）。

## 五、关键风险与待定

| 风险 | 说明 | 处置 |
| --- | --- | --- |
| 路径引用失效 | 现有引用全是路径字符串；素材库改名/移动不会破坏画布（拖入画布是复制），但会让"收藏来源"记录失效 | 收藏记录只存展示用来源路径，不做硬引用；元数据用库内相对路径 |
| 停靠面板改动面 | 画布布局已有 agent 面板的停靠实现，可复用其容器与尺寸逻辑 | 抽公共 dock 容器，避免两套拖拽逻辑 |
| 双库语义混淆 | 用户可能不清楚当前在哪个库 | 树根高亮 + 工具栏显示当前库徽标；收藏弹窗必须选库 |
| 大库性能 | 现有全树 readdir 在数千文件时会卡 | 懒加载 + 分页 + 缩略图缓存，服务端限制单目录条目数 |
| 回收站膨胀 | 永久保留会占磁盘 | 回收站显示占用总量，手动清空；超过阈值在工具栏提示 |
| 外部改动 | 用户用 Finder 直接改 library 目录 | 打开面板时对账 `.library.json`，缺失项按文件名重建 |
