# 需求矩阵：节点运行时长显示

- 记录时间：2026-10-28 16:12
- 需求来源：用户「我想再加一个节点运行的时间显示，放在运行节点的右上角，如何？」
- 代码基线：`1342529`
- 澄清结论：
  - 显示时机：**运行中滚秒 + 结束后留结果**（结束后角标写「耗时 3m12s」，直到该节点下一次运行）
  - 覆盖范围：**全部节点统一接入**（骨架层统一支持，各节点传入自己的运行态）
  - 位置形态：**内容卡片右上角浮标**（不依赖 hover / 选中，始终可见）
  - 边框联动：**只加角标，呼吸边框仍仅 textNode**
  - 结果存活：**只留本次会话内存**，不写 node.data，换画布/重启后不再显示
  - 计时口径：**只算「耗时任务」**——AI 生成、帧分析、导出、转文本、打光/多角度/全景、变速/截取等；上传、缩放、宫格切分这类瞬时操不计

## 一、背景

`nodeSkeleton` 目前只有一个 `running` prop，作用是给内容卡片加呼吸描边，且全仓库只有 `textNode` 传了它（`:running="generating"`）。其余节点（图片/视频/音频生成、帧分析、媒体处理、3D 导演台）在跑长任务时，节点外观只有各自的 `v-loading` 遮罩或进度条，**没有任何地方能看出这次任务已经跑了多久**。

实际问题：图片/视频生成动辄一两分钟，用户无法区分「正常在跑」与「卡住了」；跑完后也回看不了这次花了多久，做成本与模型选择对比时没有依据。

## 三、非目标

- 不做节点累计运行时长统计、不做历史记录、不做成本换算。
- 不改标题栏布局，不新增按钮。
- 不给「上传文件」「缩放」「宫格切分」「局部重绘笔刷」这类瞬时操作计时。
- 不做跨会话持久化（不写画布 JSON）。

## 四、验收标准

1. textNode 生成时卡片右上角出现 `00:01`、`00:02` 逐秒递增；生成结束后变为「耗时 8s」并保留。
2. 图片生成节点跑一次生成，同样有滚秒与结束耗时；期间上传替换图片不触发计时。
3. 帧分析节点跑逐帧分析时计时正常，取消后角标写「耗时 X」（取消也算一次结束）。
4. 音频节点转文本、截取、变速时计时正常。
5. 3D 导演台在文档面板里（`documentTarget` 模式）不出现角标，或出现也不破版——需明确取舍。
6. 切到另一个画布再切回，计时仍连续。
7. 节点宽度 220px 时角标不与标题栏的刷新/删除按钮重叠。
8. 计时期间画布可正常拖动、缩放、滚轮，不被角标拦截。

## 五、待定项

- **文档面板模式**：`nodeSkeleton` 在 `documentTarget` 为真时会把节点挪进文档面板（`readOnly` 场景）。此时卡片是纵向 flex 布局，右上角浮标位置需要单独处理。倾向**文档面板不显示角标**（那是编辑态，不是画布观察态）。
